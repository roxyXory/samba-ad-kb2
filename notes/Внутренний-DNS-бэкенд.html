База знаний Samba AD DC

Samba Internal DNS Back End

Суть

Контроллер домена Samba AD содержит встроенный DNS-сервер (бэкенд INTERNAL_DNS), поддерживающий базовые функции, необходимые Active Directory. Он прост в настройке и не требует дополнительного ПО или знаний о DNS. Этот бэкенд рекомендуется для простых DNS-конфигураций.

Ключевое

Ограничения внутреннего DNS

Внутренний DNS не поддерживает:

  • работу в качестве кэширующего резолвера (caching resolver);
  • рекурсивные запросы (но умеет пересылать их другому рекурсивному DNS-серверу);
  • shared-key transaction signature (TSIG);
  • stub-зоны;
  • передачу зон (zone transfers);
  • балансировку Round Robin между DC.

Динамические DNS-обновления через Kerberos

Динамические DNS-обновления с использованием Kerberos включены во внутреннем DNS-сервере по умолчанию. Чтобы изменить эту настройку, задайте параметр allow dns updates в файле smb.conf. Подробности — на man-странице smb.conf (5).

Настройка DNS-форвардера

Внутренний DNS-сервер способен разрешать только DNS-зоны Active Directory. Чтобы включить рекурсивные запросы к другим зонам, задайте в smb.conf параметр dns forwarder — один или несколько IP-адресов DNS-серверов, поддерживающих рекурсивное разрешение. Например:

dns forwarder = 8.8.8.8

Samba 4.5 и новее поддерживает несколько IP-адресов, разделённых пробелами; более старые версии — только один IP-адрес. Подробности — на man-странице smb.conf (5).

Диагностика: клиенты не могут разрешать DNS-запросы

Если записи из DNS-зоны Active Directory не разрешаются, проверьте, что в операционной системе клиента указан IP DNS-сервера, способного разрешать зону AD (в вики есть отдельные страницы: Windows DNS Configuration, Linux and Unix DNS Configuration, Mac OS X DNS Configuration).

Если конфигурация клиента верна, убедитесь, что DNS-сервер Samba запущен (см. следующий пункт).

Диагностика: DNS-сервер Samba не запускается

Проверьте, что никакой другой процесс не занимает TCP- и UDP-порт 53:

  • Просмотрите лог-файлы Samba на предмет DNS-ошибок. Например:
 [2016/01/01 00:00:00.000000,  0] ../source4/smbd/service_stream.c:346(stream_setup_socket)
  Failed to listen on 127.0.0.1:53 - NT_STATUS_ADDRESS_ALREADY_ASSOCIATED
  • Убедитесь, что на TCP- и UDP-порту 53 не слушает другой процесс. Например:
# netstat -tulpn | grep ":53"
tcp        0      0 10.99.0.1:53        0.0.0.0:*               LISTEN      972/dnsmasq
tcp        0      0 127.0.0.1:53        0.0.0.0:*               LISTEN      903/dnsmasq
udp        0      0 10.99.0.1:53        0.0.0.0:*                           972/dnsmasq
udp        0      0 127.0.0.1:53        0.0.0.0:*                           903/dnsmasq

В примере видно, что порт 53 занят процессом dnsmasq.

Как исправить:

  • Остановите службу, слушающую порт 53, и отключите её автозапуск при загрузке (см. документацию вашей операционной системы).
  • Перезапустите Samba.

Подводные камни

  • Порт 53 уже занят — самая частая причина, по которой встроенный DNS не стартует; в логе это выглядит как Failed to listen on 127.0.0.1:53 - NT_STATUS_ADDRESS_ALREADY_ASSOCIATED, а виновником в примере из вики выступает dnsmasq.
  • Внутренний DNS не кэширует и не резолвит рекурсивно внешние зоны сам по себе — без настроенного dns forwarder разрешаться будут только зоны AD.
  • Нет zone transfers, TSIG, stub-зон и Round Robin между DC — для сценариев, где это нужно, встроенного бэкенда недостаточно.
  • Ограничение по версии: несколько форвардеров через пробел работают только в Samba 4.5+; в старых версиях dns forwarder принимает лишь один адрес.
