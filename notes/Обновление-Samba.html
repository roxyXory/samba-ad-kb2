База знаний Samba AD DC

Обновление Samba

Суть

Страница «Updating Samba» описывает правильный порядок обновления установленного Samba до более новой версии — он одинаков для контроллера домена AD, NT4-style PDC, доменного члена и standalone-установки: остановить службы, сделать резервную копию, прочитать release notes всех пропущенных версий, установить новую версию поверх и запустить те же демоны, что и раньше. Для контроллеров домена добавлены рекомендации по проверке базы AD и осторожности при понижении версии. Отдельный раздел перечисляет заметные изменения в конкретных версиях (4.0.x–4.6.x), о которых нужно знать после обновления, а также развеивает заблуждение, что переход на Samba 4 требует миграции на Active Directory.

Ключевое

Общий порядок обновления

Действия одинаковы при обновлении Samba AD DC, NT4-style PDC, доменного члена или standalone-установки:

  1. Остановить все службы Samba (см. Управление службой AD DC).
  2. Создать резервную копию (см. Резервное копирование и восстановление AD DC).
  3. Прочитать release notes всех пропущенных версий — там важные сведения о новых возможностях, изменённых параметрах и исправлениях. При переходе на новый мажорный релиз читают notes начальной версии (x.y.0) и всех минорных до целевой. Пример со страницы: обновление с 4.4.4 до 4.6.2 — читаются notes версий 4.5.0, 4.6.0, 4.6.1 и 4.6.2.
  4. Установить новейшую версию поверх существующей:
    • при сборке из исходников — использовать те же опции configure, что и для предыдущей версии (см. Build Samba From the Sources);
    • при обновлении через пакеты — следовать документации дистрибутива.
  5. Запустить те же демоны, что и на предыдущей версии:
    • Samba AD DC: samba
    • Samba NT4-style PDC/BDC: smbd, nmbd
    • Samba domain member: smbd, nmbd, winbind
    • Samba standalone: smbd
  6. Проверить лог-файлы Samba на ошибки (см. Диагностика AD DC).
  7. Протестировать обновлённую установку.

Обновление контроллеров домена AD

Обновление AD DC может добавить осложнений из-за совместимости баз данных и управления FSMO-ролями. Вики рекомендует:

  • Запустить проверку базы данных Samba AD DC (Samba AD DC database check) как часть тестирования обновлённой установки.
  • Обратиться к странице «Updating Multiple Samba Domain Controllers» для безопасного раскатывания обновления на сеть контроллеров домена — порядок (сначала DC без FSMO-ролей, держатели ролей в конце, samba-tool drs showrepl после каждого шага) разобран в Обновление нескольких DC.
  • Учитывать совместимость базы данных при понижении версии AD DC через границу мажорного релиза.

Заблуждения о Samba 4

  • При обновлении до Samba 4 и новее миграция на Active Directory не требуется: поддержка AD DC — лишь одно из нововведений Samba 4.0, а все новые версии включают возможности прежних, в том числе NT4-style (classic) домены. Обновить Samba 3.x PDC можно так же, как раньше обновлялись, например, с 3.4.x до 3.5.x.
  • Поддержка создания новых NT4-style PDC сохраняется, но начиная с Samba 4.13.0 часть требуемых SMBv1-параметров объявлена устаревшей — соответственно, устарели и NT4-style домены (удалять их планируется ещё нескоро; команда Samba рекомендует по возможности переходить на AD).

Заметные изменения, требующие внимания после обновления

Общий совет страницы: всегда читать release notes всех версий между предыдущей и целевой.

Все режимы установки

  • Права на исполнение файлов (4.0.0 и новее). Раньше Samba не проверяла x-бит, и файлы (*.exe, *.bat) исполнялись на шаре даже без него. Теперь без x-бита файл не исполнится. Чтобы вернуть прежнее поведение, в отдельных шарах или в секции [global]:
    acl allow execute always = yes

Контроллеры домена AD

  • Бэкенд ntvfs отключён (4.5.0 и новее). Никогда не поддерживавшийся файловый бэкенд ntvfs больше не собирается по умолчанию; при запуске samba на DC с ntvfs в лог пишется:
    Failed to start service 'smb' - NT_STATUS_INVALID_SYSTEM_SERVICE
STATUS=daemon failed to start: Samba failed to start services, error code -1073741796
    Решение — мигрировать файловый бэкенд DC на поддерживаемый s3fs (страница «Migrating the ntvfs File Server Back End to s3fs»).
  • Исправление атрибутов replPropertyMetaData (4.5.0 и новее). До 4.5.0 атрибут replPropertyMetaData хранился неверно (например, конфликты при переименовании). Проверка:
    # samba-tool dbcheck --cross-ncs
    Исправление:
    # samba-tool dbcheck --cross-ncs --fix --yes
    Проверку и исправление нужно выполнить на всех контроллерах домена (см. «Подводные камни»).
  • Недоступны шары на DC, если в smb.conf заданы idmap config (4.4.6 и новее). По умолчанию winbindd на DC генерирует ID локально и хранит их в idmap.ldb; раньше параметры idmap config в smb.conf на DC игнорировались, но из-за бага в 4.4.6+ клиенты перестают подключаться к шарам на DC. Решение: удалить все параметры idmap config из smb.conf на DC, перезапустить службу samba, перезапустить клиенты.
  • Новый умолчальный параметр LDAP требует строгой аутентификации (4.4.1 / 4.3.7 / 4.2.10 и новее). Обновления безопасности ввели опцию ldap server require strong auth со значением по умолчанию yes — разрешены только simple bind по TLS-шифрованному соединению. (4.4.1/4.3.7/4.2.10 — первые сборки с этой опцией: они были выпущены только вендорам и содержали регрессию; публичные security-релизы — 4.4.2/4.3.8/4.2.11. Подробнее — Харденинг Samba AD DC и LDAPS Сертификаты AD DC.) Внешние LDAP-приложения без TLS получают ошибку:
    ldap_bind: Strong(er) authentication required (8)
       additional info: BindSimple: Transport encryption required.
  • Очистка базы AD от удалённых LDAP DNS-записей (4.1.12 и новее). Раньше для удалённых DNS-записей некорректно создавались удалённые объекты AD; исправленная версия при старте первого DC удаляет их все, из-за чего возможна временно медленная работа.
  • Неверные права на TLS-файлы (4.1.2 / 4.0.12 и новее). Раньше *.pem-файлы для LDAP TLS создавались с небезопасными правами. Удалить их на всех DC:
    # rm /usr/local/samba/private/tls/*.pem
    После удаления перезапустить Samba — сертификаты будут созданы заново автоматически.
  • Проблемы динамического обновления DNS (4.0.7 и новее) — см. страницу «Fix DNS dynamic updates in Samba versions prior 4.0.7».
  • Неверные ACL на Sysvol и каталогах (при обновлении с ранних 4.0.x, 4.0 beta и release candidate). Сброс неверных ACL Sysvol:
    # samba-tool ntacl sysvolreset
    Сброс всех well-known ACL в каталоге:
    # samba-tool dbcheck --cross-ncs --reset-well-known-acls --fix
    Исправление ошибок в базе AD:
    # samba-tool dbcheck --cross-ncs --fix

Доменные члены Samba

  • Проверка конфигурации ID mapping (4.6.0 и новее). Раньше неверная конфигурация ID mapping (перекрывающиеся диапазоны, неверные бэкенды для default-домена) приводила к тому, что winbindd стартовал, а маппинг не работал. Теперь testparm сообщает об ошибках, например:
    ERROR: The idmap range for the domain * (tdb) overlaps with the range of SAMDOM (ad)!
ERROR: Do not use the 'ad' backend as the default idmap backend!
    а winbindd при неверной конфигурации больше не стартует и пишет в лог, например:
    main: FATAL: Invalid idmap backend ad configured as the default backend!
    Подробности о поддерживаемых бэкендах — на странице «Identity Mapping Back Ends» и в разделе IDENTITY MAPPING CONSIDERATIONS man-страницы smb.conf(5).
  • Бэкенд id mapping «ad» поддерживает RFC2307 или template-режим по домену (4.6.0 и новее). Новый параметр idmap config domain_name:unix_nss_info задаёт на уровне каждого домена AD, брать ли shell и домашний каталог пользователей из AD или применять template shell/template homedir. Он имеет приоритет над глобальным winbind nss info = rfc2307; умолчание no — значения берутся из template. Чтобы снова получать значения из AD, в секции [global] файла smb.conf:
    idmap config domain_name:unix_nss_info = yes

Подводные камни

  • При сборке из исходников заменяйте всю установку. Код может быть удалён между версиями; если установить новую сборку поверх старой, на диске могут остаться старые библиотеки, что приводит к ошибкам. На пакетные обновления из дистрибутива это не влияет.
  • --yes исправляет все найденные проблемы, а не только replPropertyMetaData — предупреждение на странице выделено отдельно.
  • replPropertyMetaData — нережлицируемый атрибут: изменения не реплицируются на другие DC, поэтому проверку и исправление (samba-tool dbcheck --cross-ncs --fix --yes) нужно выполнить на всех контроллерах домена.
  • Понижение версии AD DC через границу мажорного релиза — учитывайте совместимость базы данных Active Directory.
  • Начиная с Samba 4.13.0 NT4-style домены объявлены устаревшими (декларирована устарелость части SMBv1-параметров); удалят их не скоро, но команду Samba рекомендует по возможности переходить на AD.
  • Файлы без x-бита больше не исполняются (с 4.0.0) — при обновлении исполняемые на шарах файлы могут перестать запускаться; временное решение — acl allow execute always = yes.
  • ldap server require strong auth = yes по умолчанию — внешние приложения, подключающиеся к AD по LDAP без шифрования TLS, не смогут установить соединение.
  • После обновления 4.4.6+ не задавайте idmap config в smb.conf на DC — из-за бага клиенты не смогут подключаться к шарам на контроллере домена; параметры нужно удалить и перезапустить samba и клиенты.
