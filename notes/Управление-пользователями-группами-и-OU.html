База знаний Samba AD DC

Управление пользователями, группами и OU через samba-tool

Суть

samba-tool — штатная утилита администрирования Samba AD DC: пользователи, группы, организационные подразделения (OU), компьютеры, делегирование Kerberos и парольные политики. Работает в двух режимах: локально на контроллере домена (читает и пишет sam.ldb напрямую, нужны права root, логин не требуется) и удалённо по LDAP (-H ldap://dc1.samdom.example.com -U 'SAMDOM\administrator', пароль спросится интерактивно). Все команды и опции ниже сверены с установленной Samba 4.22.11 — на других версиях сверяйтесь с samba-tool <раздел> <подкоманда> --help.

Общие принципы и опции

  • Короткие DN. Там, где команда принимает DN OU (--userou, --groupou, --computerou, listobjects), достаточно короткой формы 'OU=Отделы' — DN домена подставляется автоматически. Для move/rename указывайте полный DN родителя.
  • Базовый DN для списков. У user list, group list, user show и т.п. есть -b/--base-dn, чтобы ограничить выборку подразделением.
  • Фильтры. Многие команды принимают вместо имени --filter <LDAP-фильтр> — операция применится ко всем совпавшим объектам (осторожно!).
  • Формат вывода. --full-dn — полный DN; --hide-disabled, --hide-expired, --locked-only — фильтры учётных записей.
  • Справка. samba-tool user --help — список подкоманд; samba-tool user create --help — все опции.
  • Пароли в скриптах. Не передавайте --password в командной строке (виден в ps); используйте интерактивный ввод или переменные PASSWD / PASSWD_FD / PASSWD_FILE (см. Мониторинг и автоматизация Samba AD DC).

Пользователи — samba-tool user

Полный список подкоманд: add, addunixattrs, auth, create, delete, disable, edit, enable, get-kerberos-ticket, getgroups, getpassword, list, move, password, rename, sensitive, setexpiry, setpassword, setprimarygroup, show, syncpasswords, unlock.

Создание и удаление

# samba-tool user create ivanov 'Str0ng!Passw0rd' \
    --given-name=Иван --surname=Иванов \
    --userou='OU=Отделы' --mail-address=ivanov@example.com

# samba-tool user add petrov 'Str0ng!Passw0rd'    # синоним create
# samba-tool user delete petrov

Ключевые опции create/add (проверено по help): --must-change-at-next-login, --random-password (пароль не указывается), --smartcard-required, --use-username-as-cn, --userou=, --given-name=, --surname=, --initials=, --profile-path=, --script-path=, --home-drive=, --home-directory=.

Просмотр и выборки

# samba-tool user list
# samba-tool user list --full-dn --hide-disabled
# samba-tool user list -b 'OU=Отделы'
# samba-tool user show ivanov
# samba-tool user getgroups ivanov          # прямые группы пользователя

Изменение и перемещение

# samba-tool user edit ivanov               # открывает редактор AD-объекта
# samba-tool user move ivanov 'OU=IT,DC=samdom,DC=example,DC=com'
# samba-tool user rename ivanov             # переименование (CN и связанные атрибуты)

Включение, блокировка, срок действия

# samba-tool user disable ivanov
# samba-tool user enable ivanov
# samba-tool user unlock ivanov
# samba-tool user setexpiry ivanov --days=90
# samba-tool user setexpiry ivanov --noexpiry
# samba-tool user disable --filter '(description=temp-*)'   # массово, осторожно

Пароли

# samba-tool user setpassword ivanov        # задать/сбросить пароль (запросит)
# samba-tool user password                  # сменить СВОЙ пароль
# samba-tool user getpassword ivanov --attributes=virtualClearTextUTF8
# samba-tool user getpassword ivanov --attributes=virtualCryptSHA512

getpassword умеет виртуальные атрибуты: unicodePwd, virtualClearTextUTF16, virtualClearTextUTF8, virtualCryptSHA256, virtualCryptSHA512, virtualKerberosSalt, virtualSSHA, virtualSambaGPG, virtualWDigest01..29; есть --decrypt-samba-gpg (только если SambaGPG-пароль сохранён).

Unix-атрибуты (RFC2307)

# samba-tool user addunixattrs ivanov 10001 \
    --gid-number=10001 --login-shell=/bin/bash \
    --unix-home=/home/ivanov --gecos='Иван Иванов'

Требуются NIS-расширения схемы (--use-rfc2307 при provision) и idmap-бэкенд ad на членах домена — см. Idmap бэкенды и RFC2307.

Прочее

# samba-tool user sensitive ivanov show|on|off   # флаг UF_NOT_DELEGATED
# samba-tool user setprimarygroup ivanov 'Domain Users'
# samba-tool user syncpasswords --cache-ldb-initialize
# samba-tool user get-kerberos-ticket ivanov
# samba-tool user auth policy|silo                # аутентификационные политики/силосы

Группы — samba-tool group

Подкоманды: add, addmembers, addunixattrs, create, delete, edit, list, listmembers, move, removemembers, rename, show, stats.

Создание

# samba-tool group add it --group-scope=Global --group-type=Security \
    --description='Отдел ИТ' --groupou='OU=Отделы'
# samba-tool group add projects --group-scope=Universal --group-type=Distribution

Опции add/create: --group-scope (Domain | Global | Universal), --group-type (Security | Distribution), --groupou=, --description=, --mail-address=, --notes=, --gid-number=, --nis-domain=, --special (предопределённая группа).

Состав и статистика

# samba-tool group list
# samba-tool group list -v                     # тип и область группы
# samba-tool group listmembers it --full-dn
# samba-tool group listmembers it --hide-disabled --hide-expired
# samba-tool group addmembers it ivanov,petrov
# samba-tool group addmembers it --member-dn='CN=ivanov,OU=Отделы,DC=...'
# samba-tool group removemembers it petrov
# samba-tool group stats                       # сводная статистика членства

Изменение и перемещение

# samba-tool group show it
# samba-tool group edit it
# samba-tool group move it 'OU=IT,DC=samdom,DC=example,DC=com'
# samba-tool group rename it
# samba-tool group delete it
# samba-tool group addunixattrs it 10001

Организационные подразделения — samba-tool ou

Подкоманды: add, create, delete, list, listobjects, move, rename.

# samba-tool ou add 'OU=Отделы' --description='Подразделения организации'
# samba-tool ou list
# samba-tool ou move 'OU=Отделы' 'OU=Company,DC=samdom,DC=example,DC=com'
# samba-tool ou rename 'OU=Отделы' 'OU=Departments,DC=samdom,DC=example,DC=com'
# samba-tool ou delete 'OU=Отделы'

ou listobjects — содержимое OU

# samba-tool ou listobjects 'OU=MiniNode1' --full-dn -H ldap://127.0.0.1 -U 'STAND\mininode2admin'
  • Выводит объекты OU: пользователи, группы, компьютеры, вложенные OU (фильтр (objectclass=*), только DN, сортировка).
  • По умолчанию — SCOPE_ONELEVEL: только прямые дети. Рекурсивно по поддереву — флаг -r/--recursive (внутри исходник включает и вложенные объекты; пустой результат при -r даёт ou "..." is empty).
  • Короткое имя 'OU=MiniNode1' автоматически дополняется DN домена (normalize_dn_in_domain).
  • --full-dn печатает полный DN. Без флага из DN вырезается суффикс домена (DC=...), то есть вывод будет вида CN=ivanov,OU=MiniNode1 — это не «относительный RDN», а DN без DC-части.
  • Сам OU в список не попадает; пустой OU → ou "OU=MiniNode1" is empty.

Компьютеры — samba-tool computer

Подкоманды: add, create, delete, edit, list, move, show.

# samba-tool computer add WS01 --computerou='OU=Рабочие станции' \
    --description='Рабочая станция бухгалтерии' \
    --ip-address=10.99.0.51 --service-principal-name='HOST/ws01'

# samba-tool computer list --hide-disabled
# samba-tool computer show WS01
# samba-tool computer move WS01 'OU=Серверы,DC=samdom,DC=example,DC=com'
# samba-tool computer delete WS01

--ip-address и --service-principal-name можно повторять; --prepare-oldjoin — подготовка учётной записи для старого механизма join.

Делегирование Kerberos — samba-tool delegation

# samba-tool delegation show ivanov
# samba-tool delegation for-any-service ivanov on     # UF_TRUSTED_FOR_DELEGATION
# samba-tool delegation for-any-protocol ivanov on    # UF_TRUSTED_TO_AUTHENTICATE_FOR_DELEGATION (S4U2Proxy)
# samba-tool delegation add-service svc_web 'HTTP/websrv.samdom.example.com'
# samba-tool delegation add-principal svc_web 'SAMDOM\svc_sql'   # RBCD
  • add-service/del-service меняют msDS-AllowedToDelegateTo (обычное ограниченное делегирование).
  • add-principal/del-principal меняют msDS-AllowedToActOnBehalfOfOtherIdentity (resource-based constrained delegation).
  • on|off включает/снимает флаги учётной записи.

Права на объекты каталога — samba-tool dsacl

Это права в AD на объекты каталога (пользователи, группы, OU, компьютеры), а не файловые ACL шар. Хранятся в атрибуте nTSecurityDescriptor самого объекта и реплицируются как обычные данные AD.

# посмотреть текущий дескриптор (SDDL)
samba-tool dsacl get --objectdn="OU=MiniNode1,DC=stand,DC=local"

# добавить ACE (команда ДОБАВЛЯЕТ запись, а не заменяет дескриптор)
samba-tool dsacl set --objectdn="OU=MiniNode1,DC=stand,DC=local" \
  --sddl="(A;;CCDCLCRPLORC;;;S-1-5-11)"

# удалить конкретный ACE
samba-tool dsacl delete --objectdn="OU=MiniNode1,DC=stand,DC=local" \
  --sddl="(A;;CCDCLCRPLORC;;;S-1-5-11)"
  • set печатает старый и новый дескриптор, предупреждает, если такой ACE уже есть, и игнорирует наследуемые ACE; удалённо — -H ldap://dc1... -U 'STAND\administrator'.
  • Альтернативный режим без --sddl: --trusteedn=<DN> --action=allow|deny --car=<право> — строит ACE для control access right: change-rid, change-pdc, change-infrastructure, change-schema, change-naming, allocate_rids, get-changes, get-changes-all, get-changes-filtered, topology-manage, topology-monitor, repl-sync, ro-repl-secret-sync (получится (OA;;CR;<GUID>;;<SID>) для allow или (OD;;CR;...) для deny).

Разбор SDDL (A;;CCDCLCRPLORC;;;SID)

Формат ACE: (Тип;Флаги;Права;GUID_объекта;GUID_наследования;SID).

  • A — allow (есть также D — deny, OA/OD — object allow/deny для extended rights);
  • флаги пусты → ACE действует только на сам объект, без наследования на дочерние (CI — контейнеры, OI — объекты, NP — без распространения, IO — наследуемый);
  • CCDCLCRPLORC — маска прав (сумма 0x00020097):
Код Право Смысл
CC CREATE_CHILD (0x1) создавать дочерние объекты в этом объекте
DC DELETE_CHILD (0x2) удалять дочерние объекты
LC LIST_CHILDREN (0x4) видеть список дочерних объектов
RP READ_PROP (0x10) читать атрибуты объекта
LO LIST_OBJECT (0x80) право «перечисления объекта» (проверка доступа)
RC READ_CONTROL (0x20000) читать сам дескриптор безопасности

Другие полезные коды: WP (запись атрибутов), DT (удалить поддерево), CR (control access / extended right), SD (удалить объект), WD (менять DACL), WO (менять владельца), GA/GR/GW/GX (generic all/read/write/execute).

Что даёт эта конкретная ACE: доверенное лицо (SID) может в указанном объекте (обычно OU) создавать и удалять дочерние объекты (например, пользователей или компьютеры), видеть их список и читать атрибуты и дескриптор — но не может менять атрибуты существующих объектов (WP нет), удалить сам объект (SD нет) или изменить его права (WD/WO нет). Типовой сценарий — делегирование: разрешить группе создавать учётки в OU или разрешить ввод компьютеров в домен в конкретное подразделение.

Меры предосторожности

  • Сначала сохраните текущий дескриптор: samba-tool dsacl get --objectdn=... > sd-before.txt; при ошибке верните ACE через delete.
  • set не заменяет SDDL целиком, а добавляет ACE — лишние записи накапливаются.
  • Ошибочная deny-ACE на OU может отрезать администрирование; проверяйте результат dsacl get сразу после изменения.
  • Права действуют немедленно и реплицируются; для проверки расхождений между DC — samba-tool ldapcmp --sd (см. Мониторинг и автоматизация Samba AD DC).
  • SID можно указывать строкой (S-1-5-11 — Authenticated Users, S-1-5-21-... — группа домена) либо через --trusteedn с DN.

Парольные и аутентификационные политики

# samba-tool domain passwordsettings show
# samba-tool domain passwordsettings set --complexity=on --min-pwd-length=12 \
    --history-length=24 --min-pwd-age=1 --max-pwd-age=60
# samba-tool domain passwordsettings set --store-plaintext=off
# samba-tool domain passwordsettings pso --help      # fine-grained PSO

Значения по умолчанию (из help): сложность on, история 24, минимальная длина 7, минимальный возраст 1 день. Политика применяется при следующей смене пароля.

Аутентификационные политики и силосы:

# samba-tool domain auth policy --help
#   computer-allowed-to-authenticate-to | create | delete | list | modify |
#   service-allowed-to-authenticate-from | service-allowed-to-authenticate-to
# samba-tool domain auth silo --help
#   create | delete | list | member | modify | view
# samba-tool user auth policy|silo --help            # привязка к пользователю

Массовые операции и эквиваленты

# все члены каждой группы
samba-tool group list | while IFS= read -r g; do
  echo "== $g"; samba-tool group listmembers "$g"
done

# пакетное создание из CSV: login;given;sn
while IFS=';' read -r login given sn; do
  samba-tool user create "$login" --random-password \
    --given-name="$given" --surname="$sn" --must-change-at-next-login
done < users.csv

Эквиваленты на уровне LDAP (без samba-tool, через ldap-клиенты):

# пользователи в OU (только прямые дети)
ldbsearch -H ldap://127.0.0.1 -U 'STAND\mininode2admin' \
  -b 'OU=MiniNode1,DC=stand,DC=...' -s one '(objectClass=user)' dn

# члены группы (атрибут member)
ldbsearch -H ldap://127.0.0.1 -U 'STAND\mininode2admin' \
  -b 'CN=it,OU=Отделы,DC=...' -s base '(objectClass=group)' member

Подводные камни

  • Локальный режим — только на DC и от root. Удалённо (-H ldap://...) обязателен -U, иначе анонимный/LDAP-запрос не пройдёт.
  • ou listobjects по умолчанию не рекурсивен — вложенные OU не раскрываются без -r.
  • --full-dn меняет формат: без него у listobjects отрезается суффикс домена, а не OU.
  • --filter опасен: disable, setpassword, setexpiry с фильтром затрагивают все совпавшие учётки.
  • Непустой OU: сначала перенесите/удалите объекты, затем удаляйте OU.
  • Парольные политики действуют при следующей смене пароля; уже существующие пароли не перестают работать.
  • addunixattrs требует NIS-расширений (--use-rfc2307 при provision) и согласованного idmap-диапазона; иначе атрибуты есть, а Unix их не видит.
  • user setpassword ≠ user password: первый сбрасывает пароль другому (нужны права), второй меняет свой.
  • Пароли на командной строке видны в истории и ps; используйте PASSWD_FILE.
  • rm-уровня защиты нет: delete удаляет объект сразу, корзина AD (tombstones) — отдельная тема.
