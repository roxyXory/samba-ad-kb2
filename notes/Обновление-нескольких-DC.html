База знаний Samba AD DC

Обновление нескольких контроллеров домена

Суть

Страница «Upgrading a Samba AD DC» — дополнение к общей процедуре обновления (Обновление Samba) для AD DC, включая порядок обновления сети из нескольких контроллеров: в каком очерёдности обновлять DC, что проверять после каждого шага и когда вместо обновления на месте использовать метод «демоция + rejoin». Базовые шаги для одиночного DC: бэкап домена → остановить службы → установить новую версию поверх (те же опции configure при сборке из исходников) → запустить samba → samba-tool dbcheck → проверить логи и вход пользователей.

Ключевое

Подготовка (перед обновлением любого DC)

  • Создать бэкап домена хотя бы на одном DC, лучше на держателе PDC_Emulator: samba-tool domain backup (см. Резервное копирование и восстановление AD DC).
  • Прочитать release notes всех пропущенных версий (для 4.4.4 → 4.6.2 — notes 4.5.0 … 4.6.2).
  • При сборке из исходников — те же опции configure, что и раньше.
  • Не вносить изменений в AD во время обновления; выбирать время низкой нагрузки.

Порядок обновления нескольких DC

  • Обновляют по одному, начиная с DC без FSMO-ролей (или с наименьшим их числом); держатели FSMO-ролей — последними (см. Передача и захват FSMO ролей).
  • Логика: если у первого DC без ролей что-то пойдёт не так, его можно откатить без простоя сети и потери данных — PDC_Emulator и остальные продолжают работать.
  • После запуска Samba на обновлённом DC проверить репликацию:
# samba-tool drs showrepl
  • Убедиться, что новая версия работает, и только затем переходить к следующему DC.

Проверка базы после обновления

# samba-tool dbcheck --cross-ncs

--cross-ncs проверяет все партиции каталога, включая DNS-партиции (см. Диагностика AD DC).

Альтернатива при смене мажорной версии: DC rejoin

Для перехода на новую мажорную версию вместо in-place обновления применяют метод «демоция + переустановка + повторный join» (требует минимум двух DC, установку не старее v4.7 и схему 2008R2):

  1. Убедиться в репликации (при необходимости форсировать: samba-tool drs replicate).
  2. Передать FSMO-роли с этого DC другим.
  3. Понизить роль: samba-tool domain demote -U administrator (см. Понижение роли AD DC).
  4. Полностью удалить старую Samba, установить новую версию.
  5. Присоединить заново: samba-tool domain join <realm> dc (см. Присоединение второго DC к домену).

Метод пригоден и для миграции с 32-бит на 64-бит, и со сборки из исходников на пакетную.

Подводные камни

  • Не обновлять FSMO-держатель первым — сначала DC без ролей, роли в конце.
  • In-place — для минорных релизов (например, 4.10.5 → 4.10.6). При сборке из исходников в дереве остаются старые файлы, способные помешать запуску, — так нельзя перепрыгивать мажорные версии (например, 4.14.x → 4.15.0).
  • Не выполнять во время обновления samba-tool-команды, модифицирующие базу на диске, — только после перезапуска samba.
  • Понижение версии через границу мажорного релиза (например, 4.11 → 4.10) требует особой внимательности к совместимости баз данных — отдельная страница «Downgrading an Active Directory DC» (см. также Обновление Samba).
  • В хранилище есть смежное: Репликация SysVol — про содержимое SysVol, которое не реплицируется самим Samba ни при каком обновлении.
