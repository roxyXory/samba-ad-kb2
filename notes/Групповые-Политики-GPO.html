Групповые политики (GPO) в Samba AD DC

Суть

Group Policy даёт централизованное управление настройками операционной системы, приложений и пользователей. Политики доставляются клиентам через LDAP: записи groupPolicyContainer, атрибут gPCFileSysPath которых указывает на каталог политики на share SYSVOL (\\<домен>\sysvol\<домен>\Policies\<GUID>). В Samba AD DC GPO можно создавать и редактировать как через Windows-оснастку Group Policy Management (из состава RSAT), так и командой samba-tool gpo; на Linux-членах домена политики применяет samba-gpupdate — при включённой в winbind опции apply group policies = yes.

Ключевое

Где хранятся GPO

  • Клиент получает список политик из LDAP, из объектов groupPolicyContainer; каждый объект предоставляет атрибут gPCFileSysPath — путь к информации политики на share SYSVOL домена (wiki: «Policies are delivered to clients by listing them in LDAP, under groupPolicyContainer objects. These objects provide the gPCFileSysPath attribute, which points to policy information stored on the domains SYSVOL share»).
  • Каталог GPO на SYSVOL выглядит как \\<realm>\sysvol\<realm>\Policies\{GUID}. Вывод samba-tool gpo listall -UAdministrator (дословно с вики):
  # samba-tool gpo listall -UAdministrator
  GPO          : {31B2F340-016D-11D2-945F-00C04FB984F9}
  display name : Default Domain Policy
  path         : \\example.com\sysvol\example.com\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}
  dn           : CN={31B2F340-016D-11D2-945F-00C04FB984F9},CN=Policies,CN=System,DC=example,DC=com
  version      : 2097290
  flags         : NONE
  • Первый атрибут каждой строки — GUID GPO; он нужен, чтобы идентифицировать политику во всех остальных командах samba-tool gpo.
  • Привязка политики к контейнеру (домен, OU, сайт) делается через атрибут gPLink: samba-tool gpo setlink <container_dn> <gpo> (есть опции --disable и --enforce); снять привязку — samba-tool gpo dellink <container_dn> <gpo>, посмотреть привязки контейнера — gpo getlink <container_dn>, найти контейнеры, куда привязана GPO, — gpo listcontainers <gpo>, наследование — gpo getinheritance <container_dn> / gpo setinheritance <container_dn> block|inherit.
  • Интервал применения: wiki говорит «случайный интервал между 90 и 120 секундами»; release notes 4.14 и man-страница smb.conf — «каждые 90 минут плюс случайная добавка от 0 до 30 минут». См. «Подводные камни».
  • На Windows-члене домена политики применяются автоматически, вручную — gpupdate /force. На Linux-члене — samba-gpupdate --force.

Подкоманды samba-tool gpo (по текущей man-странице samba-tool.8)

Команда Назначение
gpo listall список всех GPO
gpo list <username> GPO, применяемые к учётной записи
gpo show <gpo> сведения о GPO
gpo create <displayname> / gpo del <gpo> создать пустую / удалить GPO
gpo setlink / dellink / getlink / listcontainers / getinheritance / setinheritance работа с привязкой GPO к контейнеру (атрибут gPLink)
gpo fetch <gpo> скачать GPO с DC (копирует каталог GPO в локальный каталог)
gpo load <gpo> залить в GPO registry-политики из JSON (stdin или --content); --machine-ext-name / --user-ext-name дописывают значения в gPCMachineExtensionNames / gPCUserExtensionNames, --replace заменяет политики вместо слияния
gpo remove <gpo> удалить политики из GPO (тот же JSON-формат через stdin или --content)
gpo backup <gpo> / gpo restore <displayname> <backup location> бэкап и восстановление GPO (см. ниже)
gpo admxload загрузка ADMX-шаблонов на SYSVOL (см. ниже)
gpo aclcheck «Check all GPOs have matching LDAP and DS ACLs» — сверка LDAP- и DS-ACL у GPO
gpo manage ... Linux-политики (см. ниже)
gpo cse list / register <cse_file> <cse_name> / unregister <GUID> регистрация Client Side Extension на текущем хосте: нужен хотя бы один из флагов --machine или --user; файл CSE должен лежать на постоянном пути — команда его не копирует

Пример JSON-входа для gpo load (с man-страницы):

[
    {
        "keyname": "Software\Policies\Mozilla\Firefox\Homepage",
        "valuename": "StartPage",
        "class": "USER",
        "type": "REG_SZ",
        "data": "homepage"
    }
]

Допустимые классы: MACHINE|USER|BOTH. Опции --machine-ext-name / --user-ext-name нужны потому, что Windows Group Policy требует корректных GUID клиентских расширений в gPCMachineExtensionNames / gPCUserExtensionNames; Linux-политики этого ограничения не имеют. По умолчанию добавляется {35378EAC-683F-11D2-A89A-00C04FBBCFA2}, включающий большинство registry-политик.

Загрузка ADMX-шаблонов

  • Шаблоны Samba загружаются командой:
$ samba-tool gpo admxload -U Administrator

Команда копирует ADMX Samba в каталог <domain>/Policies/PolicyDefinitions на share SYSVOL. Каталог по умолчанию — ${data_dir}/samba/admx (по исходникам команды).

  • Важно: установив только шаблоны Samba, нельзя администрировать Windows-члены — обязательно нужны и шаблоны Microsoft (предупреждение на вики).
  • При нескольких DC команду запускают с -H, чтобы шаблоны попали на нужный DC: samba-tool gpo admxload -H ldap://dc1.samdom.example.com -U Administrator.
  • Шаблоны Microsoft: скачать последние Administrative Templates для своей версии ОС, распаковать msiextract (пакет msitools в Debian/Ubuntu, RHEL/CentOS, Arch AUR) и загрузить (пример вики для Windows 10 22H2):
$ msiextract /path/to/microsoft/download/Administrative\ Templates\ \(.admx\)\ for\ Windows\ 10\ October\ 2022\ Update.msi
$ samba-tool gpo admxload -U Administrator --admx-dir=/path/to/extracted/msi/Program\ Files/Microsoft\ Group\ Policy/Windows\ 10\ October\ 2022\ Update\ \(22H2\)/PolicyDefinitions/
  • admxload печатает предупреждение: загрузка в Central Store мешает Windows показывать собственные шаблоны в Group Policy Management Console, пока туда не установлены шаблоны Microsoft.
  • Тем же способом (--admx-dir=) ставятся сторонние шаблоны: Mozilla policy-templates, Google Chrome policy_templates.

Бэкап, восстановление и перенос GPO между доменами (Samba 4.10+)

  • Порядок из wiki: создать GPO обычными средствами (Windows Group Policy Management) → узнать GUID (например, samba-tool gpo listall) → выполнить бэкап → при необходимости восстановить:
samba-tool gpo backup <GPO GUID>
samba-tool gpo restore <new GPO name> <path generated from backup>
  • Бэкап читает конфигурационные файлы GPO и сохраняет их как обобщённые (generalized) XML-файлы, а также бинарный дубликат на случай, если восстановление из XML не удастся. Файлы можно править руками, но повредить их при этом легко.
  • Обобщение для переноса в другой домен (Samba 4.10):
samba-tool gpo backup --generalize --entities=<output path>

Существуют три типа сущностей (entities): user ID (SID, имена пользователей), ACL (SDDL), share paths (пути \\unc). Пример вывода с вики:

<!ENTITY SAMBA__NETWORK_PATH__82419dafed126a07d6b96c66fc943735__ "\\realm.com">
<!ENTITY SAMBA__NETWORK_PATH__0484cd41ded45a0728333a9c5e5ef619__ "\\test">
<!ENTITY SAMBA____SDDL_ACL____4ce8277be3f630300cbcf80a80e21cf4__ "D:PAR(A;CI;KA;;;BA)(A;CIIO;KA;;;CO)(A;CI;KR;;;S-1-0-0)">
<!ENTITY SAMBA____USER_ID_____d0970f5a1e19cb803f916c203d5c39c4__ "*S-1-5-21-3075996733-1131693954-1131023892-501">
<!ENTITY SAMBA____USER_ID_____7b7bc2512ee1fedcd76bdc68926d4f7b__ "Guest">
  • При переносе в другой домен эти entities правят на значения нового домена и восстанавливают командой:
samba-tool gpo restore --entities=<new entities file>
  • После восстановления настройки нужно проверять: содержимое GPO можно менять вручную, поэтому применятся они не обязательно так, как ожидается. Опция --restore-metadata сохраняет старый GPT.INI и связанный с ним номер версии (man-страница).
  • Генерализация неполная: поддерживается лишь подмножество файлов. Известные непокрытые форматы: aas-файлы (software installation); xml-файлы (preferences, ярлыки); статус admx неизвестен. У Windows-миграционных таблиц, по замечанию страницы, пробелы тоже есть.

Применение на Linux-членах домена (Samba 4.14+)

  • winbind: включить на клиенте глобальную опцию apply group policies = yes.
  • SSSD: применение политик выполняется через oddjob-gpupdate, при этом samba-gpupdate из Samba должен быть установлен.
  • Release notes 4.14: политики применяются «каждые 90 минут, плюс случайная задержка от 0 до 30 минут». Опция smb.conf gpo update command задаёт, какая команда вызывается для применения GPO (по умолчанию ${prefix}/sbin/samba-gpupdate); на KDC samba-gpupdate применяет System Access и Kerberos-политики: minPwdAge, maxPwdAge, minPwdLength, pwdProperties в samdb и kdc:service ticket lifetime, kdc:user ticket lifetime, kdc:renewal lifetime в smb.conf. Написания в источниках различаются: man-страница и KDC-код используют форму с пробелами (kdc:user ticket lifetime в smb.conf), а GP-расширение Samba хранит те же значения в GPO-хранилище gpo.tdb под ключами с подчёркиванием (kdc:user_ticket_lifetime); разбор и практический вывод — в Доверительные отношения между доменами.
  • Политики Samba — нетатуирующие (non-tattooing): при удалении GPO из компьютера/пользователя изменения снимаются с члена домена. Управление:
samba-gpupdate --force      # применить/переприменить политики
samba-gpupdate --unapply    # снять применённые политики (требует root)
samba-gpupdate --rsop       # показать Resultant Set of Policy
  • Опции samba-gpupdate: -X/--unapply, --force, --rsop, --target=Computer|User (по умолчанию Computer) плюс штатные группы credential-опций (учётные данные, -U). Примеры с вики:
samba-gpupdate --unapply --target=Computer
samba-gpupdate --unapply --target=User -U<username>
  • Состояние применённых политик хранится в базе gpo.tdb в cache directory; список CSE (встроенных и зарегистрированных) samba-gpupdate получает при запуске, собственные CSE регистрируются через samba-tool gpo cse register.
  • Windows удалять применённые политики не умеет: единственный обходной путь — вывести машину из домена и применить политики заново (gpupdate /force /boot).

Linux-политики через samba-tool gpo manage

Каталог samba-tool gpo manage (текущая man-страница) — подкоманды sudoers, security, smb_conf, symlink, files, openssh, scripts, motd, issue, access. Примеры с вики:

  • Sudoers (совместимость с Vintela): samba-tool gpo manage sudoers add {31B2F340-016D-11D2-945F-00C04FB984F9} ALL ALL fakeu fakeg — на клиенте появляется файл /etc/sudoers.d/gp_XXXXX с записью fakeu,fakeg% ALL=(ALL) NOPASSWD: ALL.
  • MOTD/Issue: samba-tool gpo manage motd|issue set — задают содержимое /etc/motd и /etc/issue (VGP-совместимые расширения).
  • OpenSSH: samba-tool gpo manage openssh set {GUID} KerberosAuthentication Yes — настройки в /etc/ssh/sshd_config.d.
  • Startup-скрипты: samba-tool gpo manage scripts startup add {GUID} test_script.sh '-n' — скрипт загружается на SYSVOL и запускается клиентами при старте (с параметром -n).
  • Files: samba-tool gpo manage files add {GUID} ./source.txt /usr/share/doc/target.txt root root 600 — файл с SYSVOL раскладывается на клиенты с owner:group и правами.
  • Symlink: samba-tool gpo manage symlink add {GUID} /tmp/source /tmp/target.
  • Access (PAM, совместимость с Vintela Access Group Policy): samba-tool gpo manage access add {GUID} allow goodguy example.com — правило в /etc/security/access.d/0000000001_gp.conf.
  • Security: samba-tool gpo manage security set {GUID} MaxTicketAge 10; возможные политики — MaxTicketAge (в часах), MaxServiceAge (в минутах), MaxRenewAge (в минутах), MinimumPasswordAge/MaximumPasswordAge (в днях), MinimumPasswordLength, PasswordComplexity (1/0). Эти настройки применяются только на AD DC.
  • smb.conf: samba-tool gpo manage smb_conf set {GUID} 'apply gpo policies' yes — рассылает глобальные опции smb.conf клиентам. idmap-политики через неё применить нельзя.
  • Политики из GPMC, для которых нет gpo manage-команд: Sudo Rights, Messages, Scripts, GNOME Settings, Firewalld, Firefox, Chromium/Chrome (последние три — сторонние шаблоны через admxload --admx-dir); результат применения — файлы вида /etc/sudoers.d/gp_*, /etc/cron.daily/tmp*, /etc/motd, /etc/issue, /etc/security/access.d/*, /etc/chromium|/etc/opt/chrome policies.json, /usr/lib64/firefox/distribution/policies.json и др.
  • Для совместимости с Centrify есть расширения для crontab-записей и sudoers: при наличии таких GPO от Centrify они применяются samba-gpupdate автоматически.

Windows-члены, GPMC и RSAT

  • Создание и редактирование GPO: Group Policy Management Console (GPMC) входит в Windows RSAT; в ADUC-подобном дереве выбирают домен/контейнер и в меню Action выбирают «Create a GPO in this domain, and Link it here»; редактирование — Edit.
  • Политики Samba в редакторе лежат в User (или Computer) Configuration > Policies > Administrative Templates > Samba. Для Samba Domain Controllers применяются также Password и Kerberos настройки: Computer Configuration > Policies > OS Settings > Security Settings > Account Policy (минимальный/максимальный возраст пароля, минимальная длина, сложность; времена жизни Kerberos-билетов).
  • Windows-члены применяют политики автоматически; вручную — gpupdate /force.
  • Установка RSAT: на Windows 10 (1809 и новее) — через «Optional features»; например, в elevated-консоли:
dism /online /add-capability /CapabilityName:Rsat.GroupPolicy.Management.Tools~~~~0.0.1.0 /CapabilityName:Rsat.Dns.Tools~~~~0.0.1.0 /CapabilityName:Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0

На Windows Server — через Server Manager → Add roles and features, компонент Group Policy Management.

  • Администрирование должно идти от имени пользователя с достаточными правами; admxload в SYSVOL возвращает «The authenticated user does not have sufficient privileges», если прав не хватает.
  • Ограничение: Server for NIS Tools (вкладка Unix Attributes в ADUC для RFC2307) не поддерживается на Windows 10 и Windows Server 2016 — вкладки Unix Attributes там нет. Обходной путь — задавать атрибуты вручную через вкладку Attributes (нужен включённый в оснастке режим Advanced Features): msSFU30NisDomain, uidNumber, loginShell, unixHomeDirectory, primaryGroupID (пользователи), msSFU30NisDomain, gidNumber (группы). При ручной настройке UID/GID нужно самостоятельно следить за последними использованными номерами.

Подводные камни

  • Расхождение про интервал применения: wiki Samba пишет «enforced at a random interval between 90 and 120 seconds», тогда как release notes 4.14 и man-страница smb.conf говорят про 90 минут плюс случайные 0–30 минут. Формулировку вики следует считать опечаткой (seconds вместо minutes) — сверяйтесь с release notes/man.
  • Без шаблонов Microsoft администрировать Windows-члены нельзя: вики прямо предупреждает, что после установки ADMX Samba обязательно надо поставить и ADMX Microsoft.
  • msiextract берётся из пакета msitools; без него распаковать MSI с Administrative Templates не получится.
  • Несколько DC: admxload (и другие gpo-команды) надо направлять на нужный DC через -H, иначе шаблоны/изменения попадут не на тот сервер; сами GPO в SYSVOL между DC по-прежнему требуют репликации средствами Репликация SysVol.
  • Известные дефекты Samba 4.10 (на странице GPO Backup and Restore помечены как открытые, без бэкпортов):
    • BUG #13825 — файлы GPE.INI ломают backup (обход: временно убрать GPE.INI и скопировать вручную);
    • BUG #13806 — сбой GPT.INI при не-ASCII (акцентированных) display name GPO (обход: избегать не-ASCII имён; либо править GPT.INI руками, не тестировалось);
    • BUG #13627 — восстановленный GPO не включается сразу: значения gPCMachineExtensionNames / gPCUserExtensionNames не проставляются (обход: скопировать их по LDAP с исходного DC; в master это делается автоматически, но нужен новый бэкап). Исправления — в master (поздних версиях), а не в 4.10.
  • Генерализация неполная и у Windows-миграционных таблиц есть пробелы: перенос между доменами всегда проверяйте после restore.
  • Файлы бэкапа — XML, но правка вручную легко повреждает GPO (страница отмечает и обратный режим — fallback на бинарные дубликаты, который маскирует ошибки восстановления).
  • Windows не умеет снимать применённые политики — только unjoin домена + gpupdate /force /boot; нетатуирующее поведение — свойство Samba-политик на Linux-клиентах.
  • gpo manage security применим только к AD DC; для работы нужны права на запись в SYSVOL.
  • smb.conf-политика не умеет idmap: она рассылает глобальные опции smb.conf, но idmap-настройки применить через неё нельзя (вики).
  • Конфликт message-политик: одновременное применение Samba- и VGP-политик /etc/motd и /etc/issue перезаписывает результаты друг друга — предсказуемости не будет (предупреждение вики).
  • Снятие применённых политик требует root (samba-gpupdate --unapply).
  • Документация местами повреждена копипастом: в man-странице samba-tool.8 у gpo aclcheck осталось описание «Create an empty GPO.», а у gpo remove — «Show information for a GPO.» (оба попали из соседних команд); ориентируйтесь на фактическое назначение и --help.
  • Бинарные дубликаты и fallback маскируют ошибки: в каталоге бэкапа рядом с каждым XML лежит бинарная копия файла с суффиксом .SAMBABACKUP; если XML не разобрался, restore молча берёт бинарный файл (в исходниках помечено, что fallback нельзя отключить, поэтому «то, что должно падать, часто не падает»).

  • https://wiki.samba.org/index.php/GPO_Backup_and_Restore — бэкап/восстановление и generalize, entities, известные ошибки 4.10, непокрытые форматы (assets/Групповые-Политики-GPO-2.html).
  • https://www.samba.org/samba/docs/current/man-html/samba-tool.8.html — man-страница: подкоманды gpo и их опции, JSON для gpo load/remove, gpo manage ..., gpo cse (assets/Групповые-Политики-GPO-3.html).
  • https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html — опции apply group policies и gpo update command, интервал 90 минут + 0–30.
  • https://www.samba.org/samba/history/samba-4.14.0.html — клиентские Group Policy в 4.14: apply group policies, интервал, нетатуирующая семантика, samba-gpupdate --unapply/--force/--rsop, admxload, gpo manage (assets/Групповые-Политики-GPO-4.html).
  • https://wiki.samba.org/index.php/Installing_RSAT — GPMC в составе RSAT, способы установки RSAT, отсутствие вкладки Unix Attributes на Windows 10/Server 2016 и ручная установка RFC2307-атрибутов (assets/Групповые-Политики-GPO-5.html).
  • https://www.samba.org/samba/history/samba-4.9.0.html — переименование samba_gpoupdate → samba_gpupdate.
  • https://www.samba.org/samba/history/samba-4.10.0.html — появление samba-tool gpo backup/restore, поддержка SMBv2 для gpo-команд.
  • https://www.samba.org/samba/history/samba-4.16.0.html — Certificate Auto Enrollment через групповую политику.
  • https://www.samba.org/samba/history/samba-4.19.0.html — изменения gpupdate (python-реализация get_gpo_list).
  • https://www.samba.org/samba/history/samba-4.20.0.html — исправления samba-gpupdate (site support, logging).
  • https://gitlab.com/samba-team/samba/-/raw/master/source4/scripting/bin/samba-gpupdate — исходник samba-gpupdate: опции -X/--unapply, --force, --rsop, --target.
  • https://gitlab.com/samba-team/samba/-/raw/master/python/samba/netcmd/gpo.py — исходник samba-tool gpo: список подкоманд, опции setlink (--disable/--enforce), fetch, admxload (default-dir, предупреждение), cse register.
  • https://gitlab.com/samba-team/samba/-/raw/master/docs-xml/manpages/samba-tool.8.xml — исходный текст man-страницы (проверка названий подкоманд и копипаст-артефактов).
  • https://gitlab.com/samba-team/samba/-/blob/samba-4.9.0/python/samba/netcmd/gpo.py, https://gitlab.com/samba-team/samba/-/blob/samba-4.12.0/python/samba/netcmd/gpo.py и https://gitlab.com/samba-team/samba/-/blob/samba-4.13.0/python/samba/netcmd/gpo.py — проверка версий по git-тегам: состав подкоманд в 4.9.0 (show, list, fetch, setlink, dellink, getlink, listcontainers, getinheritance, setinheritance, listall, create, del, aclcheck); admxload отсутствует в 4.12.0 и появляется в 4.13.0.
  • https://bugzilla.samba.org/show_bug.cgi?id=13825, https://bugzilla.samba.org/show_bug.cgi?id=13806, https://bugzilla.samba.org/show_bug.cgi?id=13627 — открытые дефекты backup/restore на момент Samba 4.10.
