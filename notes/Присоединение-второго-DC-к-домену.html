База знаний Samba AD DC

Присоединение второго DC к домену

Суть

Один контроллер домена (DC) достаточен для работающего леса Active Directory (AD), но ради отказоустойчивости и балансировки нагрузки в лес стоит добавить дополнительные DC. Страница описывает присоединение дополнительного Samba DC к существующему AD: подготовку хоста (DNS, Kerberos, время), команду samba-tool domain join, запуск службы, синхронизацию idmap.ldb и SysVol, а также проверку DNS и репликации после join. Присоединение дополнительного DC отличается от провижининга первого DC в лесу.

Ключевое

Терминология и ограничения

  • NT4-домен использует один PDC и опциональные BDC; в лесу AD разницы между DC нет, кроме FSMO-ролей — пользуйтесь только термином «domain controller» (DC).
  • Не провижиньте компьютер как Samba AD DC, а затем пытайтесь присоединить его к существующему AD-домену — это не сработает; достаточно выполнить samba-tool domain join.
  • При join Samba DC к существующему Windows AD-домену, провиженному как Windows 2003 (или ранее), в домене должен работать интегрированный в домен DNS-сервер, настроенный с поведением 2008.

Подготовка

  • Установка Samba и подготовка хоста — как для первого DC (см. Установка Samba AD DC); устанавливайте поддерживаемую (maintained) версию Samba.
  • Локальный DNS-сервер: по умолчанию первый DC леса обслуживает DNS-зоны AD; для отказоустойчивости рекомендуется, чтобы DNS-сервис держали несколько DC. Для бэкенда BIND9_DLZ завершите его настройку до запуска службы Samba DC; для внутреннего DNS дополнительных действий не требуется.
  • Время: Kerberos требует синхронизированного времени на всех членах домена — настройка ntpd описана в Синхронизация времени.

DNS и Kerberos перед join

  • nameserver в /etc/resolv.conf должен указывать на другой AD DC — иначе join не сможет найти KDC / не выполнится. После успешного join смените nameserver на IP нового DC; не используйте 127.0.0.1 или какой-либо другой IP.
  • Настройки в /etc/krb5.conf:
[libdefaults]
    dns_lookup_realm = false
    dns_lookup_kdc = true
    default_realm = SAMDOM.EXAMPLE.COM
  • Проверка настроек — запрос билета Kerberos для администратора домена:
# kinit administrator
Password for administrator@SAMDOM.EXAMPLE.COM:
  • Список билетов Kerberos:
# klist
Ticket cache: FILE:/tmp/krb5cc_0
Default principal: administrator@SAMDOM.EXAMPLE.COM

Valid starting       Expires              Service principal
24.09.2015 19:56:55  25.09.2015 05:56:55  krbtgt/SAMDOM.EXAMPLE.COM@SAMDOM.EXAMPLE.COM
	renew until 25.09.2015 19:56:53

Присоединение к домену

Три способа аутентификации: логин и пароль либо два варианта Kerberos (оба требуют предварительно выполненного kinit от администратора).

Логин и пароль:

# samba-tool domain join samdom.example.com DC -U"SAMDOM\administrator"

Или:

# samba-tool domain join samdom.example.com DC -k yes

Или:

# samba-tool domain join samdom.example.com DC --use-krb5-ccache=/tmp/krb5cc_0

Пример вывода на странице заканчивается строкой:

Joined domain SAMDOM (SID S-1-5-21-469703510-2364959079-1506205053) as a DC

Дополнительные параметры, часто используемые с samba-tool domain join:

  • --dns-backend=NAMESERVER-BACKEND — использовать указанный DNS-бэкенд; допустимые варианты SAMBA_INTERNAL или BIND9_DLZ; если Bind9 не нужен, опция не требуется (см. Внутренний DNS бэкенд).
  • При внутреннем DNS у вас не спросят forwarder, и он не будет получен из /etc/resolv.conf автоматически — задайте его: --option="dns forwarder=forwarder_ipaddress".
  • --site=SITE — сразу присоединить хост как DC к конкретному сайту AD.
  • --option="interfaces=lo eth0" --option="bind interfaces only=yes" — если у сервера несколько сетевых интерфейсов: привязывает Samba к указанным интерфейсам, чтобы samba-tool зарегистрировал в каталоге правильный LAN IP.
  • Если остальные DC — Samba, провижененные с --use-rfc2307, следует добавить к команде join --option='idmap_ldb:use rfc2307 = yes'.

Подробнее — вывод samba-tool domain join --help.

Запуск службы Samba

Запуск вручную:

# samba

Samba не предоставляет скрипты System V init, systemd, upstart и другие файлы конфигурации служб:

  • при установке из пакетов используйте скрипт или файл конфигурации службы из пакета;
  • при сборке Samba — см. Управление службой AD DC.

DNS после join

  • После успешного join измените первый nameserver в /etc/resolv.conf на IP нового DC — это поможет в создании DNS-записей, которые не были созданы join-ом.
  • В Samba 4.7.0 и новее samba-tool создаёт необходимые начальные DNS-записи автоматически; на более старых версиях их создают вручную (см. Verifying and Creating a DC DNS Record). После запуска Samba скрипт samba_dnsupdate должен создать все остальные требуемые записи.
  • Если при join выбран бэкенд BIND9_DLZ — настройте конфигурацию BIND (см. BIND9 DLZ DNS бэкенд).
  • DNS-конфигурация на контроллерах домена важна: если DC не может найти другие DC, репликация будет падать. На новом DC в качестве primary nameserver вписывают его собственный LAN IP — в примере страницы это 10.99.0.2, то есть адрес самого нового DC (страница называет его «primary domain controller», но в её же примере два DC: DC1 = 10.99.0.1, новый DC = 10.99.0.2 — формулировка источника неточна). Пример /etc/resolv.conf:
nameserver 10.99.0.2
search samdom.example.com

ID-маппинг встроенных пользователей/групп и SysVol

  • Samba в текущем виде не поддерживает репликацию SysVol через DFS-R или старую FRS (Windows Server 2000/2003). Рекомендуемые обходные пути: «Rsync based SysVol replication workaround» (только Samba DC — быстрый и простой), «Bidirectional Rsync/Unison based» и «Bidirectional Rsync/osync based» (сложнее, нужен сторонний скрипт и cron-задача на каждом DC против каждого), «Robocopy based» (Samba DC → Windows DC). Детали rsync-варианта — Репликация SysVol.

  • Для работы обходных путей все DC должны использовать одинаковые ID-маппинги встроенных пользователей и групп. По умолчанию Samba DC хранит ID пользователей/групп в атрибутах xidNumber в idmap.ldb; из-за особенностей работы idmap.ldb нельзя гарантировать одинаковые ID на разных DC.

  • idmap.ldb синхронизируют с DC-держателя FSMO-роли PDC_Emulator на все остальные DC — иначе на каждом DC будут разные ID. Синхронизацию выполняют при первом join нового DC и затем регулярно (не при каждой синхронизации SysVol, но периодически).

  • Процедура:

    1. Создать hot-backup файла /usr/local/samba/private/idmap.ldb на существующем DC:
# tdbbackup -s .bak /usr/local/samba/private/idmap.ldb

 Будет создан файл `/usr/local/samba/private/idmap.ldb.bak`.
  1. Перенести файл бэкапа в папку /usr/local/samba/private/ на новом DC и убрать суффикс .bak, заменив существующий файл.
  2. Выполнить net cache flush на новом DC.
  3. Синхронизировать Sysvol на новый DC.
  4. Сбросить ACL файловой системы на папке Sysvol нового DC:
# samba-tool ntacl sysvolreset

Проверка репликации каталога

  • После запуска DC проверяющий согласованность (KCC, knowledge consistency checker) создаёт репликационные соглашения с другими DC леса; на создание автогенерируемых репликационных соединений может уйти до 15 минут. Подробности проверки статусов — Verifying the Directory Replication Statuses.
  • Для оптимизации задержек и стоимости репликации KCC в Samba 4.5 и новее больше не строит полносвязную (fully-meshed) топологию между всеми DC (см. The Samba KCC).
  • Перед запуском BIND-демона убедиться, что DNS-партиции каталога успешно реплицированы:
# samba-tool drs showrepl

...

		DSA object GUID: 4a6bd92a-6612-4b15-aa8c-9ec371e8994f
		Last attempt @ Thu Sep 24 20:08:45 2015 CEST was successful
		0 consecutive failure(s).

...

  • Если репликация работает корректно — запускать BIND (как запустить службу, см. документацию дистрибутива).

Проверка Samba AD DC

  • Файловый сервер — см. раздел «Verifying the File Server» документации по первому DC.
  • Локальный DNS-сервер (шаг пропускается, если при join был указан --dns-backend=NONE). Запрос локальному DNS на разрешение имени домена:
# host -t A samdom.example.com localhost
Using domain server:
Name: localhost
Address: 127.0.0.1#53
Aliases:

samdom.example.com has address 10.99.0.1
samdom.example.com has address 10.99.0.2

Локальный DNS должен разрешать имя домена в IP всех DC. При пустом или ином результате — свериться с документацией и проверить системные логи, логи Samba и (при BIND9_DLZ) логи BIND.

  • Kerberos — см. раздел «Verifying Kerberos» документации по первому DC (Установка Samba AD DC).
  • Проверка репликации каталога: создайте, например, пользователя на существующем DC и убедитесь, что он автоматически появился на новом DC. Опционально сравните два каталога утилитой ldapcmp (см. samba-tool ldapcmp).

Debian/Ubuntu: конфликт с systemd-resolve

Если /etc/resolv.conf постоянно перезаписывается, проверьте, не конфликтует ли systemd-resolved. Вывод команды должен содержать только задачу samba; наличие systemd-resolve означает конфликт DNS:

$ sudo netstat -tupln | grep :53
 tcp 0 0 127.0.0.53:53 0.0.0.0:* LISTEN 685/systemd-resolve
 tcp6 0 0 :::53 :::* LISTEN 963/samba: task[dns...
 udp 0 0 127.0.0.53:53 0.0.0.0:* 685/systemd-resolve...
 udp6 0 0 :::53 :::* 963/samba: task[dns...

Остановить службу:

$ sudo systemctl stop systemd-resolved

Отключить её, чтобы при включении питания она не стартовала снова (команда приведена на странице дословно; по смыслу это systemctl disable):

$ sudo systemctl stop

Удалить ссылки на resolv.conf, чтобы заменить файл своим содержимым:

$ sudo rm /etc/resolv.conf

$ sudo nano /etc/resolv.conf

Перезапустить Samba (у автора на вторичном DC служба называлась samba4, а не samba-ad-dc, как на первичном):

$ sudo systemctl restart samba4

Подождать 30 секунд:

$ sleep 30

Проверить, что systemd-resolve больше не держит порт:

$ sudo netstat -tulpn | grep :53
tcp6 0 0 :::53 :::* LISTEN 963/samba: task[dns...
udp6 0 0 :::53 :::* 963/samba: task[dns...

Проверить DNS — должны вывестись оба (или более) IP контроллеров домена:

$ host -t A samdom.example.com 127.0.0.1

Подводные камни

  • Не провижиньте компьютер как Samba AD DC, чтобы затем присоединить его к домену — join не сработает; сразу выполняйте samba-tool domain join.
  • Join к Windows AD-домену, провиженному как Windows 2003 или ранее, требует доменно-интегрированного DNS с поведением 2008.
  • nameserver в /etc/resolv.conf до join должен указывать на другой AD DC, иначе join не выполнится; после join первый nameserver меняют на IP нового DC — не 127.0.0.1.
  • Внутренний DNS: forwarder не спрашивается при join и не берётся из /etc/resolv.conf — задайте --option="dns forwarder=forwarder_ipaddress".
  • BIND9_DLZ нужно настроить до запуска службы Samba DC (BIND9 DLZ DNS бэкенд).
  • Без синхронизации idmap.ldb ID пользователей и групп будут разными на разных DC; синхронизируют только с держателя роли PDC_Emulator — при первом join и затем периодически.
  • SysVol не реплицируется автоматически (нет поддержки DFS-R/FRS); если на других DC больше GPO, чем четыре дефолтных, SysVol обязательно синхронизируют на новый DC, иначе samba-tool ntacl sysvolreset бросит ошибку.
  • KCC создаёт репликационные соединения до 15 минут; с Samba 4.5 топология репликации не полносвязная.
  • Debian/Ubuntu: systemd-resolved конфликтует с DNS Samba за порт 53; в команде отключения службы на странице, судя по всему, опечатка (sudo systemctl stop без аргумента — по смыслу systemctl disable).
