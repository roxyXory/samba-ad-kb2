База знаний Samba AD DC

Синхронизация времени (Time Synchronisation)

Суть

В Active Directory обязательна точная синхронизация времени: Kerberos требует корректных меток времени для защиты от replay-атак, а AD использует время для разрешения конфликтов репликации. Максимально допустимое отклонение по умолчанию — 5 минут; при большей разнице доступ запрещается, и пользователь не может обращаться к шарам или опрашивать каталог. Samba поддерживает ntpd (ntp.org) и chrony (chrony.tuxfamily.org). Сервер времени должен быть настроен на всех Samba AD DC.

Ключевое

Допустимое отклонение

Максимум по умолчанию — 5 минут. Если у члена домена или DC разница больше (в любую сторону), доступ запрещён: пользователь не может получить доступ к общим ресурсам и запросам к каталогу.

Рекомендуемая иерархия источников времени

internet time server
          ^
          |
          |
  PDC Emulator DC
   ^         ^
   |         |
   |         |
Other DC <----Workstation

Только PDC Emulator DC берёт время с внешних серверов; остальные DC — с PDC Emulator; рабочие станции — с любого DC. По умолчанию присоединённые к домену Windows-клиенты синхронизируются через протокол NT5DS (с цифровой подписью), которую Samba обеспечивает при опциях mssntp и ntpsigndsocket. Настройка NT5DS рекомендуется вместо обычного NTP на всех машинах.

Требования для DC

  • ntpd >= 4.2.6 с http://www.ntp.org, собранный с поддержкой signed NTP (--enable-ntp-signd при сборке NTP), или
  • chrony >= 3.0 с https://chrony.tuxfamily.org, собранный с --enable-ntp-signd.

Каталог ntp_signd появится только после первого запуска Samba — это не проблема: настройте всё, и после старта Samba всё заработает.

Права на каталог ntp_signd

Проверка (вариант для ntpd, пользователь ntp):

# ls -ld /usr/local/samba/var/lib/ntp_signd/
drwxr-x--- 2 root ntp 4096  1. May 09:30 /usr/local/samba/var/lib/ntp_signd/

Установка прав для ntpd:

# chown root:ntp /usr/local/samba/var/lib/ntp_signd/
# chmod 750 /usr/local/samba/var/lib/ntp_signd/

Для chrony пользователь обычно _chrony (вывод ls -ld показывает drwxr-x--- 2 root _chrony ...), и права ставятся так:

# chown root:_chrony /usr/local/samba/var/lib/ntp_signd/
# chmod 750 /usr/local/samba/var/lib/ntp_signd/

Настройка ntpd на DC

Файл конфигурации — /etc/ntpd.conf. Минимальный пример: синхронизация с тремя внешними NTP-серверами и обслуживание клиентов через signed NTP:

# Local clock. Note that is not the "localhost" address!
server 127.127.1.0
fudge  127.127.1.0 stratum 10

# Where to retrieve the time from
server 0.pool.ntp.org     iburst prefer
server 1.pool.ntp.org     iburst prefer
server 2.pool.ntp.org     iburst prefer

driftfile       /var/lib/ntp/ntp.drift
logfile         /var/log/ntp
ntpsigndsocket  /usr/local/samba/var/lib/ntp_signd/

# Access control
# Default restriction: Allow clients only to query the time
restrict default kod nomodify notrap nopeer limited mssntp

# No restrictions for "localhost"
restrict 127.0.0.1

# Enable the time sources to only provide time to this host
restrict 0.pool.ntp.org   mask 255.255.255.255    nomodify notrap nopeer noquery
restrict 1.pool.ntp.org   mask 255.255.255.255    nomodify notrap nopeer noquery
restrict 2.pool.ntp.org   mask 255.255.255.255    nomodify notrap nopeer noquery

Настройка chrony на DC

Файл конфигурации — /etc/chrony/chrony.conf. Минимальный пример:

# Welcome to the chrony configuration file. See chrony.conf(5) for more
# information about usuable directives.

# This directive specify the location of the file containing ID/key pairs for
# NTP authentication.
keyfile /etc/chrony/chrony.keys

# This directive specify the file into which chronyd will store the rate
# information.
driftfile /var/lib/chrony/chrony.drift

# Uncomment the following line to turn logging on.
#log tracking measurements statistics

# Log files location.
logdir /var/log/chrony

# Stop bad estimates upsetting machine clock.
maxupdateskew 100.0

# This directive tells 'chronyd' to parse the 'adjtime' file to find out if the
# real-time clock keeps local time or UTC. It overrides the 'rtconutc' directive.
hwclockfile /etc/adjtime

# This directive enables kernel synchronisation (every 11 minutes) of the
# real-time clock. Note that it can't be used along with the 'rtcfile' directive.
rtcsync

# Step the system clock instead of slewing it if the adjustment is larger than
# one second, but only in the first three clock updates.
makestep 1 3

# ipaddress of this DC
bindcmdaddress 192.168.0.2

# The source, where we are receiving the time from
server 0.pool.ntp.org     iburst
server 1.pool.ntp.org     iburst
server 2.pool.ntp.org     iburst

# dns netmask
allow 192.168.0.0/24

ntpsigndsocket  /usr/local/samba/var/lib/ntp_signd

Unix Domain Member: ntpd

Член домена только потребляет время — подписанный NTP (signd) ему не нужен. Минимальный /etc/ntpd.conf: синхронизация с DC1 и DC2, время другим хостам не раздаётся:

# Local clock. Note that is not the "localhost" address!
server 127.127.1.0
fudge  127.127.1.0 stratum 10

# Where to retrieve the time from
server DC1.samdom.example.com     iburst prefer
server DC2.samdom.example.com     iburst

driftfile /var/lib/ntp/ntp.drift
logfile   /var/log/ntp

# Access control
# Default restriction: Disallow everything
restrict default ignore

# No restrictions for "localhost"
restrict 127.0.0.1

# Enable the time sources only to only provide time to this host
restrict DC1.samdom.example.com   mask 255.255.255.255    nomodify notrap nopeer noquery
restrict DC2.samdom.example.com   mask 255.255.255.255    nomodify notrap nopeer noquery

Unix Domain Member: systemd-timesyncd

Демон читает конфигурацию из /etc/systemd/timesyncd.conf, из network-конфигурации (/etc/systemd/network/your.network) или из настроек DHCP.

Вариант 1 — /etc/systemd/timesyncd.conf:

[Time]
NTP=DC1.samdom.example.com DC2.samdom.example.com
FallbackNTP=the.same.ntp-server.as.your.dc.points.to one-extra.ntp-server.as.your.dc.points.to

Fallback-серверы в примере используются, но это не обязательно.

Вариант 2 — серверы времени в network-конфигурации (например, /etc/systemd/network/20-wired-dev1.network):

#/etc/systemd/network/20-wired-dev1.network
[Network]
NTP=dc1.samdom.example.com
NTP=dc2.samdom.example.com

[Address]
Address=192.168.0.200/24

[Route]
Destination=0.0.0.0/0
Gateway=192.168.0.1

После изменений включить и запустить демон, затем проверить:

systemctl enable systemd-timesyncd
systemctl start systemd-timesyncd

systemctl status systemd-timesyncd

journalctl -u systemd-timesyncd

timedatectl status

При необходимости — список зон и смена часового пояса:

timedatectl list-timezones

timedatectl set-timezone Europe/Amsterdam

На странице вики команда приведена с опечаткой — set-timezones (с «s»); timedatectl такой глагол не знает («Unknown command verb 'set-timezones', did you mean 'set-timezone'?»), правильный глагол — set-timezone.

Смысл timesyncd для член-сервера: работает нормально и не требует установки дополнительного ПО.

Windows Domain Member

По умолчанию члены AD-домена используют любой DC как источник времени (NT5DS) — при настроенном на DC ntp обычно ничего перенастраивать не нужно. Для пользовательских источников — через GPO (редактирование требует RSAT):

  1. Войти под учёткой с правом редактирования групповых политик (например, администратор домена AD).
  2. Открыть Group Policy Management Console.
  3. Правый клик по домену AD → «Create a GPO in this domain, and Link it here».
  4. Задать имя GPO, например «Time Sources».
  5. Правый клик по созданному GPO → «Edit» — откроется Group Policy Management Editor.
  6. Перейти в Computer Configuration → Policies → Administrative Templates → System → Windows Time Service → Time Providers, открыть «Configure Windows NTP Client»:
    • Включить политику.
    • В поле NtpServer ввести FQDN NTP-сервера с флагом 0x9 (несколько серверов — через пробел).
    • Оставить тип NT5DS.
    • При необходимости обновить дополнительные параметры.
  7. Там же открыть «Enable Windows NTP Client» и включить политику.
  8. Сохранить (OK), закрыть редактор и консоль.

Подводные камни

  • Отклонение более 5 минут = отказ в доступе: Kerberos не примет аутентификацию, пользователь не попадёт на шары и в каталог.
  • Отключение PDC Emulator: если PDC Emulator DC уходит в оффлайн, остальные DC продолжают искать его, и время может «уплыть». Обход: настроить одни и те же внешние серверы времени на всех DC, а при невозможности быстро перезапустить PDC Emulator — передать или захватить роль PDC Emulator другому DC (Передача и захват FSMO ролей).
  • ntpsec с Samba не работает (Debian bug 1033088, NTPsec issue 785); пока замечание на странице не убрано, рекомендуется использовать только Chrony. В пакете ntpsec Debian Trixie проблема исправлена, в Bookworm — ещё нет.
  • Аутентифицированная синхронизация с Windows 2000 клиентами не поддерживается.
  • Каталог ntp_signd не существует до первого запуска Samba — настройте время заранее, заработает после старта Samba.
  • Путь к ntp_signd зависит от дистрибутива — может быть, например, /var/lib/samba/ntp_signd/; тогда его нужно поменять и в конфиге (ntpd.conf / chrony.conf).
  • Виртуальные машины: добавьте tinker panic 0 в конец ntp.conf — тогда NTP не будет паниковать и завершаться при любом смещении времени (у ВМ нет физических часов, их могут поставить на паузу и запустить часами позже). Подробности: https://www.redhat.com/en/blog/avoiding-clock-drift-vms
  • GPO для Windows-клиентов: тип по умолчанию NT5DS игнорирует параметр NtpServer и синхронизируется с DC. Если на DC не настроены mssntp с ntpsigndsocket, используйте Type NTP. Для клиентов, долго не имеющих связи с DC (ноутбуки), — Type AllSync с NtpServer time.windows.com,0x9: клиент будет пробовать и NT5DS к DC, и NTP к NtpServer.
  • При включённом SELinux на сервере см. страницу вики «Time Synchronisation - SELinux Labeling and Policy» (в хранилище отдельной заметки нет).
