База знаний Samba AD DC

Windows DC рядом с Samba DC: совместимость, adprep и функциональные уровни

Суть

Смешанный домен (Windows DC + Samba DC) упирается в три независимых понятия: уровень схемы (какие объекты вообще можно создать), уровень подготовки (preparation — какие объекты реально созданы) и функциональный уровень (число, по которому DC меняют поведение). Windows 2008/2008 R2 DC входит в домен Samba без всякой подготовки; для 2012/2012 R2 нужны схема 2012 R2 плюс samba-tool domain functionalprep, но сам функциональный уровень домена при этом остаётся ниже 2012 (иначе ломается репликация). Для Windows 2016 и новее инфраструктура не готова — остаётся обход через промежуточный 2008 R2 DC, который даёт adprep обновить домен. Обратный вход (Samba DC в Windows-домен) работает до функционального уровня 2008 R2 включительно; на 2012+ join падает с WERR_DS_INCOMPATIBLE_VERSION.

Ключевое

Три уровня, которые обычно путают

Страница «Windows 2012 Server compatibility» (ред. 13.04.2021) разделяет:

  • Schema level — описывает, какие классы и атрибуты существуют. Обновление схемы обратно совместимо: схема 2012 R2 работает и на 2008 DC. Windows не позволяет обратного — новый DC (2012 R2) в старом домене (2008 R2) требует сначала поднять схему домена; Samba такого требования при входе в Windows-домен не имеет.
  • Preparation level — реальное создание объектов, нужных новому функциональному уровню. Пример: схема 2008 R2 добавила объект msDS-PasswordSettingsContainer (PSO), но пока preparation не создаст CN=Password Settings Container, PSO не работает.
  • Functional level — просто число в каталоге, по которому DC меняют поведение. Вся работа делается заранее (схемой и подготовкой) либо переключается на лету по этому числу.

На Windows все три вопроса решает adprep.exe; с 2012+ он запускается автоматически при повышении DC. И сам adprep, и новые способы его вызова несовместимы с Samba — отсюда обход ниже.

Схемы Windows (страница «AD Schema Version Support», ред. 11.09.2025): 2000 — 13, 2003 — 30, 2003 R2 — 31, 2008 — 44, 2008 R2 — 47, 2012 — 56, 2012 R2 — 69, 2016 — 87, 2019/2022 — 88, 2025 — 91. Samba поддерживает: 4.0–4.4 — 47, 4.5–4.10 — 69 (экспериментально), 4.11–4.18 — 69, 4.19 и новее — 88.

Как проверить уровень схемы

На Samba DC (подставить свой домен вместо dc=samdom,dc=example,dc=com):

# ldbsearch -H /usr/local/samba/private/sam.ldb -b 'cn=Schema,cn=Configuration,dc=samdom,dc=example,dc=com' -s base objectVersion
# record 1
dn: CN=Schema,CN=Configuration,DC=samdom,DC=example,DC=com
objectVersion: 47

Из Windows: dsquery * "cn=Schema,cn=Configuration,dc=samdom,dc=example,dc=com" -scope base -attr objectversion или в PowerShell Get-ADObject (Get-ADRootDSE).schemaNamingContext -properties objectVersion.

Матрица совместимости DC ↔ домен

Из «Windows 2012 Server compatibility» (строки — присоединяемый DC, столбцы — функциональный уровень домена):

DC \ Уровень домена Win2008 R2 Win2012 R2 Win2016 Samba
Win2008 R2 — OK OK OK
Win2012 R2 OK* — OK OK*
Win2016 OK* OK* — Not supported
Samba OK Not supported Not supported —

* Требуется предварительно поднять уровень схемы и уровень подготовки домена.

Windows 2008 / 2008 R2 DC → домен Samba

«This should work without any special preparation». Отдельная страница описывает вход через dcpromo.exe (Existing forest → Add a domain controller to an existing domain), с проверкой времени (Kerberos: расхождение больше 5 минут по умолчанию недопустимо), статическим IP и DNS, указывающим на DC, который резолвит AD-зону. После повышения обязательно проверить, что DC-записи DNS созданы, — «Do not continue without verifying the DNS records. They must exist for a working directory replication!».

Windows 2012 / 2012 R2 DC → домен Samba

Работает, но не «из коробки»:

  • Samba поддерживает схему 47, 56 и 69; с Samba 4.11 поддержка схемы 69 больше не экспериментальна, но поддержка самих Windows Server 2012/2012 R2 как DC, возможно, всё ещё экспериментальна («Please report bugs and incompatibilites»).
  • Нужны уровень схемы 2012 R2 и уровень подготовки. С v4.11 дефолтная схема — уже 2012 R2, поэтому для домена, созданного на 4.11+, остаётся только шаг подготовки. Для домена, созданного до 4.11, сначала обновляют схему:
samba-tool domain schemaupgrade
samba-tool domain functionalprep --function-level=[2012|2012_R2]
  • Команда schemaupgrade существует с v4.8, но на странице рекомендуется сначала обновиться до v4.11 — «important fixes were added in v4.11». Про schemaupgrade сказано: «This tool may error out when a live server is running, but it has actually succeeded. There is also a bug in 4.11.0rc1 in the LDAP server preventing the actual Windows domain join.»
  • schemaupgrade и functionalprep достаточно выполнить на одном DC — изменения разойдутся репликацией.
  • Требования: все Samba DC — 4.6 или новее; Windows Server 2008/2008 R2, с которого идёт начальная репликация, должен отдавать шару Sysvol, иначе join 2012/2012 R2 падает.
  • Перед повышением первого Windows Server 2012/2012 R2 в DC домена роли Schema Master, Infrastructure Master и PDC Emulator должны принадлежать существующему Windows DC 2008/2008 R2. «Forest and domain preparation fails if a Samba DC holds one to three of the previous mentioned roles when you join the first Windows Server 2012 or 2012 R2 DC.» После обновления роли можно вернуть на Samba DC.
  • В мастере повышения источником репликации нужно выбрать существующий Windows DC: «Samba currently does not support schema replication using the Windows management instrumentation (WMI) protocol.»

Важное предупреждение (страница join 2012/2012 R2, ред. 19.07.2023): «Joining a Windows Server 2012 or 2012 R2 DC to a Samba AD with 2012R2 functional level breaks the AD replication! Do not use this documentation until the problem is fixed! For more details, see Bug #13618. Thankfully Windows 2012 can join a down-level (2008/2008R2) domain, just not at Functional Level 2012/2012R2, provided the schema is updated, which samba can do.» То есть схему/подготовку поднимают до 2012 R2, а функциональный уровень домена оставляют 2008/2008 R2.

Windows 2016 и новее → домен Samba: обход через adprep

Статус на странице совместимости (ред. 2021): «Not yet complete. All the infrastructure is in place, but the work needs to be done/funded. This may still be possible using the adprep workaround.»

Обход (дословно из раздела «adprep workaround»):

  1. A 2008R2 version of Windows is joined to Samba.
  2. All the FSMO roles are transferred to the Windows 2008R2 DC.
  3. The Windows 2012 DC joins the 2008R2 DC and adprep automatically updates the domain's schema and preparation levels.
  4. The 2008R2 DC can now be removed and/or FSMO roles transferred back to Samba.

Смысл в том, что adprep не работает напрямую против Samba DC, но может обновить промежуточный Windows DC — обновлённая база домена затем реплицируется и на Samba DC. Функциональный уровень домена при этом не меняется («note that the domain's functional level remains unchanged»).

Samba DC → Windows-домен

  • Pre-2008 R2. В целом возможно, но с оговорками. Samba поддерживает обновление схемы только начиная с доменов 2008 R2; если домен создавался Windows DC старее 2008 R2, samba-tool схему не обновит. Шаги переезда с Windows (подъём схемы и подготовки штатным adprep до вывода Windows DC) описаны в Миграция NT4 домена в Samba AD.
  • Pre-2003. Проблема в том, что DNS-записи ещё лежат в основном разделе, а не в DC=DomainDNSZones. Перед входом Samba DC нужно поднять функциональный уровень до 2003 и перенести DNS-записи в DC=DomainDNSZones и DC=ForestDNSZones; «If you have not migrated the DNS entries first, then joining the Samba DC will fail». Страница «Joining a Samba DC to an Existing Active Directory» формулирует это так: если домен создавался Windows 2003 (или раньше), DNS-сервер должен быть domain integrated и настроен на поведение 2008.
  • 2008 / 2008 R2. «Generally speaking, this should work» — стабильные версии входят без проблем; известен баг 14046 (по странице совместимости — только Samba v4.10, сборка с Python 3; в самом баг-репорте — v4.10 и v4.11/master): join падает с
DsAddEntry failed with status WERR_ACCESS_DENIED info (8363, 'WERR_DS_NO_CROSSREF_FOR_NC')

Обходной путь для 4.10 — запустить samba-tool под python2 (при наличии python2-пакетов Samba).

  • 2012 и выше. Невозможно: потребовалась бы реализация функционального уровня 2012. Join даёт ошибку
DsAddEntry failed with status WERR_ACCESS_DENIED info (8567, 'WERR_DS_INCOMPATIBLE_VERSION')

Рекомендация страницы — понизить функциональный уровень леса и домена на Windows DC до 2008 R2 и отключить связанные функции 2012, прежде чем присоединять Samba. Запрос на поддержку join на уровне 2012R2 — bug 13619; в 2023 году он помечен RESOLVED FIXED, в комментарии разработчика (22.05.2023) сказано, что коммит 72335e742e041ea213598a62ae165edeed4b8c99 «allows Samba to claim to be Windows 2016 at join time», но недостающие функции уровня не доделаны, а пользоваться этим можно «as long as you understand the risks».

FSMO-роли в Samba: что реализовано

Из раздела «FSMO roles» страницы совместимости:

  • Schema master — обрабатывается, но часть компонентов Windows предполагает, что schema master работает под Windows; из-за этого adprep и обновление схемы против Samba не работают. Обновлять схему нужно инструментами Samba против Samba schema master и инструментами Windows против Windows schema master.
  • Domain naming master — «Currently no behaviour is implemented in regards to this role in Samba»; создание разделов не работает или работает частично.
  • PDC emulator — большая часть функциональности реализована на уровне 2008 R2, но «we currently do not implement certain aspects of authentication and password changes (including urgent replication)». Проблема не в самом PDC, а в том, что остальные DC Samba не уважают PDC emulator: репликация должна распространиться естественным путём, прежде чем заработает часть логинов.
  • RID master — реализован (преаллокация RID).
  • Infrastructure master (домен + domain DNS + forest DNS) — «Currently no behaviour appears to be implemented for these roles in Samba»; именно эта роль отвечает за часть кросс-ссылок и recycle bin, которых в Samba тоже нет.

Чего нет в Samba (по состоянию страницы, ред. 2021)

  • Уровень 2008 R2: Recycle Bin, DFSR (репликация Sysvol), частичная поддержка доверий/леса, DCOM/WMI (и связанные DCE/RPC-пайпы), ADWS / совместимость с AD PowerShell.
  • Уровень 2012/2012 R2: group managed service accounts, новые возможности Kerberos (claims based access control, authentication policy silos, FAST armoring).
  • Уровень 2016: temporary (time-limited) group memberships.
  • Доверительные отношения: «Samba still has a number of limitations to its trusted domain support. In a mixed environment, expect Samba to allow or disallow operations differently from Windows». Плюс: «In Samba, trust support isn't yet complete and so in general terms, the domain is often considered the forest».

Расхождения по версиям (проверять по release notes, страница устарела):

  • Samba 4.19: «An initial, partial implementation of Active Directory Functional Level 2012, 2012R2 and 2016 is available in this release»; Kerberos Armoring (FAST) для Windows-клиентов работает, если функциональный уровень DC выставлен в 2012, 2012_R2 или 2016 (страница 2021 года всё ещё числит FAST среди отсутствующего).
  • Samba 4.20: поддержка Authentication Silos и Authentication Policies (нужен функциональный уровень 2012_R2 или выше).
  • Samba 4.21: «Samba 4.21 adds support for gMSAs (Group Managed Service Accounts), completing support for Functional Level 2012» и «Samba can now claim Functional Level 2012R2 support».

SysVol: реестр на Windows DC и robocopy-обход

Windows DC при входе в домен пытается реплицировать содержимое Sysvol, но Samba не поддерживает DFS-R, поэтому содержимое не реплицируется и Windows не включает шару Sysvol. Включают вручную: сохранить в файл (например, Win-Create-Sysvol-Share.reg) и импортировать

Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Netlogon\Parameters]

"SysvolReady"=dword:00000001

и перезагрузить сервер. Это не включает репликацию Sysvol.

Сама репликация между Samba и Windows DC делается robocopy-обходом (rsync не годится: он не сохраняет ACL между Linux и Windows): задача в Task Scheduler, каждые 5 минут, запуск от доменного администратора, действие

Program/script:               C:\Windows\System32\Robocopy.exe
Add arguments (optional):     \\DC1\SYSVOL\samdom.example.com\ C:\Windows\SYSVOL\domain\ /mir /sec

плюс перезапуск службы File Replication Service. Источник — Samba DC (рекомендуется PDC Emulator, к нему по умолчанию подключается GPMC). Репликация односторонняя: правки GPO/скриптов делают только на источнике, на остальных DC они будут перезаписаны. Подробнее — Репликация SysVol.

Если после входа Windows DC шары «SysVol» и «Netlogon» не видно, страница отсылает к KB947022.

Подъём функционального уровня

Здесь источники расходятся, и расхождение принципиальное:

  • Страница «Windows 2012 Server compatibility» (ред. 2021): «Samba does not currently support any attempts to update the functional level» и «The samba-tool command to raise your functional level is not safe to use against Samba (and probably not even safe against Windows either). The tool is currently incomplete in that it does not check for the appropriate schema version or preparation level before deciding to change the functional level. Please do not run this! If changing the functional level is necessary, using Windows to perform the change is required.»
  • Страница «Raising the Functional Levels» (ред. 14.06.2024): уровни выставляются через samba-tool. Таблица поддержки: 2016 — Samba 4.20 и новее, 2012_R2 — 4.19 и новее, 2012 — 4.19 и новее, 2008_R2/2008/2003 — 4.0 и новее. После подъёма любого уровня «you will need to restart the Samba AD DC(s)».
# samba-tool domain level raise --domain-level=2008_R2
# samba-tool domain level raise --forest-level=2012_R2

Функциональный уровень леса нельзя поднять выше уровня домена («You can not set the forest functional level higher than the domain functional level»). Подъём из оснастки Windows «Active Directory Domains and Trusts» не поддерживается (в источнике: «Raising the domain functional level using the Active Directory Domains and Trusts utility is currently not supported») — см. bug 10360; при этом страница всё равно приводит шаги для этой оснастки, то есть противоречит сама себе.

  • Официальный рецепт для 2016 (release notes 4.19.0): на каждом DC в smb.conf добавить
 ad dc functional level = 2016

перезапустить Samba и выполнить

samba-tool domain schemaupgrade --schema=2019
samba-tool domain functionalprep --function-level=2016
samba-tool domain level raise --domain-level=2016 --forest-level=2016

Для нового домена — samba-tool provision с --option="ad dc functional level = 2016" --function-level=2016. В 4.19 Samba всё ещё даёт по умолчанию только FL 2008 R2, но база нового домена готовится под FL 2016 — release notes 4.19.0: «in provision ensure that the blank database is already prepared for Functional Level 2016, with AD Schema 2019». В release notes 4.21 схема при этом названа «default 2016 schema» («Provided the default 2016 schema is used, new Samba domains provisioned with Samba 4.21 will have this enabled once the domain functional level is set to 2016») — формулировки источников расходятся (2019 против 2016). Фактическое умолчание samba-tool domain provision — схема 2019: в python/samba/netcmd/domain/provision.py тегов 4.19.0–4.21.0 у опции --base-schema перечислены 2008_R2|2008_R2_old|2012|2012_R2|2016|2019 с умолчанием «Default is (Windows) 2019» (локальная проверка на 4.22.11 даёт то же), а схему готового домена можно проверить через objectVersion (см. раздел «Как проверить уровень схемы» выше). Домены, обновлённые со старых версий, ротацию паролей smartcard-only аккаунтов не получат «even after the functional level preparation, matching the behaviour of upgraded Windows AD domains».

  • ad dc functional level (smb.conf, man current): «the Active Directory functional level that this Domain Controller will claim to support», значения 2008_R2/2012/2012_R2/2016, по умолчанию 2008_R2. «Normally this option should not be set as Samba will operate per the released functionality of the Samba Active Directory Domain Controller.» Если выставить вручную, «the protection against mismatching features between domain controllers is reduced, so all domain controllers should be running the same version of Samba».

Подводные камни

  • Не поднимайте функциональный уровень домена до 2012/2012_R2, если рядом Windows DC 2012/2012 R2 — по предупреждению страницы join это ломает репликацию AD (bug 13618). Поднимать нужно только схему и подготовку, а функциональный уровень оставлять 2008/2008 R2.
  • samba-tool domain functionalprep на работающем DC падает с INTERNAL ERROR: Signal 11 (bug 13705, «samba-tool domain functionalprep: Segmentation fault», статус NEW). Разработчик поясняет: «The functional prep command actually succeeds in this case, but for some reason it's crashing in the messaging code with a live server». Ошибка ложная, но и безобидной её считать нельзя: в 4.14.5 баг воспроизводился, а автотесты его не ловят, потому что там Samba не запущена. Смежный факт со страницы совместимости: schemaupgrade «may error out when a live server is running, but it has actually succeeded».
  • adprep не работает против Samba DC. Любое обновление схемы/подготовки через Windows — только против промежуточного Windows DC, иначе шаг провалится. Для этого промежуточному DC нужны роли Schema Master, Infrastructure Master и PDC Emulator (Передача и захват FSMO ролей).
  • Windows GUI не поднимет функциональный уровень на Samba DC: «AD Domains and Trusts» отвечает «Not sufficiant privileges to raise the forest functional level» (и то же самое для domain functional level) — bug 10360, статус NEW с 2014 года, воспроизводился и в 4.6.0rc3; при этом samba-tool делает это без проблем. Утверждение страницы 2021 года о том, что менять уровень нужно только из Windows, устарело: для Samba DC всё наоборот, а уровень 2012_R2/2016 через samba-tool заявлен с 4.19/4.20.
  • Обновление схемы Samba — только с домена 2008 R2. Для более старых домов придётся вручную применять ldf-файлы из Windows adprep: «the ldf files must be manually sourced from the Windows adprep tool and run with the --ldf-file= option».
  • Ошибка «This operation is only allowed for the Primary Domain Controller of the domain» при повышении Windows DC означает, что он не смог обратиться к Sysvol партнёра репликации (Windows Server 2008/2008 R2) — лечится включением шары Sysvol.
  • WMI-репликация схемы не поддерживается — в мастере повышения Windows DC выбирайте источником существующий Windows DC, иначе шаг репликации схемы не пройдёт.
  • Без шары Sysvol на партнёре join Windows 2012/2012 R2 падает — сначала включают шару на 2008/2008 R2 DC.
  • PDC emulator без urgent replication: смена пароля и часть аутентификации не форвардятся на PDC, репликация должна дойти естественным путём — логин с новым паролем может не работать сразу на всех DC.
  • Domain naming master и infrastructure master не реализованы — не полагайтесь на них в смешанном домене; recycle bin и часть кросс-ссылок отсутствуют.
  • Неполные доверия: в смешанной среде Samba может разрешать/запрещать операции не так, как Windows; домен в Samba фактически приравнивается к лесу.
  • Robocopy-репликация SysVol односторонняя, а флаг /mir зеркалирует каталог: локальные правки GPO на Windows DC будут перезаписаны содержимым источника.
  • Страница «Windows 2012 Server compatibility» не обновлялась с 13.04.2021 — её списки отсутствующих функций и оценок «not supported» могут быть устаревшими (см. release notes 4.19–4.21); перед выводами сверяйтесь с текущими release notes и man-страницами.
