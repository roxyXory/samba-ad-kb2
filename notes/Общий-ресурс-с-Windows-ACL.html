База знаний Samba AD DC

Настройка общего ресурса с использованием Windows ACL

Суть

Расширенные списки контроля доступа (ACL) позволяют задавать права на шары, файлы и каталоги стандартными Windows-инструментами (Computer Management, вкладка Security в свойствах папки). Поддерживается на членах домена, контроллерах домена AD (DC), NT4 PDC/BDC и standalone-хостах. Права настраиваются не параметрами в smb.conf, а из Windows: базовые POSIX-права задаются один раз при создании шары, всё остальное — Windows-утилитами. ACL хранятся в файловой системе в виде расширенных POSIX ACL и расширенного атрибута security.NTACL.

Ключевое

Подготовка хоста

Перед созданием шары Samba должна быть настроена: см. Samba как член домена, Установка Samba AD DC, NT4 PDC/BDC или standalone (по типу сервера).

Требования к файловой системе

Файловая система шары обязана поддерживать:

  • пространства имён xattr user и system;
  • расширенные ACL.

Проверка поддержки ACL в Samba

Служба smbd должна быть собрана с поддержкой ACL (на AD DC она включена всегда):

# smbd -b | grep HAVE_LIBACL
 HAVE_LIBACL

Если вывода нет: Samba собрана с --with-acl-support=no либо configure не нашёл нужные библиотеки (см. Package Dependencies Required to Build Samba).

Включение расширенных ACL на Unix domain member

Идеально — система с поддержкой NFS4 ACL; для систем вроде Linux добавить в секцию [global] файла smb.conf:

vfs objects = acl_xattr
map acl inherit = yes
# the next line is only required on Samba versions less than 4.9.0
store dos attributes = yes

На AD DC поддержка расширенных ACL включается глобально автоматически — вручную её включать нельзя. Вместо глобального включения можно добавить те же параметры в секцию отдельной шары. Подробности по параметрам — в man-странице smb.conf(5).

Привилегия SeDiskOperatorPrivilege

  • По умолчанию единственный держатель привилегии — BUILTIN\Administrators.
  • Члены BUILTIN\Administrators — это Administrator, Domain Admins и Enterprise Admins; они наследуют её. Значит, при входе в Windows под Administrator или членом Domain Admins/Enterprise Admins выдавать привилегию не нужно вовсе.
  • Использовать можно только пользователей и группы, известных Unix: при winbind-бэкенде ad на Unix domain member нужно добавить атрибут uidNumber пользователям или gidNumber группам в AD.
  • Рекомендуется выдавать привилегию группе, а не отдельным учёткам: право добавляется/отзывается изменением членства в группе.

Посмотреть всех держателей привилегии:

# net rpc rights list privileges SeDiskOperatorPrivilege -U "SAMDOM\administrator"
Enter administrator's password:
SeDiskOperatorPrivilege:
 BUILTIN\Administrators

Если привилегию нужно выдать — это делается на том сервере Samba, где расположена шара.

Добавление шары

Пример: каталог /srv/samba/Demo/ под именем шары Demo.

Создать каталог от root:

# mkdir -p /srv/samba/Demo/

Чтобы не только Administrator мог задавать права из Windows, выдать Full control (rwx) группе, которой выдана SeDiskOperatorPrivilege. Для бэкенда ad:

# chown root:"Unix Admins" /srv/samba/Demo/
# chmod 0770 /srv/samba/Demo/

Для любого другого бэкенда:

# chown root:"Domain Admins" /srv/samba/Demo/
# chmod 0770 /srv/samba/Demo/

Добавить определение шары в smb.conf:

[Demo]
 path = /srv/samba/Demo/
 read only = no

Дальнейшие настройки шары и права файловой системы задаются Windows-утилитами. При желании можно добавить строку acl_xattr:ignore system acls = yes в шару (см. «Подводные камни»). Других параметров в определение шары не добавлять.

Перечитать конфигурацию Samba:

# smbcontrol all reload-config

Настройка прав шары и ACL из Windows

Шара с поддержкой расширенных ACL настраивается Windows-утилитами вместо параметров в секции шары smb.conf:

  1. Войти на Windows-хост под SAMDOM\Administrator или учёткой из группы шары (например, SAMDOM\john, где john — член Domain Admins).
  2. Start → Computer Management, запустить приложение.
  3. Action / Connect to another computer — ввести имя хоста Samba, OK.
  4. Открыть System Tools / Shared Folders / Shares.
  5. Правый клик по шаре → Properties.
  6. Вкладка Share Permissions: должно быть видно только Everyone; если так — ничего не менять, иначе выставить Everyone : Full Control, Change и Read. Samba хранит права этой вкладки в базе /usr/local/samba/var/locks/share_info.tdb.
  7. Изменения прав делать на вкладке Security: кнопка Edit — задать ACL корневого каталога шары. Добавление группы: Add → Advanced → Find Now → выбрать, например, Domain Users → OK → OK → выбрать права (например, Full control) → подтвердить в окне Windows Security («Do you want to continue») кнопкой Yes → убедиться, что Domain Users появился в списке Group or user names → OK → OK.

Настраивать вкладку Share Permissions могут только держатели SeDiskOperatorPrivilege; вкладку Security — только пользователь или члены группы, которая назначена owner:group на каталоге шары на сервере.

ACL на папке внутри шары

  1. Войти на Windows-хост под учёткой с Full control на эту папку.
  2. Перейти к папке, правый клик → Properties.
  3. Вкладка Security → кнопка Edit, задать права.
  4. OK (закрыть Permissions for Folder) → OK (сохранить настройки).

ACL в бэкенде

Samba хранит права файловой системы в расширенных ACL и расширенном атрибуте. Посмотреть POSIX ACL каталога:

# getfacl /srv/samba/Demo/
# file: srv/samba/Demo/
# owner: root
# group: root
user::rwx
user:root:rwx
group::---
group:root:---
group:domain\040users:rwx
group:unix\040admins:rwx
mask::rwx
other::---
default:user::rwx
default:user:root:rwx
default:group::---
default:group:root:---
default:group:domain\040users:rwx
default:group:unix\040admins:rwx
default:mask::rwx
default:other::---

Посмотреть расширенный атрибут security.NTACL (вывод — base64-блоб NT ACL):

# getfattr -n security.NTACL -d /srv/samba/Demo/

Приведённые ACL соответствуют следующим Windows-правам:

Principal Permissions Applies to
Domain Users (SAMDOM\Domain Users) Modify, Read & execute, List folder contents, Read, Write (This folder, subfolders and files)
Unix Admins (SAMDOM\Unix Admins) Full control (This folder, subfolders and files)

Более читаемая форма ACL (пример на sysvol):

# samba-tool ntacl get /usr/local/samba/var/locks/sysvol --as-sddl
# O:BAG:SYD:PAI(A;OICIIO;WOWDGRGWGX;;;CO)(A;OICIIO;GRGX;;;AU)(A;;0x001200a9;;;AU)(A;OICIIO;GA;;;SY)(A;;0x001f01ff;;;SY)(A;OICIIO;WOWDGRGWGX;;;BA)(A;;0x001e01bf;;;BA)(A;OICIIO;GRGX;;;SO)(A;;0x001200a9;;;SO)

По устранению проблем — см. Troubleshooting Samba Domain Members и Диагностика AD DC.

Подводные камни

  • На AD DC поддержка расширенных ACL включается автоматически на глобальном уровне — вручную включать её нельзя.
  • Строка store dos attributes = yes нужна только на Samba версии ниже 4.9.0.
  • Привилегию можно выдавать только пользователям/группам, известным Unix; при winbind-бэкенде ad требуются атрибуты uidNumber/gidNumber в AD.
  • Не добавлять атрибут gidNumber группе Domain Admins при бэкенде ad — это ломает маппинг в idmap.ldb (Domain Admins там имеет тип ID_TYPE_BOTH, чтобы группа могла владеть файлами в Sysvol на Samba AD DC). Вместо этого создать отдельную группу (например, Unix Admins), дать ей gidNumber, включить в Administrators и использовать на Unix вместо Domain Admins.
  • С бэкендом ad использовать созданную группу Unix Admins; с любым другим бэкендом (autorid, rid и т.п.) можно использовать Domain Admins.
  • Выдавать привилегию рекомендуется группе, а не отдельным учёткам.
  • SeDiskOperatorPrivilege выдаётся именно на том сервере Samba, где лежит шара.
  • Строку acl_xattr:ignore system acls = yes добавлять только ПОСЛЕ того, как права шары настроены из Windows, иначе можно потерять возможность менять права из Windows. После её добавления setfacl на каталоге шары не покажет изменения, сделанные из Windows (Samba игнорирует стандартные Unix-ACL ugo). Добавлять строку только если подключаться к шаре будут исключительно через Samba.
  • Не задавать НИКАКИХ дополнительных параметров в определении шары — любой дополнительный параметр может помешать настройке или использованию шары.
  • Вкладку Share Permissions трогать не нужно (только при наличии проблем; перед её использованием лучше посоветоваться в списке рассылки samba): на ней должно быть ровно Everyone с Full Control, Change и Read — менять права следует на вкладке Security.
  • Настраивать вкладку Share Permissions могут только держатели SeDiskOperatorPrivilege, вкладку Security — только owner:group каталога шары на сервере.
