Bug Reporting — как правильно сообщать об ошибках в Samba

Суть

Страница Samba Wiki описывает, куда и как сообщать об ошибках в Samba и в клиенте SMB ядра Linux (cifs.ko). Главные правила: сообщения об ошибках безопасности отправляются только на security@samba.org (никогда — в Bugzilla, IRC или публичные списки рассылки), обычные ошибки — в багтрекер Samba на Bugzilla с обязательным указанием номера версии. Для проблем с kernel-клиентом CIFS приведён набор команд для сбора отладочного вывода ядра и сетевого трассировочного файла.

Ключевое

Ошибки в Samba

  • Сообщайте обо всех предполагаемых проблемах безопасности на security@samba.org, чтобы команда могла следовать своему процессу работы с уязвимостями (Security Process).
  • Прочтите инструкции: https://www.samba.org/~asn/reporting_samba_bugs.txt
  • Сообщайте о проблеме в системе отслеживания ошибок Samba (bug tracking system): https://bugzilla.samba.org/
  • Всегда указывайте номер версии Samba в сообщении об ошибке.

Ошибки в клиенте SMB ядра Linux (cifs.ko)

  • Если у вас проблема с клиентом SMB в ядре Linux (cifs.ko, mount.cifs) — сообщите об этом.
  • Сообщения о проблемах безопасности в kernel-клиенте или в пользовательских утилитах (cifs-utils, mount.cifs) отправляйте на security@samba.org — никогда через IRC, публичные списки рассылки или Bugzilla.
  • Существуют две системы отслеживания ошибок:
    • для ядра: раздел ядра в багзилле Samba (в исходном тексте страницы: https://bugzilla.samba.org/)
    • для пользовательских утилит cifs: раздел cifs в багзилле ядра Linux
  • Вопросы можно задать в списке рассылки linux-cifs: linux-cifs@vger.kernel.org
  • Полезно приложить дамп трафика (network capture) и консольный лог ядра (kernel console log).

Команды для сбора отладочной информации (дословно со страницы):

    # make the kernel as verbose as possible
    echo 'module cifs +p' > /sys/kernel/debug/dynamic_debug/control
    echo 'file fs/cifs/* +p' > /sys/kernel/debug/dynamic_debug/control
    echo 1 > /proc/fs/cifs/cifsFYI
    echo 1 > /sys/module/dns_resolver/parameters/debug

    # get kernel output + network trace
    dmesg --clear
    tcpdump -s 0 -w trace.pcap & pid=$!
    sleep 3
    mount.cifs ....cd ... ls.. etc.. (the thing that fails)
    sleep 3
    kill $pid
    dmesg > trace.log

В результате получаются файлы trace.pcap (сетевой трассировочный файл) и trace.log (вывод ядра).

При сообщении об ошибке обязательно упомяните:

  • версию ядра;
  • программное обеспечение сервера и его версию.

Больше информации: https://wiki.samba.org/index.php/LinuxCIFS_troubleshooting

Подводные камни

  • Проблемы безопасности нельзя публиковать в Bugzilla, в IRC или публичных списках рассылки — только на security@samba.org. Это правило повторяется и для Samba, и для kernel-клиента cifs.
  • Без номера версии Samba в сообщении об ошибке репорт считается неполным — версия указывается всегда.
  • Для ошибок kernel-клиента обязательно указывайте версию ядра, а также серверное ПО и его версию — без этого воспроизведение затруднено.
