Настройка Samba в качестве сервера печати

Суть

Страница описывает настройку Samba как сервера печати: клиенты в сети отправляют задания на хост Samba по протоколу SMB — через мастер «Add printer» в Windows, CUPS на Linux-клиенте или сетевой интерфейс печати в macOS. Samba-принт-сервер имитирует поведение Windows-принт-сервера и поддерживает технологию point and print — клиенты автоматически скачивают драйвер принтера с сервера, без локальной установки. Печать строится поверх бэкенда печати (CUPS или LPRng), а для очередей и управления ими дополнительно включается служба spoolssd (в Samba 4.15 и старше — отдельной настройкой, в 4.16 и новее — через новый RPC daemon framework).

Ключевое

Требования

  • Для поддержки печати нужен работающий бэкенд печати на UNIX-хосте: CUPS-сервер, LPRng или другие бэкенды, перечисленные в параметре printing man-страницы smb.conf(5).
  • Бэкенд должен работать на локальном хосте; удалённый CUPS-сервер не поддерживается. Задания можно отправлять на удалённый CUPS через его внутренний форвардинг или CUPS-псевдопринтер (см. документацию CUPS).
  • Для шаринга всех очередей бэкенда нужна специальная шара [printers] в smb.conf.

Проверка поддержки CUPS в Samba

# smbd -b | grep "HAVE_CUPS"
HAVE_CUPS

Если вывод другой — проверить зависимости дистрибутива (заголовочные файлы CUPS) и то, как включается поддержка CUPS при сборке.

Добавление принтера в бэкенд печати

CUPS — добавить принтер printer_name:

# lpadmin -p printer_name -E -v ipp://printer_name/ipp/port

Для нелокального CUPS-сервера вместо ipp можно использовать URI lpd и smb, например:

  • lpd://printer_name/queue
  • ipp://printer_name/ipp/port
  • smb://username:password@domain/windows_print_server_host_name/printer_name

LPRng — добавить строку в /etc/printcap:

printer_name:sd=/var/spool/lpd/printer_name/:sh:mx=0:mc=0:rm=Printer_DNS_name_or_IP_address

Затем проверить printcap-кэш, каталоги спула и исправить проблемы:

# checkpc -f

Включение службы spoolssd (Samba 4.15 и старше)

Spoolssd интегрирована в smbd. Она поддерживает управление принтерами через MMC, кэширует spool-файлы и позволяет обрабатывать большое количество заданий/принтеров с низкой нагрузкой на CPU. Без spoolssd обработка spoolss идёт в smbd в один поток — при большом потоке заданий служба тормозит, MMC отвалится по таймауту.

В секцию [global] файла smb.conf:

rpc_server:spoolss = external
rpc_daemon:spoolssd = fork

Необязательные параметры стартового поведения (рекомендуется подстроить под себя):

spoolssd:prefork_min_children = 5           # Minimum number of children
spoolssd:prefork_max_children = 25          # Maximum number of children
spoolssd:prefork_spawn_rate = 5             # Start (n) new children if one of the existing children is used
spoolssd:prefork_max_allowed_clients = 100  # Number of clients a child process should handle
spoolssd:prefork_child_min_life = 60        # Minimum lifetime of a child process (60 seconds
                                            # is the minimum, even a lower value has been
                                            # configured)

Перезапустить Samba: у пакетной сборки — менеджером служб дистрибутива, например systemctl restart smbd; у самособранной — перезапустить демон smbd:

# killall smbd; smbd

spoolssd в Samba 4.16 и новее

Служба работает в новом RPC daemon framework и больше не является пулом prefork-процессов. Поведение настраивается так:

rpcd_spoolss:idle_seconds=300 # Controls how long an idle rpcd_spoolss process is kept
rpcd_spoolss:num_workers = 10 # Controls how many rpcd_spoolss processes are available

Значения по умолчанию:

rpcd_spoolss:idle_seconds = 60
rpcd_spoolss:num_workers = 5

idle_seconds — от 10 до 300, num_workers — от 1 до 100.

Включение принт-сервера: шара [printers]

Чтобы расшарить все принтеры бэкенда, добавьте специальную шару [printers]:

[printers]
 path = /var/tmp/
 printable = yes

После правки smb.conf перечитать конфигурацию (при неверных значениях/параметрах Samba не сможет перечитать конфиг):

# smbcontrol all reload-config

При printing = CUPS в [global] все принтеры из бэкенда CUPS расшариваются в Samba автоматически.

Ручной шаринг отдельного принтера

Чтобы расшарить только один принтер:

[Samba_printer_name]
 path = /var/tmp/
 printable = yes
 printer name = printer_name_in_the_back_end

Параметр printer name задаёт имя принтера в бэкенде печати. Затем перечитать конфигурацию:

# smbcontrol all reload-config

Принт-сервер на члене домена и standalone-сервере

На домен-члене (Samba как член домена) или standalone-сервере при ручном шаринге принтеров дополнительно отключить автозагрузку принтеров из бэкенда:

load printers = no

На AD DC это не требуется — параметр там игнорируется.

Раздача драйверов Windows-клиентам

Начиная с Windows 11 22H2 и Windows Server 2022, Windows по умолчанию пытается подключаться к принт-серверу только через шифрованный RPC-канал (NCALRPC с уровнем «Packet Privacy») и при отказе соединение рвёт. Дефолтная конфигурация Samba разрешает любой уровень шифрования RPC, а в некоторых дистрибутивах (например, Debian и Ubuntu) шифрование для всех RPC-соединений по умолчанию отключено — Windows-клиенты к таким принт-серверам не подключаются.

Принудительное шифрование на сервере:

[global]
	rpc server dynamic port range = 49152-65535
	rpc start on demand support = no
	rpc server ports = 49152-65535

	rpc servers = rpcecho, epmapper, winreg, srvsvc, netlogon, samr, lsarpc, drsuapi, dssetup, unixinfo, browser, eventlog6, backupkey, dnsserver

	raw tcp provider = rpcecho
	remote activation support = yes

	# Global settings
	rpc auth type = Kerberos
	rpc server context timeout = 30
	rpc server accept encryption = yes
	rpc server require encryption = yes

	# make sure we use SMB signing/encryption
	server signing = required
	server encryption = required

Принудительное шифрование на клиенте — через реестр:

reg add "HKLM\SYSTEM\CurrentControlSet\Control\Print" /v RpcAuthnLevelPrivacyEnabled /t REG_DWORD /d 1 /f

или

reg add "HKLM\Software\Policies\Microsoft\Windows NT\Printers\RPC" /v RpcUseProtSeq /t REG_SZ /d 1 /f
reg add "HKLM\Software\Policies\Microsoft\Windows NT\Printers\RPC" /v RpcAuthenticationLevel /t REG_SZ /d 1 /f

Автоматическая раздача драйверов (point and print) описана на отдельной странице вики — Setting up Automatic Printer Driver Downloads for Windows Clients.

Подводные камни

  • Бэкенд печати обязан работать на локальном хосте — удалённый CUPS-сервер напрямую не поддерживается (только пересылка заданий средствами CUPS или через CUPS-псевдопринтер).
  • Инструкция по включению spoolssd (rpc_server:spoolss = external, rpc_daemon:spoolssd = fork) — только для Samba 4.15 и старше; в 4.16+ служба живёт в новом RPC daemon framework и настраивается параметрами rpcd_spoolss:*.
  • Шара [printers] требует установки path и printable; path — это каталог спула, и он должен быть доступен на запись всем пользователям, которые печатают.
  • Если в smb.conf есть неверные значения или параметры, Samba не сможет перечитать конфигурацию.
  • Windows 11 22H2 / Windows Server 2022 и новее по умолчанию требуют шифрованный RPC к принт-серверу и «настойчиво» рвут нешифрованные соединения; в Debian/Ubuntu шифрование RPC отключено по умолчанию — клиенты к такому принт-серверу не подключатся (см. серверные и клиентские фиксы выше).
  • На члене домена/standalone при ручном шаринге принтеров обязательно load printers = no; на AD DC параметр игнорируется, ставить его там не нужно.
