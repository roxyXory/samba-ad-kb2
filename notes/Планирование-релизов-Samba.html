Samba Release Planning

Суть

Страница описывает цикл релизов Samba и режимы поддержки каждой версии (series). Каждая серия поддерживается около 18 месяцев: шесть месяцев полной поддержки, затем шесть месяцев в режиме обслуживания (maintenance mode) и ещё шесть месяцев — только исправления безопасности. Приведена таблица всех серий (от 3.0 до 4.25) с ветками Git, статусами и датами, а также регламент попадания патчей в релизные ветки.

Ключевое

Цикл релизов

Регулярный цикл релизов Samba предполагает для каждой серии:

  • шесть месяцев полной поддержки (fully supported);
  • ещё шесть месяцев в режиме обслуживания (maintenance mode);
  • шесть месяцев в режиме «только исправления безопасности» (security fixes only mode).

Итого каждая серия поддерживается примерно 18 месяцев. Пример из страницы: если 4.5 — текущая серия, то 4.4 находится в maintenance mode, 4.3 — в режиме «только security», а поддержка 4.2 прекращается с выходом 4.5.0.

  • Минорные релизы обычно выходят каждые 6 недель (для текущей стабильной серии) или каждые 9 недель (в maintenance mode).
  • Снятым с поддержки сериям (EOL, discontinued) обновления больше не выходят.
  • Новые возможности сначала попадают в ветку master — для включения в следующий стабильный релиз; разработка в master идёт параллельно со стабильными релизами.

Режимы поддержки (Modes)

  • Upcoming Release — новая готовящаяся ветка, не готова к продуктиву (not ready for production). Ветка создаётся, когда становится доступен первый Release Candidate; до этого разработка идёт в ветке master. Релизы выпускаются по фиксированному временному графику: удержать релиз могут лишь отдельные баги-блокеры (blocker bugs), соответствующие критериям остановки релиза-кандидата.
  • Current Stable Release — текущая релизная ветка. Исправления выходят в регулярных bug fix релизах — обычно каждые шесть недель (и по мере необходимости). Новые возможности или параметры добавляются только в мажорные релизы, а не внутри релизного цикла (возможны редкие исключения).
  • Maintenance Mode — регулярные bug fix релизы для крупных проблем и проблем безопасности. В эту ветку бэкпортится меньше патчей, чем в текущую стабильную серию.
  • Security Fixes Only Mode — в этой серии исправляются только проблемы безопасности. Samba Security Process используется на этом и всех предыдущих этапах: патчи готовятся и передаются вендорам Samba на эмбарго-условиях для скоординированного выпуска.
  • Discontinued (End of Life) — новых версий этой серии не будет.

Регламент коммитов в релизные ветки

Релизная ветка создаётся в момент первого release candidate. Для каждой серии есть две разные ветки:

  • v4-X-stable — последний официальный релиз (или release candidate). Используется для бэкпорта исправлений безопасности.
  • v4-X-test — то, что станет следующим официальным релизом (кроме security-релизов). Используется для бэкпорта всех остальных исправлений.

Релизные ветки закрыты для прямых коммитов с момента создания — в них допускаются только исправления багов по следующей процедуре:

  1. Каждый баг, патч которого попадает в релизную ветку, должен быть привязан к багрепорту в Samba Bugzilla.
  2. Если это регрессия — блокер мажорного релиза, отметить её как regression и выставить правильный milestone.
  3. Патч по возможности уже должен быть в master. Если ожидается бэкпорт — баг открывается до коммита в master.
  4. Добавить к патчу теги:
BUG: https://bugzilla.samba.org/show_bug.cgi?id=XXXXX
RN: <high-level description of the bugfix for the release notes (understandable 
for admins without code knowledge), can be multi-line, followed by a blank line
to mark the end of the RN>
  1. После прохождения autobuild и попадания в master на git.samba.org патч переносится в ветку командами git cherry-pick -x и git format-patch -1. Опция cherry-pick -x добавляет маркер (cherry picked from commit XXXXX), позволяющий отследить историю патча между ветками. Пример:
(cherry picked from commit 047b0d8ab534c7a10a8572fd9f21e2456fd30710)
  1. Если cherry-pick не применился чисто, строку (cherry picked from commit XXXXX) меняют на (backported from commit XXXXX) и на следующей строке добавляют однострочное пояснение конфликта в формате [your@mail: reason]. Пример:
(backported from commit 62621bd686a91328ae378cd56f9876c66be8eac4)
[slow@samba.org: delay_for_oplock() got refactored in 4.12]
  1. Добавить BUG-теги патчам, у которых их нет. Баг должен быть в статусе ASSIGNED (если закрыт — переоткрыть); на этом этапе допустимо завести баг, если его ещё нет.
  2. Автор патча должен убедить двух членов команды, что баг достаточно критичен для релизной ветки: выставляется флаг review? на загруженном патче. Член команды загружает патч — ревью нужен ещё один участник; не член команды — просит двух членов команды.
  3. После ревью ревьюер назначает патч на samba-release@samba.org.
  4. Release Manager применяет патч из Bugzilla только при sign-off от двух членов Samba Team, а закрывает баг после попадания патчей во все соответствующие ветки.

См. также Обновление Samba о процедуре обновления, Git для разработки Samba о работе с Git и Код ревью о процессе ревью.

Подводные камни

  • Поздние патчи. Патчи для релизных веток подавайте заранее: присланные слишком близко к дате релиза могут не попасть в него. Применение патчей из Bugzilla в релизную ветку — ручной процесс, и «слишком близко» целиком на усмотрение Release Manager.
  • Неполные маркеры ревью. Патчи без полных review-маркеров и т.п. не рассматриваются.
  • Не меняйте release candidate в последний момент. Постоянные изменения противоречат духу названия «release candidate»; слишком много изменений после финального RC в прошлом задерживало релизы.
  • Приблизительные даты. Будущие даты в таблице с пометкой ~ — лишь прогнозы по историческому паттерну; детали цикла — на усмотрение release manager.
  • Upcoming Release не для продакшена. Готовящаяся серия до статуса стабильной не предназначена для производственной эксплуатации.
  • Статусы серий в таблице устаревают. Таблица — снимок на дату последней правки страницы; «текущая стабильная серия» на момент чтения может быть другой (на 2026-10-07 стабильная — 4.25, а не 4.24). Сверяться с Главная Samba Wiki.
