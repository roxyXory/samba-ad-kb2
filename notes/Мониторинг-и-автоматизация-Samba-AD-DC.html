База знаний Samba AD DC

Мониторинг и автоматизация Samba AD DC

Суть

Регулярная проверка здоровья контроллеров домена Samba опирается на штатные подкоманды samba-tool: drs showrepl (статус репликации, с машинно-читаемыми режимами --json и --summary), dbcheck --cross-ncs (консистентность локальной базы — запускается на каждом DC отдельно, не по LDAP), ldapcmp (сравнение баз двух DC по LDAP) и ntacl sysvolcheck (ACL каталога SysVol и GPO). Для неинтерактивного запуска из скриптов пароль передаётся не через --password, а через переменные окружения PASSWD, PASSWD_FD или PASSWD_FILE. Автоматизацию удобно строить на Ansible: задачи вокруг AD DC закрывает community-коллекция jomrr.samba (нативные Python-биндинги, идемпотентность, check mode), объекты AD — общие модули community.general.ldap_entry / ldap_attrs / ldap_passwd; официальной коллекции от Samba Team в Ansible Galaxy нет.

Ключевое

Проверка репликации: samba-tool drs showrepl

Команда samba-tool drs showrepl выводит входящие и исходящие соглашения репликации с другими DC леса; результат даётся с точки зрения того DC, на котором команда запущена (страница вики Verifying the Directory Replication Statuses):

# samba-tool drs showrepl
Default-First-Site-Name\DC2
DSA Options: 0x00000001
DSA object GUID: c14a774f-9732-4ec2-b9fa-2156c95c4e48
DSA invocationId: 7bdb135c-6868-4dd9-9460-33dea4b6b87b

==== INBOUND NEIGHBORS ====

CN=Schema,CN=Configuration,DC=samdom,DC=example,DC=com
       Default-First-Site-Name\DC1 via RPC
               DSA object GUID: 4a6bd92a-6612-4b15-aa8c-9ec371e8994f
               Last attempt @ Sat May 13 02:52:36 2017 CEST was successful
               0 consecutive failure(s).
               Last success @ Sat May 13 02:52:36 2017 CEST
...
  • По умолчанию реплицируются контейнеры DC=Forest_Root_Domain, CN=Configuration,..., CN=Schema,..., DC=ForestDnsZones,..., DC=DomainDnsZones,....
  • KCC (knowledge consistency checker) не строит полносвязную топологию: после присоединения нового DC может пройти до 15 минут, пока KCC создаст connection objects и репликация по всем контейнерам начнётся. Поэтому пустой/неполный вывод сразу после join — не всегда авария.
  • В секции ==== KCC CONNECTION OBJECTS ==== встречается предупреждение Warning: No NC replicated for Connection! — вики отсылает за разъяснением к FAQ (см. FAQ Samba).
  • На Windows DC аналог — repadmin /showrepl; исходящую репликацию Windows не показывает, её смотрят через showrepl на Samba DC, куда реплицирует Windows DC.

Режимы для скриптов (man-страница samba-tool(8) 4.25.0):

drs showrepl — Show replication status. The [--json] option results in JSON output, and with the [--summary] option produces very little output when the replication status seems healthy.

  • --summary — «very little output», пока репликация здорова; --json — JSON. Release notes Samba 4.9.0 (раздел «New samba-tool options for diagnosing DRS replication issues»): «With --summary, the command says very little when DRS replication is working well. With --json, JSON is produced. These options are intended for human and machine audiences, respectively.» В теге 4.8.0 этих опций в исходнике python/samba/netcmd/drs.py ещё нет — то есть для скриптов они доступны начиная с 4.9.0.
  • Исходник 4.25.0 добавляет к ним не описанные в man-странице --pull-summary («Have we successfully replicated from all relevant servers?») и --notify-summary («Have we successfully notified all relevant servers of local changes…»), а также --classic (режим по умолчанию) и -v/--verbose.
  • --summary возвращает код выхода 1, если есть проблемные связи: он печатает [ALL GOOD] (зелёным), когда всё в порядке, иначе — There are failing connections с деталями и return 1. Проблемной считается не удалённая связь (is deleted) с consecutive failures != 0 или last success == 0 (исходник python/samba/netcmd/drs.py). Точка входа samba-tool завершается через sys.exit(retval), поэтому этот код виден мониторингу (Nagios/check-скрипты, systemd-таймер).
  • JSON (там же): объект содержит dsa (options, objectGUID, invocationId), массивы repsFrom/repsTo и NTDSConnections; ключи site и server из JSON удаляются при выводе. Элемент связи: NC dn, DSA objectGUID, DSA, last attempt time, last attempt message, consecutive failures, last success, NTDS DN, is deleted.
  • Пример разбора (структура полей — из исходника, не из документации; jq — внешний инструмент):
samba-tool drs showrepl --json | jq '.repsFrom[] | select(.["consecutive failures"] > 0)'
  • Для оценки отставания репликации есть отдельные команды: samba-tool drs uptodateness (man-страница: -H/--URL, -p/--partition, --json, --maximum, --median, --full) и samba-tool visualize uptodateness — «visualizes replication lag as a heat-map matrix based on the DRS uptodateness vectors. This will show you if (but not why) changes are failing to replicate to some DCs» (release notes 4.9.0). Подкоманда drs uptodateness присутствует в исходнике начиная с 4.10.0 (в теге 4.9.0 её ещё нет), --json у неё есть уже в 4.10.0.

Консистентность базы: samba-tool dbcheck --cross-ncs

  • dbcheck — «Check the local AD database for errors.» (man-страница). Проверка: # samba-tool dbcheck --cross-ncs. Без --cross-ncs проверяется только основная партиция домена; с ней — все партиции (naming contexts).
  • Запускать локально на каждом DC: «You must run the check and fix command on every Samba AD DC locally, because some fixes apply to non-replicated attributes and modifications are not replicated to other DCs. The tool cannot be run over LDAP.» (вики Dbcheck). Выполнять регулярно: «As database inconsistencies have the potential to accumulate over time, it is worth running dbcheck regularly.»
  • Запуск без --fix только сообщает о проблемах и «is completely safe»; --fix правит базу. Команда исправления:
# samba-tool dbcheck --cross-ncs --fix
  • С --fix вопросы задаются по каждой ошибке; ответ all исправляет все ошибки того же типа. Параметр --yes отвечает «да» автоматически. Ускорение заметное: «passing the --yes parameter to the command fixed 3500 objects in 10 seconds in our test environment. Without this parameter, the command required 4:50 minutes for the same operation»; причина — без --yes на каждый объект выполняется три вызова fsync().
  • Формулировка из --help в исходнике 4.25.0: «don't confirm changes individually. Applies all as a single transaction (will not succeed if any errors are found)»; в 4.5–4.7 текст был «don't confirm changes, just do them all as a single transaction». По исходнику 4.25.0 единая транзакция открывается только при --fix --yes вместе (if yes and fix: samdb.transaction_start()).
  • После починки базу проверяют повторно. Перед --fix вики советует сделать резервную копию домена (лучше и online-, и offline-): «The dbcheck tool is modifying your database… There is a small risk that the act of fixing the problem could itself have a unforeseen and negative side-effects» (см. Резервное копирование и восстановление AD DC).
  • Если починка навредила, вики предлагает по порядку: samba-tool drs replicate --full-sync --sync-forced по всем партициям; переподключить DC (join заново, база пересобирается); в крайнем случае восстановить домен из backup-файла (потребует заново присоединить все DC).

Сравнение двух DC: samba-tool ldapcmp

  • Вики: подкоманда сравнивает LDAP-базы двух DC независимо от того, Samba это или Windows.
  • Ограничения: сравнение идёт по LDAP, сервер должен быть доступен на порту 389; сравниваются только объекты, возвращаемые wildcard-поиском (скрытые атрибуты не обрабатываются); часть атрибутов игнорируется явно — «non replicating attributes… always have different values on the corresponding objects in separate DCs».
  • Примеры из вики:
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator domain
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator configuration
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator schema
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator dnsdomain
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator dnsforest
  • Даже на исправной репликации сравнение контекста domain падает на нереплицируемых атрибутах msDS-NcType и serverState, а в configuration добавляется subrefs; их исключают фильтром:
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator domain --filter=msDS-NcType,serverState
# samba-tool ldapcmp ldap://DC1 ldap://DC2 -Uadministrator --filter=msDS-NcType,serverState,subrefs
  • Исходник 4.25.0, дополнительные опции: -w/--two (домены разные), -q/--quiet — «Do not print anything but relay on just exit code», -v/--verbose, --sd (сравнивать только nTSecurityDescriptor), --sort-aces, --view section|collision, --base/--base2, --scope SUB|ONE|BASE, --filter («List of comma separated attributes to ignore in the comparison»), --skip-missing-dn.
  • При расхождениях команда поднимает CommandError("Compare failed: %d" % status) — то есть завершается с ненулевым кодом; в связке с --quiet это готовый чек для мониторинга.

ACL SysVol: samba-tool ntacl sysvolcheck

  • man-страница: ntacl sysvolcheck — «Check sysvol ACLs match defaults (including correct ACLs on GPOs).»; парная команда ntacl sysvolreset — «Reset sysvol ACLs to defaults (including correct ACLs on GPOs).»
  • Исходник 4.25.0: sysvolcheck берёт из smb.conf пути netlogon и sysvol, извлекает domain_sid и вызывает provision.checksysvolacl(...) — то есть проверяются ACL всего дерева SysVol, включая GPO.
  • Команда локальная (работает с ACL файловой системы конкретного DC), поэтому её имеет смысл запускать на каждом DC.
  • На присоединённом DC: сначала синхронизировать SysVol, затем # samba-tool ntacl sysvolreset; «If there are more than the default GPOs in Sysvol on the other DC(s), you must sync Sysvol to the new DC, samba-tool ntacl sysvolreset will throw an error if you do not» (вики Joining a Samba DC…). См. Репликация SysVol.

Неинтерактивный samba-tool: PASSWD, PASSWD_FD, PASSWD_FILE

man-страница samba-tool(8) 4.25.0, общий блок про --password:

Specify the password on the commandline. […] If --password is not specified, the tool will check the PASSWD environment variable, followed by PASSWD_FD which is expected to contain an open file descriptor (FD) number. Finally it will check PASSWD_FILE (containing a file path to be opened). The file should only contain the password. Make certain that the permissions on the file restrict access from unwanted users!

Там же о безопасности: не включать пароли в скрипты и не передавать значения пользователей в командную строку; лучше дать инструменту запросить пароль или получить билет через kinit; «While Samba will attempt to scrub the password from the process title (as seen in ps), this is after startup and so is subject to a race.»

  • Порядок поиска подтверждается реализацией в исходниках Samba: auth/credentials/credentials.c последовательно вызывает getenv("PASSWD"), getenv("PASSWD_FD") (номер FD, atoi) и getenv("PASSWD_FILE") (путь к файлу). Этот код общий для инструментов Samba, поэтому переменные работают и для samba-tool.
  • Альтернативы из той же man-страницы: -U|--user=[DOMAIN\]USERNAME[%PASSWORD] — при отсутствии %PASSWORD клиент сначала смотрит USER (там пароль допустим через %), затем LOGNAME (пароль не допускается), затем может взять имя из кэша билетов Kerberos; отдельно есть файл учётных данных (-A).
  • В тестах самой Samba встречается форма с дескриптором: out=$(PASSWD_FD=0 eval $cmd) (testprogs/blackbox/test_net_offline.sh).

Автоматизация на Ansible: community-коллекция jomrr.samba

Коллекция jomrr.samba (автор Jonas Mauer, GPL-3.0-or-later, репозиторий на GitHub) управляет доменом Samba AD через нативные Python-биндинги (samba.samdb.SamDB, samba.join, samba.net_s3, samba.dcerpc), а не через подпроцессы samba-tool. «Every module is idempotent and supports check mode: the object modules diff the current against the desired state, while the lifecycle modules use a binary "is it already provisioned/joined?" check. A second run with the same parameters reports changed: false.»

Требования (README и meta/runtime.yml артефакта 2.4.0):

  • python3-samba на исполняющем хосте (модули импортируют samba.samdb.SamDB; без биндингов падают с missing_required_lib);
  • ansible-core >= 2.19.0;
  • Kerberos/GSSAPI: рабочее разрешение DNS/SRV до DC, подходящий krb5.conf, синхронные часы;
  • атрибуты RFC2307/POSIX (uid_number, gid_number, unix_home_directory, login_shell, gecos и др.) требуют домена, развёрнутого с --use-rfc2307.

Модули (README коллекции; для 2.4.0 в артефакте — 20 файлов модулей):

Модуль Назначение
samba_provision развернуть новый DC (запускается локально на будущем DC; check mode только сообщает changed, сам провижн в нём не выполняется)
samba_join_dc присоединить хост к домену как дополнительный DC (samba.join, полная репликация; запуск локально на присоединяемом хосте)
samba_join_member, samba_join_sssd член домена через winbind (samba.net_s3, secrets.tdb) и через adcli (keytab); samba_join_sssd объявлен устаревшим с удалением в 3.0.0
samba_user, samba_group, samba_ou, samba_computer (+ *_info) объекты каталога; идемпотентны, check mode, diff
samba_dns_record, samba_dns_zone (+ *_info) DNS-записи и AD-интегрированные зоны Samba Internal DNS
samba_password_policy, samba_password_settings политика паролей домена и объекты тонких политик (PSO)
samba_schema_extension, samba_ntacl расширение схемы (LAPS, OpenSSH, LDAP compat) и NT ACL корней шар

Подключение объектных модулей: LDAP с SASL/GSSAPI, принудительно client ldap sasl wrapping = seal (шифрование), порт 389, без LDAPS/StartTLS; билет Kerberos держится в памяти процесса; учётные данные задаются явно (server, bind_username, bind_password, realm) и один раз выносятся в module_defaults через группу действий jomrr.samba.all. Объектные модули предпочтительно запускать на самом DC (loopback); вариант с контроллера требует python3-samba на контроллере и открытого RPC endpoint mapper для управления DNS-зонами.

Пример провижна (дословно из README):

- name: Provision a new Samba AD domain controller
  hosts: dc1.example.com           # runs locally on the host becoming the DC
  tasks:
    - name: Ensure the domain is provisioned
      jomrr.samba.samba_provision:
        realm: EXAMPLE.COM
        domain: EXAMPLE
        admin_password: "{{ vault_dc_admin_password }}"   # from Ansible Vault
        dns_backend: SAMBA_INTERNAL
        use_rfc2307: true
        state: present

На Ansible Galaxy высшая версия коллекции — 2.4.0: в MANIFEST.json артефакта указаны репозиторий https://github.com/jomrr/ansible-collection-samba и requires_ansible: ">=2.19.0" (поле license пустое, есть license_file: LICENSE); лицензия по README и файлу LICENSE — GNU GPL v3.0 или новее.

Автоматизация объектов AD: community.general.ldap_entry / ldap_attrs / ldap_passwd

  • ldap_entry — «Add or remove LDAP entries. This module only asserts the existence or non-existence of an LDAP entry, not its attributes. To assert the attribute values of an entry, see community.general.ldap_attrs.» Требует python-ldap; поддержка check mode — full, diff mode — none.
  • ldap_attrs — «Add or remove multiple LDAP attribute values»; state=present добавляет недостающие значения, absent удаляет указанные, exact приводит набор значений ровно к заданному.
  • ldap_passwd — «Set a password for an LDAP entry. This module only asserts that a given password is valid for a given entry.»; параметры dn, passwd, bind_dn, bind_pw.
  • По умолчанию модули пытаются SASL-бинд EXTERNAL через UNIX-сокет; для явного простого бина задаются bind_dn/bind_pw.

Пример из документации ldap_entry:

- name: Make sure we have a parent entry for users
  community.general.ldap_entry:
    dn: ou=users,dc=example,dc=com
    objectClass: organizationalUnit

Официальной коллекции Samba Team не существует

  • В Ansible Galaxy нет пространства имён samba (API v3 отдаёт HTTP 404; запрос /api/v3/namespaces/?name=samba — 0 записей; также отсутствуют samba-team и sambateam). Коллекция вида samba.* от команды Samba не публиковалась — искать её не нужно.
  • Все коллекции с именем «samba» (поиск API .../collection-versions/?name=samba) — community-проекты:
    • jomrr.samba — Samba AD DC (провижн, join, объекты, DNS, политики) — то, что нужно для AD DC;
    • vladgh.samba — только файловый сервер: «An Ansible collection for setting up Samba as a file server» (README 3.5.9), задачи — установка пакетов, каталоги шар, пользователи, доступ; «The following are not considered concerns of this collection… Managing firewall settings. Creating system users.»;
    • eliminyro.samba (1.0.1) — также файловый сервер/клиент: роли config (шары, пользователи, безопасность) и mount (монтирование CIFS на клиентах);
    • vmutti.samba (1.0.2) — не роль: install.sh + восстановление архива конфигов и users.backup.tdb.
  • Поиск Galaxy по ключевому слову «samba» (keywords=samba) возвращает 176 версий коллекций, среди которых много совпадений по содержимому (например, jcook3701.pkgs с playbook samba.yml) — на такие совпадения ориентироваться не стоит.

Подводные камни

  • dbcheck предназначен для локального запуска на каждом DC: часть исправлений касается неповторяемых атрибутов, они не реплицируются. Man-страница при этом описывает -H/--URL («LDB URL for database or target server»), а исходник умеет подключаться по ldap://, но рабочее правило из вики — запускать на самом DC.
  • --yes без --fix ничего не исправляет; единая транзакция (и связанное с ней ускорение) включается только при --fix --yes (исходник 4.25.0). Если ошибки найдены, в этом режиме не применяется ничего — это ожидаемое поведение, а не сбой.
  • --fix модифицирует базу и может дать неожиданные побочные эффекты; полностью безопасен только прогон без --fix. Перед починкой — резервная копия домена (лучше online + offline), после починки — повторная проверка.
  • Warning: No NC replicated for Connection! в выводе showrepl — не обязательно поломка: вики отсылает за объяснением к FAQ. Отсутствие соседей сразу после join тоже нормально — до 15 минут на построение связей KCC.
  • В JSON drs showrepl нет ключей site/server (удаляются при выводе), а связи с is deleted нужно отбрасывать — «summary» считает проблемными только живые связи, иначе скрипт увидит ложные ошибки.
  • ldapcmp всегда найдёт различия в нереплицируемых атрибутах (msDS-NcType, serverState, subrefs) — без --filter сравнение не имеет смысла как регулярная проверка; для машинного использования есть -q и ненулевой код возврата.
  • ntacl sysvolcheck/sysvolreset работают с ACL локальной файловой системы и путями sysvol/netlogon из smb.conf; на новом DC без синхронизированного SysVol (нестандартные GPO) sysvolreset завершится ошибкой.
  • Модули community.general.ldap_* используют python-ldap и по умолчанию пробуют SASL EXTERNAL через UNIX-сокет. В Samba по умолчанию действует ldap server require strong auth = yes: «Unencrypted connections only allow sasl binds with sign or seal» — простой бинд по незашифрованному 389 будет отвергнут, поэтому для объектов AD нужен LDAPS/StartTLS (см. LDAPS Сертификаты AD DC).
  • jomrr.samba требует python3-samba на исполняющем хосте и ansible-core >= 2.19.0 — на старых ansible-core коллекция не заработает; samba_join_sssd объявлен устаревшим (удаление в 3.0.0). Это community-коллекция, не официальная; версия, проверенная для этой заметки, — 2.4.0.
  • Опции --json и --summary у drs showrepl появились только в Samba 4.9.0: на 4.7/4.8 их нет (проверено по исходнику и release notes). Для мониторинга лагов репликации нужен ещё более новый Samba: подкоманда drs uptodateness есть в исходнике с 4.10.0 (в 4.9.0 — только visualize uptodateness).
  • Переменные PASSWD/PASSWD_FD/PASSWD_FILE — не нововведение 4.25.0: реализация в auth/credentials/credentials.c присутствует уже в теге 4.0.0, а блок man-страницы с их описанием (docs-xml/build/DTD/samba.entities) появляется начиная с 4.15.0 (в 4.14.0 этих строк ещё нет).

Отсюда: описание drs showrepl с --json/--summary, dbcheck, ldapcmp (синтаксис), ntacl sysvolcheck/sysvolreset, drs uptodateness (список опций), visualize, блок --password с PASSWD/PASSWD_FD/PASSWD_FILE и -U/--user с USER/LOGNAME.
  • https://wiki.samba.org/index.php/Dbcheck — обязательный локальный запуск на каждом DC, --cross-ncs, --fix, --yes (3500 объектов: 10 с против 4:50), список проверок, «worth running dbcheck regularly», precautions и порядок восстановления после неудачной починки.
  • https://wiki.samba.org/index.php/Samba-tool_ldapcmp — команды сравнения целиком и по партициям, ограничения (LDAP/389, wildcard, нереплицируемые атрибуты), примеры --filter=msDS-NcType,serverState,subrefs.
  • https://wiki.samba.org/index.php/Verifying_the_Directory_Replication_Statuses — назначение и формат вывода samba-tool drs showrepl (INBOUND/OUTBOUND NEIGHBORS, KCC CONNECTION OBJECTS), до 15 минут на создание связей KCC, список реплицируемых контейнеров, repadmin /showrepl на Windows DC.
