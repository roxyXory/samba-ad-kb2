База знаний Samba AD DC

PowerShell-командлеты AD и атрибуты объектов

Суть

Администрировать домен из Windows удобно штатными средствами: оснастками RSAT (ADUC, DNS, GPMC) и модулем PowerShell ActiveDirectory. Но есть принципиальное ограничение: модуль ActiveDirectory работает только через ADWS (Active Directory Web Services, TCP 9389), а в Samba AD DC ADWS не реализован — соответствующий запрос в багтрекере Samba (bug 11231 «Active Directory Web Services (ADWS) should be supported») до сих пор в статусе NEW. Поэтому против чистого Samba DC командлеты Get-ADUser, New-ADUser и т.п. не работают — они уместны только в смешанном домене с Windows DC. Ниже: что работает с Samba, таблица соответствия командлетов (для смешанных доменов и как справочник), рабочие способы через LDAP из PowerShell и «данные» — атрибуты AD-объектов.

Что реально работает с Samba AD DC

  • Оснастки RSAT по LDAP/RPC: dsa.msc (ADUC), dnsmgmt.msc, gpmc.msc — работают с Samba DC (см. Групповые Политики GPO).
  • ADAC (dsac.exe) и модуль ActiveDirectory — требуют ADWS, с Samba DC не работают.
  • PowerShell через LDAP: System.DirectoryServices.Protocols или System.DirectoryServices (ADSI) — работают против Samba без ADWS (примеры ниже).
  • samba-tool — штатный путь для всех операций (см. Управление пользователями группами и OU).

Примеры (для домена с Windows DC или смешанного):

New-ADUser -Name "Иван Иванов" -SamAccountName ivanov -UserPrincipalName ivanov@samdom.example.com `
  -GivenName "Иван" -Surname "Иванов" -Path "OU=Отделы,DC=samdom,DC=example,DC=com" `
  -AccountPassword (ConvertTo-SecureString 'Str0ng!Passw0rd' -AsPlainText -Force) `
  -Enabled $true -ChangePasswordAtLogon $true

Get-ADUser -Filter * -SearchBase "OU=Отделы,DC=samdom,DC=example,DC=com" -Properties mail,uidNumber |
  Select-Object SamAccountName, Name, mail, uidNumber

Add-ADGroupMember -Identity it -Members ivanov,petrov
Get-ADGroupMember -Identity it -Recursive | Select-Object Name, SamAccountName

Set-ADAccountPassword -Identity ivanov -Reset -NewPassword (ConvertTo-SecureString 'N3w!Passw0rd' -AsPlainText -Force)
Unlock-ADAccount -Identity ivanov
Move-ADObject -Identity "CN=Иван Иванов,OU=Отделы,DC=samdom,DC=example,DC=com" -TargetPath "OU=IT,DC=samdom,DC=example,DC=com"

PowerShell через LDAP: рабочий обход для Samba

Чтение (DirectoryServices.Protocols):

$cred = New-Object System.Net.NetworkCredential('STAND\mininode2admin', 'Пароль')
$ldap = New-Object System.DirectoryServices.Protocols.LdapConnection('dc1.stand.local:389')
$ldap.AuthType = [System.DirectoryServices.Protocols.AuthType]::Basic
$ldap.Credential = $cred
$ldap.Bind()

$req = New-Object System.DirectoryServices.Protocols.SearchRequest(
  'OU=MiniNode1,DC=stand,DC=local', '(objectClass=user)',
  [System.DirectoryServices.Protocols.SearchScope]::OneLevel)
$resp = $ldap.SendRequest($req)
foreach ($e in $resp.Entries) { $e.DistinguishedName }

ADSI (проще для чтения свойств):

$searcher = New-Object System.DirectoryServices.DirectorySearcher
$searcher.SearchRoot = [ADSI]"LDAP://OU=MiniNode1,DC=stand,DC=local"
$searcher.Filter = '(objectClass=user)'
$searcher.PageSize = 1000
$searcher.FindAll() | ForEach-Object { $_.Properties['distinguishedname'][0] }

Запись пароля через LDAP требует защищённого канала (LDAPS/StartTLS): атрибут unicodePwd принимается только по TLS, иначе LDAP_SERVER_UNAVAILABLE/unwilling to perform.

Ключевые атрибуты AD-объектов (данные)

Идентификаторы

Атрибут Что это Пример
distinguishedName полный DN объекта CN=ivanov,OU=Отделы,DC=samdom,DC=example,DC=com
objectGUID неизменный GUID объекта (переживает переименование/перемещение) {4a6b...}
objectSid SID: S-1-5-21-<domain>-<rid> S-1-5-21-1004336348-...-1105
sAMAccountName логин (≤20 символов) ivanov

Учётная запись

Атрибут Что это
userAccountControl битовая маска состояния: 512 — обычная включённая учётка, 514 — отключённая (512+2), 66048 — пароль не истекает (512+65536), 66050 — отключена + пароль не истекает
pwdLastSet время установки пароля (FILETIME; 0 — «сменить при следующем входе»)
accountExpires срок действия (FILETIME; 0 и 9223372036854775807 — бессрочно)
lastLogonTimestamp время последнего входа (реплицируется, точность до ~14 дней)
logonHours разрешённые часы входа (битовая строка)
msDS-User-Account-Control-Computed вычисляемые флаги (например, LOCKED_OUT)

Группы

Атрибут Что это
groupType тип/область: Global Security = -2147483646, Domain Local Security = -2147483644, Universal Security = -2147483640; Distribution: 2 / 4 / 8
member / memberOf состав группы (прямой) / прямые группы объекта
primaryGroupID первичная группа (обычно 513 = Domain Users); в Samba менять без нужды не стоит
isCriticalSystemObject защищённая системная группа (не удалять)

Unix / RFC2307

Атрибут Что это
uidNumber, gidNumber Unix uid/gid (нужны для бэкенда idmap ad)
loginShell, unixHomeDirectory оболочка и домашний каталог
gecos описание пользователя
unixPrimaryGroup первичная Unix-группа (в Samba задаётся через unix_primary_group = yes)

Практические выборки

Модуль AD (только при наличии ADWS/Windows DC):

# пользователи без почты
Get-ADUser -Filter * -Properties mail | Where-Object { -not $_.mail }

# экспорт в CSV
Get-ADUser -Filter * -Properties mail,uidNumber,lastLogonTimestamp |
  Select-Object SamAccountName, Name, mail, uidNumber, lastLogonTimestamp |
  Export-Csv users.csv -NoTypeInformation -Encoding UTF8

# отключённые учётки, которые не входили 90 дней
Search-ADAccount -AccountDisabled -UsersOnly |
  Where-Object { $_.LastLogonDate -lt (Get-Date).AddDays(-90) }

Без ADWS (Samba): те же выборки через ldbsearch/ldapsearch (см. Управление пользователями группами и OU) или PowerShell + LDAP (выше).

Подводные камни

  • ADWS — ключевое ограничение: в Samba его нет (bug 11231, NEW), поэтому модуль ActiveDirectory против Samba DC не работает; не тратьте время на Get-ADUser -Server samba-dc.
  • Атрибуты схемы: часть атрибутов Windows (claims, central access policy, msDS-KeyCredentialLink на старых версиях) в Samba отсутствует или поддерживается частично — проверяйте версию.
  • userAccountControl нельзя менять «в лоб»: используйте Set-ADAccountControl / Enable-ADAccount, иначе легко получить противоречивые флаги.
  • objectSid и objectGUID неизменяемы — не пытайтесь их «исправить»; SID задаёт права, GUID — ссылки.
  • sAMAccountName ≤ 20 символов; UPN должен быть в допустимом суффиксе леса.
  • unicodePwd только по TLS (LDAPS/StartTLS) — иначе запись пароля отклоняется.
  • primaryGroupID не меняйте без необходимости: Windows и Samba рассчитывают на членство всех в Domain Users (в Samba смена ломает поведение).
  • GPO через GPMC работает, ADAC — нет (ADAC тоже требует ADWS).
  • PowerShell 7: модуль ActiveDirectory требует Windows PowerShell 5.1 (совместимость через -UseWindowsPowerShell).
