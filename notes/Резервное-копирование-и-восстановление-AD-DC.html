База знаний Samba AD DC

Резервное копирование и восстановление Samba AD DC

Суть

Страница описывает создание резервных копий домена Samba AD на Samba v4.9 и новее (для Samba v4.0–v4.8 используется отдельный скрипт резервного копирования). Бэкапы позволяют восстановить весь домен Samba AD в случае катастрофического сбоя, но не отдельные DC. Все типы копий создаются вариантами команды samba-tool domain backup и дают файл .tar.bz2, из которого домен разворачивается командой samba-tool domain backup restore.

Ключевое

Что именно резервируется

  • Бэкап восстанавливает домен, а не отдельные DC. Восстановление из бэкап-файла создаёт новый DC с данными домена; остальные DC затем нужно заново присоединить (join) к восстановленному.
  • Если DC используется ещё и как файлсервер (не рекомендуется), эти данные нужно резервировать отдельно.
  • Достаточно бэкапить доменные данные одного DC, но можно всех — для избыточности; для воссоздания домена используется только одна из копий.
  • Детали копии сохраняются в файле backup.txt внутри бэкап-файла.

Три типа бэкапов

  • Online — клон базы работающего DC, по сути аналогичен присоединению нового DC к сети. Лучший вариант для долгосрочной замены домена.
  • Offline (local) — копирует файлы Samba так, как они лежат на диске, включая локальные метаданные репликации, которых нет в online-копии. Доступен с Samba v4.10 (остальные команды — с v4.9).
  • Rename — бэкап с переименованным доменом, только временная замена; восстановленный домен может работать параллельно с отказавшим, так как имя другое.

Какой бэкап выбрать

  • Rename — временная заменяющая домен-копия; плох как долгосрочная замена.
  • Online — долгосрочная замена, если не планируете разбираться в причинах сбоя, а просто откатываетесь к рабочей копии.
  • Offline — лучше всего для форензики (содержит нереплицируемые данные); быстрее для большого домена; содержит все секреты домена; может скопировать уже имеющуюся порчу базы.

Восстановление одиночного DC

База AD распределена по DC, репликация держит копии в синхроне. Если сломался один DC, а домен в порядке — просто переприсоедините его командой samba-tool domain join dc: локальная база перезапишется свежей копией. Никогда не используйте samba-tool domain backup/restore для восстановления отдельного DC.

Пример сценария восстановления домена

Админ случайно изменил/удалил объект, и порча отреплицировалась на все DC. Порядок действий:

  1. Остановить все DC со сломанной копией базы (двух копий одного домена быть не может).
  2. Восстановить новый DC из «хорошего» бэкап-файла.
  3. Заново присоединить (rejoin) старые DC — простого перезапуска samba недостаточно: DC продолжит использовать старую сломанную базу, и в сети окажутся два разных домена.

Тестирование восстановления

  • Rename-бэкап всегда безопасно восстановить на новый DC и запустить samba — он не конфликтует с продакшеном; если rename работает, скорее всего сработает и online.
  • Распаковать бэкап на диск (untar) безопасно, если не запускать samba на распакованной базе; объекты можно проверить утилитой ldbsearch по локальному пути к базе.
  • Варианты: лабораторный домен для проверки online/offline-копий либо полная изоляция восстановленного DC на коммутаторах (сложно сделать правильно).
  • Перед созданием нового бэкапа полезно прогонять samba-tool dbcheck (у него есть опция --fix), иначе все проблемы базы пройдут сквозь бэкап и восстановление.

Online-бэкап

sudo samba-tool domain backup online --targetdir=<output-dir> --server=<DC-server> -UAdministrator

Команда выполняется локально на DC или удалённо на другой машине; при удалённом запуске может понадобиться опция --configfile, чтобы в бэкап попал правильный smb.conf.

Offline-бэкап

Выполнить на самом DC, указав каталог для бэкап-файла:

sudo samba-tool domain backup offline --targetdir=<output-dir>

Несмотря на название, DC не обязан быть выключен — инструмент копирует локальные файлы с достаточной блокировкой, чтобы копия создавалась безопасно.

Rename-бэкап

Подробности создания — на странице Domain rename tool (вики Samba).

Процедура восстановления домена

  1. Остановить samba на всех старых DC (для rename-бэкапа шаг пропускается).
  2. Выполнить восстановление домена на одном новом DC:
sudo samba-tool domain backup restore --backup-file=<tar-file> --newservername=<DC-name> --targetdir=<new-samba-dir>
  1. Запустить samba на новом DC.
  2. Вернуть старые DC в сеть, присоединив их к восстановленному:
samba-tool domain join <dns-realm> DC --server=<restored-dc>
  1. Для rename-бэкапа — перенастроить сетевое оборудование, чтобы трафик шёл на восстановленный домен.

Шаг samba-tool domain backup restore выполняется один раз — он воссоздаёт домен на одном DC; все старые DC затем переприсоединяются к нему.

Детали восстановления

  • Восстановление похоже на первичный domain provision, но в бэкапе уже есть все добавленные объекты. Новый DC (--newservername) не должен существовать в сети ранее.
  • Целевой каталог (--targetdir) должен быть пустым или не существовать, поэтому восстановить базу в стандартный путь установки (например, /usr/local/samba) нельзя. Рекомендуется восстановить в другой targetdir и запускать samba с опцией -s (или --configfile):
samba -s <targetdir>/etc/smb.conf
  • Восстановленный DC попадает в сайт Default-First-Site-Name (сайт создаётся в восстановленной базе, если его нет); альтернативный сайт задаётся опцией --site.
  • Перед запуском samba проверить восстановленный smb.conf; полезно выполнить samba_dnsupdate (хотя при старте samba он запускается автоматически).
  • Для восстановленного DC можно указать --host-ip.

Рекомендуемая стратегия

Неудобства восстановления — нестандартный каталог и новое имя DC. Простой способ их обойти — временный сервер (или VM) под восстановленный DC:

  1. Восстановить бэкап-файл на временный DC и запустить Samba.
  2. Переприсоединять исходные DC к временному по одному, при join повторно используя прежние имена серверов и стандартный путь установки.
  3. Когда все исходные DC вошли в домен, удалить временный DC командой samba-tool domain demote. Сеть DC окажется той же, что раньше, — но в рабочем состоянии.

Устранение неполадок

  • Проверить учётные данные и адрес сервера для online/rename-бэкапа:
ldbsearch -H ldap://<server> -UAdministrator
  • Увеличить уровень отладки опцией --debug=3.
  • Сообщения Committing SAM database и Cloned domain <domain> означают, что join-подобная часть бэкапа, скорее всего, прошла успешно.
  • Сценарий «совершенно новый DC без выделенного RID» даёт ошибку list index out of range (rIDNextRID); решение — создать временного пользователя (samba-tool user create), чтобы форсировать выделение RID.
  • Offline-бэкап требует установленный пакет lmdb-utils, иначе падает исключение при вызове mdb_copy().
  • Ошибку бэкапа против Windows DC (A file cannot be opened because the share access flags are incompatible.) вызывает блокировка папок DfsrPrivate\Deleted и DfsrPrivate\Installing службой DFSR: перед бэкапом остановите на этом DC службу «DFS Replication» и не забудьте запустить её после.
  • Ошибку восстановления не под root ((1, 'Operation not permitted') либо PANIC (pid ...): Security context active token stack) вызывает восстановление NTACL файлов sysvol, требующее прав root.
  • Имя --newservername, уже существующее в исходном домене, даёт ошибку Entry CN=...,OU=Domain Controllers,... already exists.
  • Если smb.conf из бэкапа содержит настройки interfaces, не совпадающие с IP восстанавливаемого DC, появится ERROR: Please specify a host-ip for the new server — укажите --host-ip при восстановлении (актуально в основном для rename-бэкапов).
  • Если samba не стартует на восстановленном DC с ошибкой invalid ownership on directory .../private/msg.sock — копия была сделана не под root; проще пересоздать бэкап под root, чем чинить chown'ом.

FAQ

  • Каталог bind-dns/ пуст, DNS-записи не сохранены? Бэкап — это бэкап домена; по умолчанию восстановление настраивается на внутренний ('internal') DNS. Для перехода на DLZ_BIND9 используйте samba_upgradedns.
  • Каталог private/tls пуст, сертификаты не в бэкапе? Это бэкап реплицируемых данных домена, а не отдельного DC: информация, специфичная для сервера, не бэкапится и должна быть сгенерирована заново.
  • От какого пользователя запускать бэкапы? Online-бэкап можно выполнять любым AD-пользователем с правами Administrator; offline-бэкапы и восстановление работают с локальной файловой системой и требуют root. Поскольку бэкап-файл содержит все данные AD домена, безопаснее всегда запускать бэкап под root, ограничив круг лиц с доступом к файлу.

Подводные камни

  • Бэкапы восстанавливают домен, а не DC: для одного неисправного DC при живом домене используйте rejoin (samba-tool domain join dc), а не backup/restore.
  • После отката к бэкапу нельзя просто перезапустить samba на старых DC — их нужно именно переприсоединить (rejoin), иначе в сети окажутся два разных домена.
  • Backup/restore-команды появились только в Samba v4.9 (offline — в v4.10); их стоит заранее протестировать, потому что запуск samba на восстановленной online/offline-копии в продакшен-сети небезопасен — восстановленный DC будет вмешиваться в трафик.
  • Нельзя запускать samba на просто распакованном (untar) бэкапе — только через команду restore.
  • Бэкап-инструменты не работают против Windows DC (sysvol блокируется службой DFSR); в смешанном домене бэкапьте Samba DC, в чисто Windows-домене — временно останавливайте службу «DFS Replication» на время бэкапа.
  • Offline-бэкап содержит все секретные данные домена — делиться таким файлом (например, с разработчиками Samba или в списках рассылки) нельзя без осторожности; кроме того, при копировании базы с диска в бэкап может попасть уже существующая порча.
  • Запускайте бэкап как root: online-бэкап от не-root может пройти успешно, но приведёт к проблемам при восстановлении и старте samba.
  • Rename-домен не поддерживается для долгосрочного использования в продакшене — это только временная замена.
  • При ошибке backup/restore в --targetdir могут остаться временные каталоги; перед повторным запуском restore их нужно удалить вручную (они же — подсказка о причине сбоя).
