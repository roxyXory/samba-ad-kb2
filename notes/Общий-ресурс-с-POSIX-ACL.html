Общий ресурс с POSIX ACL

Суть

Страница описывает создание общего файлового ресурса Samba с правами доступа на основе POSIX ACL, которые управляются локально на хосте утилитами UNIX (chmod, chown, setfacl). Такие ресурсы поддерживаются на членах домена, NT4 PDC/BDC и автономных серверах, но не поддерживаются на Samba AD DC — там обязаны использоваться Windows ACL. На Linux доступны только «устаревшие, но всё ещё применяемые» POSIX draft ACLs, поэтому для тонкой настройки прав рекомендуется вариант с Windows ACL.

Ключевое

  • Samba поддерживает ресурсы с файловыми ACL на: членах домена, NT4 PDC и BDC, автономных серверах.
  • На контроллере домена (AD DC) поддержка Windows ACL включена глобально, поэтому ресурсы с POSIX ACL не поддерживаются — нужно использовать Windows ACL.
  • Файловая система должна поддерживать расширенные атрибуты. С ними можно использовать NFS4 ACLs; в Linux NFS4 ACL обычно нет и доступны только POSIX draft ACLs с режимами: None, Read, Write, Full control.
  • Перед созданием ресурса должен быть настроен сам Samba (член домена, NT4 PDC, NT4 BDC или автономный сервер).

Разрешение запуска файлов

По умолчанию пользователи могут запускать файлы (например, *.exe, *.bat) на ресурсе только при установленном POSIX x-бите. Чтобы разрешить выполнение всех файлов независимо от x-бита, задайте в секции [global] или конкретного ресурса smb.conf:

acl allow execute always = yes

Добавление ресурса

Создать каталог:

# mkdir -p /srv/samba/Demo/

Добавить определение ресурса [Demo] в smb.conf:

[Demo]
 path = /srv/samba/Demo/
 read only = no

Это минимально необходимые параметры записываемого ресурса. Перечитать конфигурацию Samba:

# smbcontrol all reload-config

Стандартные права UNIX

Классические права UNIX задают доступ для одного владельца, одной группы и всех остальных (other). Для владельца root и группы Domain Users с чтением/записью и запретом остальным:

# chmod 2770 /srv/samba/Demo/
# chown root:"Domain Users" /srv/samba/Demo/

Бит SGID (2770) автоматически наследует группу каталога всем новым файлам и каталогам вместо основной группы пользователя.

Расширенные ACL (Extended ACLs)

Добавить параметры inherit acls = yes и map acl inherit = yes в конфигурацию ресурса (они влияют на наследование расширенных ACL):

[Demo]
 path = /srv/samba/Demo/
 read only = no
 map acl inherit = yes
 inherit acls = yes

Перезагрузить Samba:

# smbcontrol all reload-config

Проверить, что каталог лежит на файловой системе с поддержкой расширенных ACL (см. File System Support в вики).

Отключить автоматическую выдачу прав основной группе учётных записей:

# setfacl -m group::--- /srv/samba/Demo/
# setfacl -m default:group::--- /srv/samba/Demo/

Задать права на каталог — чтение/запись/выполнение для Domain Admins, чтение/выполнение для Domain Users, запрет остальным:

# setfacl -m group:"SAMDOM\Domain Admins":rwx /srv/samba/Demo/
# setfacl -m group:"SAMDOM\Domain Users":r-x /srv/samba/Demo/
# setfacl -R -m other::--- /srv/samba/Demo/

Эти настройки применяются только к самому каталогу (в Windows — «This folder only»). Чтобы те же права наследовались новым объектам файловой системы:

# setfacl -m default:group:"SAMDOM\Domain Admins":rwx /srv/samba/Demo/
# setfacl -m default:group:"SAMDOM\Domain Users":r-x /srv/samba/Demo/
# setfacl -m default:other::--- /srv/samba/Demo/

После этого режим для субъектов меняется с «This folder only» на «This folder, subfolders, and files».

Соответствие Windows ACL

Заданные POSIX ACL отображаются в следующие Windows ACL:

Субъект Доступ Применяется к Комментарий
SAMDOM\Domain Admins Full control This folder, subfolders, and files
SAMDOM\Domain Users Read & execute This folder, subfolders, and files
Everyone None This folder, subfolders, and files Samba отображает сюда запись UNIX other.
directory_owner (Unix User\directory_owner) * Full control This folder only Samba отображает владельца каталога.
directory_primary_group (Unix User\directory_primary_group) * None This folder only Samba отображает основную группу каталога.
CREATOR OWNER * Full control Subfolders and files only Создатель автоматически наследует эти права на новых объектах.
CREATOR GROUP * None Subfolders and files only Основная группа создателя автоматически наследует эти права на новых объектах.

Права доступа к ресурсу (share permissions)

Доступ на основе пользователей и групп — членам Domain Users доступ разрешён, учётной записи example_user запрещён:

 valid users = +SAMDOM\"Domain Users"
 invalid users = SAMDOM\example_user

Параметр invalid users имеет более высокий приоритет, чем valid users.

Доступ на основе хостов — по имени хоста, IP-адресу или диапазону IP:

 hosts allow = 127.0.0.1 10.99.0.0/24 GoodHost
 hosts deny = BadHost

Параметр hosts deny имеет более высокий приоритет, чем hosts allow.

Подводные камни

  • На Samba AD DC ресурсы с POSIX ACL не поддерживаются: поддержка Windows ACL на DC включена глобально, использовать нужно Windows ACL.
  • Основная группа каталога дополнительно отображается на динамический субъект CREATOR GROUP; при использовании POSIX draft ACL этот субъект добавляется автоматически, и удалить его нельзя.
  • Настроить или убрать из ACL субъекты, отмеченные звёздочкой в таблице соответствия (directory_owner, directory_primary_group, CREATOR OWNER, CREATOR GROUP), можно только при использовании Windows ACL.
  • POSIX draft ACLs в Linux ограничены режимами None, Read, Write, Full control и считаются менее точными, чем Windows/NFS4 ACL; рекомендация вики — запускать файловый сервер Samba на системе с NFS4 ACL, а для тонкой granular-настройки — использовать Windows ACL.
  • Команды setfacl без префикса default: задают права только на сам каталог («This folder only»); для наследования новыми объектами нужны отдельные записи default:.
  • Если нужен запуск всех файлов на ресурсе независимо от x-бита, требуется acl allow execute always = yes — по умолчанию исполняемы только файлы с установленным x-битом.
