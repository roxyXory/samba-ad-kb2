База знаний Samba AD DC

Захват пакетов (Capture Packets)

Суть

Страница описывает, как снимать сетевые дампы (packet capture / trace) для диагностики проблем с Samba — именно их запрашивают разработчики Samba при разборе бага. Приведены команды для tshark, tcpdump и snoop, рекомендации, где снимать дамп (на клиенте или сервере), как фильтровать SMB-трафик по порту 445 и как захватить начало SMB-соединения.

Ключевое

Какой инструмент использовать

  • Лучший способ зависит от доступных инструментов; дополнительные сведения — в документации к каждому инструменту.
  • tshark (CLI-версия Wireshark) — пример захвата на хосте samba3:
tshark -i eth0 -w FILENAME.pcap

Файл FILENAME.pcap затем отправляется разработчикам.

  • tcpdump — доступен практически везде, есть порты под Windows:
tcpdump -i eth0 -w FILENAME.pcap
  • snoop — стандартный инструмент Solaris:
snoop -o FILENAME.pcap -d eth0

Где запускать захват

  • Трассировку нужно запускать на клиенте или на сервере — зависит от проблемы:
    • Аутентификация / проблемная работа с AD → снимать на сервере, чтобы увидеть весь диалог между клиентом и DC.
    • Обмен файлами → дамп можно снимать на любой из сторон.
    • Если трассировка получается слишком большой/нагруженной (например, участвуют машины из других подсетей) → снимать на клиенте, чтобы ограничить трафик только одной машиной.

Общий порядок действий

  1. Запустите инструмент захвата с подходящими параметрами.
  2. Воспроизведите проблему (лучше с минимальным числом посторонних действий).
  3. Остановите захват и приложите полученный файл FILENAME.pcap к отчёту об ошибке.

Фильтрация только SMB-трафика

  • Пример с tcpdump (аналогично для других инструментов):
tcpdump -w FILENAME.pcap port 445
  • Трафик конкретного клиента:
tcpdump -w FILENAME.pcap host IP_ADDRESS_OF_THE_CLIENT
  • Возможности фильтрации: подробности в man tcpdump, man pcap-filter (в старых версиях man tcpdump упоминал man netman).

Кольцевой буфер в tcpdump

Пример длительного захвата в кольцевой буфер:

tcpdump -W 10 -C 50 -w smb.pcap -s 0 port 445
  • -W 10 — максимальное число файлов (-W: "Number of files").
  • -C 50 — размер файла в мегабайтах (-C: "size in MB").

Захват через GUI (Wireshark)

  1. Запустите Wireshark на клиенте или на сервере.
  2. В меню Capture → Options выберите интерфейс и параметры.
  3. Нажмите Start для начала захвата.
  4. Воспроизведите проблему.
  5. Остановите захват (Capture → Stop) и сохраните результат.

Как захватить начало SMB-соединения

  • Для некоторых проблем нужно начало соединения SMB; просто запустить трассировку и ждать не получится — соединение может быть уже установлено.
  • Найти процесс smbd, обслуживающий проблемный клиент (вывод команды smbstatus), и завершить его — перезапускать всю Samba не обязательно.
  • Клиент автоматически переподключится, и начало соединения попадёт в дамп.

Kerberos: расшифровка трафика

  • Основная часть сетевого трафика в домене зашифрована, поэтому в дампе нужен начальный обмен ключами.
  • Заставьте Windows сбросить уже имеющиеся билеты Kerberos, чтобы новый диалог попал в трассировку:
    • Windows XP / Windows Server 2003: утилита kerbtray.exe из Resource Kit (входит в Windows Support Tools); правый клик по значку в трее → Purge tickets.
    • Windows Vista / Windows Server 2008 и новее: страница вики указывает ktutil purge — это дословно воспроизведённая ошибка источника: ktutil — инструмент MIT/Heimdal Kerberos для Unix, а штатная утилита Windows начиная с Vista — klist.exe, поэтому правильная команда — klist purge.

Подводные камни

  • Большая часть трафика зашифрована: дамп бесполезен для анализа содержимого, если в нём нет начального обмена ключами Kerberos — перед захватом сбросьте билеты Kerberos на клиенте (см. выше).
  • Снимаемый трафик может быть слишком велик и нагружать систему: если дамп на сервере получается слишком объёмным (много машин из разных подсетей), снимайте его на клиенте — там трафик ограничен одной машиной.
  • Если проблема требует начала SMB-соединения, недостаточно просто начать запись: завершите процесс smbd, обслуживающий клиента (по данным smbstatus), — клиент переподключится сам; перезапускать Samba целиком не нужно.
