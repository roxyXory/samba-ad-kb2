FAQ — Samba

Суть

Официальная страница FAQ SambaWiki: собрание ответов на вопросы, которые часто задают в списке рассылки Samba. Она охватывает общие вопросы (сроки релизов, обновление, лимиты размеров баз TDB/LDB), работу Samba в роли AD DC (стабильность, схема, Kerberos, репликация, DNS, доверия, групповые политики, LDAP), а также короткие разделы про domain member, NT4-style PDC и standalone-сервер. Для большинства тем даны ссылки на отдельные статьи вики.

Ключевое

Общие вопросы

  • Когда выйдет следующая версия Samba? — сроки описаны на странице Samba Release Planning.
  • Помощь по неподдерживаемой версии — сначала обновитесь до поддерживаемой: минорные версии исправляют ошибки, мажорные добавляют функции. Если дистрибутивный Samba больше не поддерживается проектом — обращайтесь в поддержку дистрибутива.
  • Как обновить Samba — см. Обновление Samba.
  • Максимальный размер базы TDB/LDB — 4 ГБ, так как базы используют 32-битные структуры (проект NTDB, призванный снять лимит, остановлен). Для sam.ldb на AD DC на базе LMDB максимальный размер задаётся параметром --backend-store-size=SIZE команд samba-tool domain provision и samba-tool domain join (по умолчанию 8 ГБ); LMDB — настоящая 64-битная БД, предел ограничен только хранилищем.

Samba как AD DC

  • Стабильность: Samba AD стабильна для production. Поддержка AD DC появилась в Samba 4.0 (декабрь 2012), но часть функций ещё не реализована — например, репликация Sysvol.
  • Какие Windows Server можно ввести в лес как DC: по таблице со страницы — Windows Server 2016: «Not supported»; Windows Server 2012 / 2012 R2: поддерживается в Samba >=4.5; Windows Server 2008 / 2008 R2: поддерживается в Samba >=4.0; Windows Server 2003 / 2003R2 и Windows 2000: «Not tested». Ограничивающий фактор — версия схемы AD (AD Schema Version Support).
  • Пустое «Сетевое окружение»: демон smbd AD DC не поддерживает browsing; сроков появления функции нет.
  • AD DC как файлсервер: не рекомендуется, но возможно; среди ограничений — нельзя получить домашний каталог и shell пользователя из AD, придётся использовать template-строки в smb.conf.
  • Параметр server services задаётся при provisioning; если его нет в [global] — используются значения по умолчанию. Разрешённые ручные изменения: отключение спулера печати (spoolss → -spoolss) и смена DNS-бэкенда.
  • Гостевой доступ на AD DC: map to guest = bad user на AD DC не работает — параметр guest account, на котором он основан, в режиме AD не реализован.
  • Диапазон ID на DC: просто задайте пользователям uidNumber в нужном диапазоне, а группе Domain Users — gidNumber из того же диапазона.
  • Репликация: всё, что хранится внутри AD (пользователи, группы, DNS-записи), реплицируется между DC. DFS-R для репликации Sysvol не поддерживается (обход — см. Sysvol Replication (DFS-R)). Репликация с не-AD LDAP-серверами не поддерживается и не планируется.
  • Внутренний DNS: несколько DNS-forwarder'ов поддерживается с Samba 4.5 (см. Setting up a DNS Forwarder). Трансфер зон BIND на не-AD DNS-серверы не поддерживается — обновления зон идут только через репликацию каталога.
  • Доверия (trusts): страница FAQ устарела (её правка — 20.10.2024). SID filtering действительно не применяется, и стороны должны доверять друг другу полностью, но запрет «нельзя добавлять пользователей и группы доверенного домена в группы домена» снят в 4.9 (foreignSecurityPrincipal создаются автоматически, членства раскрываются на границах доверия). Актуальная картина — Доверительные отношения между доменами.
  • Парольные политики: Samba не применяет ограничения из GPO, а лишь раздаёт GPO клиентам через share Sysvol. Доменные политики задаются командой samba-tool domain passwordsettings.
  • OpenLDAP как бэкенд AD DC: не поддерживается, активной работы нет (проблемы: метаданные DRS-репликации и dirsync, манипуляция схемой, транзакции, ACL). Команда Samba не рассматривает это как направление разработки.
  • Анонимные LDAP-поиски: Samba учитывает флаг dSHeuristics (см. http://support.microsoft.com/kb/326690), но включать анонимный доступ не рекомендуется — настройте LDAP-аутентификацию или Kerberos в клиенте.

Ошибки и их устранение

  • Warning: No NC replicated for Connection! в выводе samba-tool drs showrepl — Samba неверно выставляет флаги при регистрации DC на репликацию; предупреждение безвредно и игнорируется.
  • UpdateRefs failed with WERR_DS_DRA_BAD_NC/NT code 0xc00020f8 ... при первом запуске Samba DC в существующем лесу Windows AD — ошибку пишет KCC, пока Windows DC не установит соединения с Samba DC. Исправление — на Windows DC:
C:\> repadmin /kcc

либо на Samba DC:

# samba-tool drs kcc -Uadministrator Windows_DC.samdom.example.com
  • Сообщение GPMC «The permissions for this GPO in the SYSVOL folder are inconsistent with those in Active Directory» — шаги устранения на странице Sysvolreset.
  • User Administrator in your existing directory has SID ..., expected it to be ...-500 при классическом (NT4) апгрейде: RID администратора домена не равен 500. Исправление — удалить учётку (будет пересоздана при апгрейде) или вручную сменить RID на 500, перепроверив ACL и приложения, ссылающиеся на этого администратора.

Samba как domain member

  • samba-tool domain provision для члена домена не используется: из ролей, которые предлагает samba-tool domain provision --help, поддерживается только DC. Если создали другую роль — удалите все базы Samba и сгенерированный smb.conf и вводите машину командой net (см. Samba как член домена).
  • getent passwd/getent group не показывают пользователей при бэкенде idmap_ad: winbind по умолчанию больше не перечисляет пользователей и группы — запрашивайте явно (getent passwd auser, компьютеры — getent passwd SAMDOM\hostname$). Для просмотра всех записей (только для тестирования) добавьте в smb.conf:
   winbind enumerate users = yes
   winbind enumerate groups = yes

Если записей всё ещё нет, проверьте: у пользователей uidNumber внутри диапазона из smb.conf (пример со страницы: idmap config DOMAIN : range = 10000-999999), у группы Domain Users есть gidNumber из того же диапазона (иначе все пользователи игнорируются), у компьютеров при необходимости свой uidNumber; корректность libnss_winbind; строки passwd и group с winbind в /etc/nsswitch.conf.

Samba как NT4 PDC и standalone

  • Мигрировать NT4-домен в AD не обязательно: «Samba 4» — это не «только AD»; классическая (NT4-style) поддержка PDC сохраняется во всех новых версиях, обновляйте Samba 3.x PDC как раньше.
  • SMB2/SMB3 не имеют сетевого просмотра: browsing заменён на Network Discovery (WSD/LLMNR), который Samba пока не поддерживает. Ресурсы доступны напрямую по \\name или \\ip.address. Если на Windows включён SMB1 — проверьте NetBIOS over TCP/IP и что запущен nmbd.
  • Локальное подключение пользователя: пользователь должен существовать в /etc/passwd и быть добавлен в локальный smbpasswd:
# smbpasswd -a username

Для гостевого подключения нужен map to guest = bad user в [global], а гостевой пользователь (по умолчанию guest user = nobody) должен существовать в системном файле паролей.

Подводные камни

  • Удаление или изменение опций server services может привести к некорректной работе AD DC — вручную меняют только -spoolss и DNS-бэкенд.
  • Не добавляйте в smb.conf AD DC строки idmap_ad из конфигурации domain member: они не дадут эффекта и могут привести к проблемам.
  • Windows Server 2016 как дополнительный DC в лесу с Samba DC не поддерживается (по таблице FAQ).
  • Репликация Sysvol (DFS-R) не поддерживается — при нескольких DC Sysvol придётся синхронизировать обходным путём.
  • Доверия (trusts): FAQ называет их экспериментальными и запрещает добавлять пользователей/группы доверенного домена в группы своего домена — второе неверно с 4.9 (про SID filtering — верно). См. Доверительные отношения между доменами.
  • Не используйте TLD .local для зоны AD DNS — не рекомендуется (см. Using an Invalid TLD).
  • AD DC как файлсервер не рекомендуется; гостевой доступ на AD DC не реализован (параметр guest account отсутствует в режиме AD).
  • Строки winbind enumerate users/groups = yes добавляйте только для тестирования.
  • Включение анонимного доступа к AD через LDAP создаёт проблемы безопасности и не рекомендуется.
  • Изменение RID администратора (на 500) делает его другим аккаунтом (идентификация по objectSID) — придётся переписать приложения и ACL, где он указан.
