Понижение роли Samba AD DC (Demoting a Samba AD DC)

Суть

Чтобы навсегда убрать контроллер домена из Active Directory, его нельзя просто удалить — DC нужно понизить (demote). Страница описывает две процедуры: понижение работающего (online) DC командой samba-tool domain demote -Uadministrator и удаление недоступного («мёртвого») DC без репликации командой samba-tool domain demote --remove-other-dead-server=DC2, выполняемой с оставшегося рабочего DC. Если DC не понижен корректно, AD становится нестабильным.

Ключевое

Почему нельзя просто удалить DC

Удаление обычного члена домена сводится к удалению записи машинной учётной записи, но для DC требуется именно демоция. При некорректном удалении DC возможно:

  • сбои репликации (replication failures);
  • оставшиеся DC замедляются из-за таймаутов и неудачных попыток репликации;
  • входы на членах домена заканчиваются ошибкой или выполняются дольше.

Понижение работающего (online) DC

Если понижаемый DC работает нормально:

  1. Войти локально на понижаемый DC.
  2. Убедиться, что служба samba запущена.
  3. Проверить, не владеет ли DC ролями FSMO. Если владеет — передать их другому DC (Transferring an FSMO Role).
  4. Опционально показать objectGUID DC (пример для хоста DC2):
# ldbsearch -H /usr/local/samba/private/sam.ldb '(invocationId=*)' --cross-ncs objectguid | grep -A1 DC2
dn: CN=NTDS Settings,CN=DC2,CN=Servers,CN=Default-First-Site-Name,CN=Sites,CN=Configuration,DC=samdom,DC=example,DC=com
objectGUID: c14a774f-9732-4ec2-b9fa-2156c95c4e48

Имя хоста, IP-адрес и objectGUID нужны, чтобы после демоции проверить удаление всех DNS-записей.

  1. Понизить DC:
# samba-tool domain demote -Uadministrator

Password for [SAMDOM\administrator]:
Deactivating inbound replication
Asking partner server DC1.samdom.example.com to synchronize from us
Changing userControl and container
Removing Sysvol reference: CN=DC2,CN=Enterprise,CN=Microsoft System Volumes,CN=System,CN=Configuration,DC=samdom,DC=example,DC=com
Removing Sysvol reference: CN=DC2,CN=samdom.example.com,CN=Microsoft System Volumes,CN=System,CN=Configuration,DC=samdom,DC=example,DC=com
Removing Sysvol reference: CN=DC2,CN=Domain System Volumes (SYSVOL share),CN=File Replication Service,CN=System,DC=samdom,DC=example,DC=com
Removing Sysvol reference: CN=DC2,CN=Topology,CN=Domain System Volume,CN=DFSR-GlobalSettings,CN=System,DC=samdom,DC=example,DC=com
Demote successful
  1. Остановить службу samba.
  2. Если DC использовал DNS-бэкенд BIND9_DLZ для зон Active Directory: остановить службу Bind9 и убедиться, что ни один член домена не использует этот хост для разрешения AD DNS-зон.

Понижение недоступного (offline) DC

При аппаратных сбоях и подобных ситуациях нужно убрать из домена недоступный DC. Демоция выполняется с оставшегося рабочего Samba DC.

  1. Войти на работающий Samba DC в лесу AD.
  2. Убедиться, что установлен Samba 4.4 или новее:
# samba --version
  1. Проверить, что понижаемый удалённый DC не владеет ролями FSMO. Если владеет — захватить (seize) их на локальный DC.
  2. Убедиться, что понижаемый DC выключен.
  3. Опционально показать objectGUID DC (команда та же, что и для online-случая).
  4. Понизить удалённый DC (пример для DC2):
# samba-tool domain demote --remove-other-dead-server=DC2

Removing RID Set: CN=RID Set,CN=DC2,OU=Domain Controllers,DC=samdom,DC=example,DC=com
Removing computer account: CN=DC2,OU=Domain Controllers,DC=samdom,DC=example,DC=com (and any child objects)
Removing Samba-specific DNS service account: CN=dns-DC2,CN=Users,DC=samdom,DC=example,DC=com
updating samdom.example.com keeping 3 values, removing 1 values
...
updating DC=c14a774f-9732-4ec2-b9fa-2156c95c4e48,DC=_msdcs.samdom.example.com,CN=MicrosoftDNS,DC=ForestDnsZones,DC=samdom,DC=example,DC=com keeping 0 values, removing 1 values
...
Removing Sysvol reference: CN=DC2,CN=Topology,CN=Domain System Volume,CN=DFSR-GlobalSettings,CN=System,DC=samdom,DC=example,DC=com

(в выводе многоточием пропущены однотипные строки updating DC=... — утилита удаляет записи DC из зон DomainDnsZones и ForestDnsZones)

  1. Если пониженный DC обслуживал DNS для зон AD — убедиться, что члены домена и DC больше не используют этот хост для разрешения AD DNS-зон.

Проверка понижения (Verifying the Demotion)

Ручная проверка, что DC успешно понижен (и ручная зачистка остатков, если официальный процесс не сработал):

  1. Войти на член домена Windows под учётной записью из группы Domain Admins (например, администратор домена AD).
  2. Установить Remote Server Administration Tools (RSAT).
  3. В приложении Active Directory Users and Computers перейти в контейнер Domain Controllers и убедиться, что пониженный DC удалён. Если запись осталась — удалить вручную: правый клик на записи DC → Delete → Yes → выбрать «Delete this Domain Controller anyway. It is permanently offline and can no longer be removed using the removal wizard.» → OK; если DC является сервером глобального каталога — подтвердить Yes.
  4. В Active Directory Sites and Services убедиться, что пониженный DC не значится ни в одной записи сайта AD; если значится — правый клик → Delete → Yes.
  5. В приложении DNS убедиться, что имя хоста, IP-адрес и objectGUID DC больше не встречаются ни в одной DNS-записи ни в одной зоне AD DNS; лишние записи удалить вручную (правый клик → Delete → Yes).

Подводные камни

  • Процедуру --remove-other-dead-server запускать только если DC больше не подключён к AD и его нельзя понизить обычным способом. Иначе изменения (например, смены паролей) не будут реплицированы на другой DC и будут потеряны; список расхождений можно получить командой samba-tool ldapcmp.
  • Нельзя понизить offline-удалённый DC с DC, работающего на Samba 4.4 или старее — сначала обновитесь до Samba 4.4.0 или новее.
  • Никогда не подключайте удалённо пониженный (remotely demoted) DC обратно к сети — AD может стать неконсистентным.
  • Шаги из раздела проверки не заменяют официальные процедуры демоции: они нужны только для проверки и ручного удаления остаточных записей, если официальный процесс понижения завершился неудачей.
  • Перед понижением разберитесь с FSMO: на работающем DC роли передают (transfer), у выключенного — захватывают (seize) на другой DC.

Связанные заметки

  • Передача и захват FSMO ролей
  • Присоединение второго DC к домену
  • Управление службой AD DC
  • Диагностика AD DC
