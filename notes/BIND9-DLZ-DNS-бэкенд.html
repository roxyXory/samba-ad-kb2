BIND9_DLZ DNS-бэкенд

Суть

Страница описывает DNS-бэкенд BIND9_DLZ: плагин BIND9, который на запросы зон, зарегистрированных в Active Directory, читает базу Samba AD напрямую. Бэкенд рекомендуется для сложных DNS-конфигураций, которые внутренний DNS-сервер Samba не поддерживает (Внутренний DNS бэкенд — ограничения: нет кэширования, рекурсии, передачи зон). Зоны хранятся и реплицируются в каталоге AD. Конфигурация модуля — /usr/local/samba/bind-dns/named.conf (до Samba 4.7 — /usr/local/samba/private/named.conf); файл создаётся при provision/join/upgrade с --dns-backend=BIND9_DLZ или при запуске samba_upgradedns.

Ключевое

Требования к BIND

  • Поддерживаются только версии BIND, активно сопровождаемые ISC. Модули поставляются под версии: dlz_bind9.so — 9.8.x, dlz_bind9_9.so — 9.9.x, dlz_bind9_10.so — 9.10.x, dlz_bind9_11.so — 9.11.x, dlz_bind9_12.so — 9.12.x, dlz_bind9_14.so — 9.14.x, dlz_bind9_16.so — 9.16.x (файлы в /usr/local/samba/lib/bind9/).
  • Версия BIND в системе: named -v. Модули 9.8/9.9 поддерживаются с Samba 4.0, 9.10 — с 4.2, 9.11 — с 4.5.2, 9.12/9.14/9.16 — с 4.12.10/4.13.2.
  • BIND обязан работать на том же хосте, что и Samba AD DC, и не должен запускаться в chroot-окружении.

Настройка

  1. Подключить конфигурацию Samba в named.conf BIND:

    include "/usr/local/samba/bind-dns/named.conf";

  2. В /usr/local/samba/bind-dns/named.conf раскомментировать модуль под свою версию BIND, например для 9.11:

    database "dlopen /usr/local/samba/lib/bind9/dlz_bind9_11.so";

  3. В секцию options {} named.conf добавить (динамические обновления требуют BIND ≥ 9.8):

    tkey-gssapi-keytab "/usr/local/samba/private/dns.keytab";
minimal-responses yes;

  4. Проверить, что /etc/krb5.conf читаем пользователем BIND, и что есть утилита nsupdate (which nsupdate).

  5. Проверить конфигурацию named-checkconf и запустить BIND.

  6. Для BIND9_DLZ на Samba до 4.4.0 права на dns.keytab исправить: chmod 640 /usr/local/samba/private/dns.keytab и chown root:named ...; при обновлении с версий до 4.8.0 — права на каталог bind-dns (chmod 770, chown root:named).

Смена/перенастройка бэкенда (заодно пересоздаёт учётки dns-* в AD и чинит проблемы keytab):

# samba_upgradedns --dns-backend=BIND9_DLZ

после чего перезапустить BIND.

Отладка и проверка

  • Логирование модуля: дописать к database "dlopen ..." аргумент -d 3 и запустить named -u named -f -g 2>&1 | tee /tmp/named.log.
  • Динамические обновления проверяются отдельной страницей «Testing Dynamic DNS Updates»; ошибки вида NOTAUTH видны в выводе samba_dnsupdate --verbose.
  • Проверка жёстких ссылок баз DNS: inode файлов в /usr/local/samba/private/sam.ldb.d/ и /usr/local/samba/private/dns/sam.ldb.d/ должны совпадать (ls -lai).

Подводные камни

  • Проблема блокировок (lockup): каждый вызов плагина сериализуется мьютексом, доступ к базе — fcntl-блокировкой; заблокированная база останавливает обработку любых запросов BIND, включая внешние (не-samba). Поэтому для высоконагруженных сред BIND9_DLZ не рекомендуется как основной DNS: лучше внешний сервер, форвардящий в узел только запросы зон AD. В небольших средах проблема маловероятна; увеличение worker-потоков (-n) не помогает.
  • BIND нельзя reload — только restart: на Samba AD DC rndc reload/reload логирует «Ignoring duplicate zone»; проверить logrotate и переопределить юнит (systemctl edit bind9.service, очистить/заменить ExecReload).
  • Порядок запуска служб: Samba должна стартовать после BIND — в override юнита After=network.target network-online.target bind9.service.
  • systemd-изоляция: при ошибке «Read-only file system» добавить /var/lib/samba/bind-dns в ReadWritePaths= юнита.
  • WINS-записи из Windows AD вызывают «unhandled record type 65281»: отключить WINS-resolving в DNS Windows DC, перезапустить Samba, повторить samba_upgradedns --dns-backend=BIND9_DLZ, перезапустить BIND.
  • Каталог bind-dns существует только при provision/join с --dns-backend=BIND9_DLZ или после samba_upgradedns.
  • Пакетные сборки могут ставить слишком строгие права на родительские каталоги dns.keytab — BIND не сможет его прочитать.
  • Бэкенд выбирается при provision/join (--dns-backend=BIND9_DLZ); BIND9_FLATFILE не поддерживается и будет удалён (см. Установка Samba AD DC).
