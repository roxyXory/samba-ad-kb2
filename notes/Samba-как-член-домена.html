База знаний Samba AD DC

Samba как член домена

Суть

Член домена (domain member) — это Linux-машина с Samba, введённая в домен и не предоставляющая доменных служб (в отличие от DC). На ней можно использовать доменных пользователей и группы в локальных ACL, поднимать файловые и print-сервисы и через PAM давать доменным пользователям локальный вход. Страница описывает подготовку хоста (DNS, Kerberos, время, имя хоста), выбор idmap-бэкенда, ввод в домен, настройку NSS и запуск служб.

Ключевое

Требования и общая подготовка

  • Все члены AD-домена должны быть в одном DNS-домене, а Realm — это DNS-домен в верхнем регистре: DNS-домен samdom.example.com, Realm SAMDOM.EXAMPLE.COM.
  • Для Samba ранее 4.15.0 никогда не использовать samba-tool domain provision для создания Unix-члена домена — только процедура с этой страницы.
  • Убедиться, что не запущены процессы Samba:
# ps ax | egrep "samba|smbd|nmbd|winbindd"
  • Если на хосте ранее была установка Samba: сделать резервную копию smb.conf (путь показывает # smbd -b | grep "CONFIGFILE") и удалить все файлы баз Samba (*.tdb, *.ldb; папки показывает # smbd -b | egrep "LOCKDIR|STATEDIR|CACHEDIR|PRIVATE_DIR").

Настройка DNS (/etc/resolv.conf)

nameserver 10.99.0.1
search samdom.example.com

NetworkManager может перезаписать этот файл — постоянную настройку делают через nmcli или графический интерфейс (видимый /etc/resolv.conf с nameserver 127.0.0.53 при этом работает корректно).

Проверки разрешения имён:

# nslookup DC1.samdom.example.com
# host DC1.samdom.example.com        # прямой lookahead
# nslookup 10.99.0.1                 # обратный lookahead
# host -t SRV _ldap._tcp.samdom.example.com   # SRV-записи

Типичные ошибки: ** server can't find DC1.samdom.example.com: NXDOMAIN и ;; connection timed out; no servers could be reached (используемый DNS-сервер недоступен).

Настройка Kerberos (/etc/krb5.conf)

[libdefaults]
	default_realm = SAMDOM.EXAMPLE.COM
	dns_lookup_realm = false
	dns_lookup_kdc = true

Команда Samba рекомендует не задавать других параметров в /etc/krb5.conf. Если файл содержит строку include — она не будет работать, её нужно удалить. На некоторых дистрибутивах с MIT Kerberos для корректного маппинга ID нужно добавить:

[plugins]
       localauth = {
             module = winbind:/usr/lib64/samba/krb5/winbind_krb5_localauth.so
             enable_only = winbind
       }

Эти же настройки могут понадобиться в /etc/security/pam_winbind.conf:

[global]
      krb5_auth = yes
      krb5_ccache_type = FILE

На дистрибутивах с crypto-policies:

update-crypto-policies --set DEFAULT:AD-SUPPORT

Время и имя хоста

  • Kerberos требует синхронизированного времени на всех членах домена — рекомендуется NTP-клиент (см. Синхронизация времени).
  • Проверить разрешение имени хоста: # getent hosts M1 — имя и FQDN не должны разрешаться в 127.0.0.1 или любой другой IP, кроме адреса LAN-интерфейса. При необходимости прописать в /etc/hosts:
127.0.0.1      localhost
10.99.0.5      M1.samdom.example.com    M1

Алиасы имени машины добавляются в конец строки с IP-адресом машины, а не в строку 127.0.0.1. Для ввода в NT4-домен подготовка не требуется.

Выбор idmap-бэкенда

Три основных бэкенда: ad, autorid, rid.

  • Нужны одинаковые ID везде и/или разные shell и домашние каталоги — бэкенд ad + RFC2307-атрибуты в AD (uidNumber, gidNumber и т.д.). Атрибуты не добавляются автоматически, их нужно задавать вручную. ID из диапазона 3000000, которые видно на DC, — НЕ RFC2307-атрибуты и на Unix-членах использоваться не могут.
  • Нужны только Unix ID — бэкенды rid или autorid: ID вычисляются из Windows RID; при одинаковом [global] в smb.conf на всех членах ID совпадают; RFC2307-атрибуты игнорируются; через template shell и template homedir можно задать shell и домашний каталог (по умолчанию /bin/false и /home/%D/%U).
  • Бэкенд hash — в таблице страницы помечен «Do not use», не использовать.

Локальные системные пользователи занимают диапазон 0-999, локальные Unix-пользователи обычно с 1000. Рекомендуемые непересекающиеся диапазоны idmap config:

Домен Диапазон
* (default domain) 3000-7999
DOMAIN 10000-999999
TRUSTED (доверенные) 1000000-9999999

Диапазоны * и DOMAIN не должны начинаться с 999 или меньше и не должны пересекаться; вариант «* на всё» годится только для бэкенда autorid. Для каждого доверенного домена добавляется отдельная конфигурация ID mapping (кроме autorid, где это опционально).

Полный пример smb.conf на этой странице не приводится — базовый файл собирается по вики-странице выбранного бэкенда (idmap config rid / idmap config autorid / idmap config ad); примеры конфигурации всех трёх бэкендов, требования к диапазонам и включение RFC2307-атрибутов в AD — в Idmap бэкенды и RFC2307.

Маппинг Administrator → root

  • В раздел [global] smb.conf:
username map = /usr/local/samba/etc/user.map
  • Создать файл /usr/local/samba/etc/user.map:
!root = SAMDOM\Administrator

Делать это можно только на Unix-члене домена; после настройки не входить на член домена под Administrator. Если имя аккаунта Administrator меняли — в user.map используется новое имя.

Ввод в домен

# net ads join -U administrator
Enter administrator's password: Passw0rd
Using short domain name -- SAMDOM
Joined 'M1' to dns domain 'samdom.example.com'

Для NT4-домена:

# net rpc join -U administrator

Только для Samba ≥ 4.15.0:

# samba-tool domain join samdom.example.com MEMBER -U administrator

При net ads join прямая DNS-запись компьютера создаётся автоматически, но при фиксированном IP-адресе обратную PTR-запись нужно создать самостоятельно. При проблемах ввода — Диагностика AD DC и страница Troubleshooting Samba Domain Members.

Name Service Switch (/etc/nsswitch.conf)

passwd: files winbind
group:  files winbind
  • Запись files остаётся первой в обеих базах.
  • Не добавлять winbind в базу shadow — это может привести к отказу wbinfo.
  • Если есть строка с директивой initgroups, добавить [success=continue] winbind; если строки нет — не создавать её.
  • При самостоятельной сборке Samba нужны симлинки libnss_winbind в библиотечный путь ОС (см. libnss_winbind Links); у пакетной установки ссылка обычно создаётся автоматически.

Запуск служб

Полноценный Unix-член домена требует служб: smbd, nmbd (не нужна без Network Browsing), winbindd. Службу samba на члене домена запускать нельзя — она нужна только на DC. Samba не поставляет init-скрипты/systemd-юниты: при пакетной установке используется скрипт из пакета, при сборке из исходников — документация дистрибутива. Начиная с Samba 4.11.0 минимальный протокол — SMBv2; SMBv1 не работает, если вручную не задать client min protocol = NT1 и server min protocol = NT1 (Samba больше не рекомендует SMBv1).

Проверка winbindd

# wbinfo --ping-dc
checking the NETLOGON for domain[SAMDOM] dc connection to "DC.SAMDOM.EXAMPLE.COM" succeeded

Если команда не проходит — проверить, что winbindd запущен и smb.conf настроен верно. Поиск доменных учёток через NSS:

# getent passwd SAMDOM\\demo01
SAMDOM\demo01:*:10000:10000:demo01:/home/demo01:/bin/bash

# getent group "SAMDOM\\Domain Users"
SAMDOM\domain users:x:10000:

Назначение владельца файла доменным пользователем и группой:

# chown "SAMDOM\\demo01:SAMDOM\\domain users" file.txt

Подводные камни

  • Samba < 4.15.0: samba-tool domain provision нельзя использовать для создания Unix-члена домена — не сработает.
  • Никогда не добавлять строки idmap config в smb.conf на Samba AD DC — ID mapping back end на DC не поддерживается.
  • Не маппить Administrator → root на DC: он уже замаплен в idmap.ldb, такой маппинг сломает AD. На Unix-члене после маппинга не входить под Administrator. С бэкендом ad никогда не задавать uidNumber аккаунту Administrator — значение перекроет локальный UID 0 (root) и маппинг не сработает.
  • Не дублировать имена: не использовать в локальном /etc/passwd те же имена пользователей, что в домене; не использовать локальные Unix-имена при смене владельца файлов на доменных шарах.
  • NetworkManager может перезаписать ручные правки /etc/resolv.conf.
  • Обратная зона в Samba AD не создаётся автоматически; при фиксированном IP PTR-запись создаётся вручную.
  • Имя хоста и FQDN не должны разрешаться в 127.0.0.1.
  • Если в /etc/krb5.conf есть строка include — она не работает, её нужно удалить.
  • Диапазоны idmap config не должны пересекаться и не должны начинаться с 999 или меньше.
  • Не запускать службу samba на члене домена — только smbd, nmbd, winbindd.
  • Не добавлять winbind в базу shadow в /etc/nsswitch.conf — может сломать wbinfo.

Связанные заметки

  • Установка Samba AD DC — развёртывание контроллера домена, к которому затем вводятся члены
  • Общий ресурс с Windows ACL — файловые шары на члене домена
  • Синхронизация времени — обязательная синхронизация времени для Kerberos
  • Внутренний DNS бэкенд — DNS-сервер AD, на который указывает resolv.conf члена домена
