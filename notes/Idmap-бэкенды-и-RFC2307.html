База знаний Samba AD DC

Idmap-бэкенды члена домена и RFC2307

Суть

Сводка по настройке ID-маппинга (idmap config) на Unix domain member — того, чего не хватает для завершения ввода в домен по Samba как член домена и для шар с Windows ACL (привилегия и права требуют, чтобы пользователь/группа были «известны Unix», то есть имели uidNumber/gidNumber — см. Общий ресурс с Windows ACL). Три основных бэкенда:

  • ad — ID и (опционально) shell/home читаются из RFC2307-атрибутов AD (uidNumber, gidNumber, loginShell, unixHomeDirectory); одноимённые страницы вики — idmap config ad, Setting up RFC2307 in AD;
  • rid — ID вычисляются алгоритмически из Windows RID;
  • autorid — как rid, но ID раздаются всем доменам автоматически, без per-domain конфигов.

Ключевое

Общие правила для всех бэкендов

  • На Samba AD DC строки idmap config не добавляют — бэкенды ID-маппинга в smb.conf контроллера не поддерживаются и ломают доступ к шарам (на DC своё хранилище idmap.ldb).
  • Обязательна конфигурация * (default domain) на read-write бэкенде (обычно tdb); ad/rid — read-only и дефолтными быть не могут (autorid может обслуживать *).
  • Диапазоны непрерывны, достаточно велики (с запасом на будущие объекты — расширять можно только верхнюю границу) и не пересекаются между * и доменами; диапазоны не должны начинаться с 999 или меньше (конфликт с локальными системными пользователями 0–999 и обычными Unix-пользователями от 1000).
  • Все uidNumber/gidNumber в AD должны попадать в диапазон своего домена в smb.conf.
  • Для каждого доверенного домена нужна отдельная конфигурация (кроме autorid).
  • После правки: smbcontrol all reload-config.

Пример для бэкенда ad (Samba 4.6.0+)

idmap config * : backend = tdb
idmap config * : range = 3000-7999
idmap config SAMDOM:backend = ad
idmap config SAMDOM:schema_mode = rfc2307
idmap config SAMDOM:range = 10000-999999
idmap config SAMDOM:unix_nss_info = yes
idmap config SAMDOM:unix_primary_group = yes
  • Минимально нужны uidNumber пользователям и gidNumber группам; объекты без атрибутов в Unix не маппятся вовсе.
  • unix_nss_info = yes подтягивает из AD также loginShell и unixHomeDirectory (до 4.6.0 вместо этого winbind nss info = rfc2307, а shell/home задают шаблонами template shell, template homedir).
  • Обязателен gidNumber у группы Domain Users (она первичная у всех пользователей), иначе winbind не смапит учётки.
  • До 3000000 (диапазон xidNumber на DC) атрибуты RFC2307 не имеют отношения — на членах домена они не используются.

Бэкенд rid

idmap config * : backend = tdb
idmap config * : range = 3000-7999
idmap config SAMDOM : backend = rid
idmap config SAMDOM : range = 10000-999999
template shell = /bin/bash
template homedir = /home/%U
  • ID вычисляются из RID (формула — в man idmap_rid(8)); RFC2307-атрибуты игнорируются.
  • Одинаковый [global] на всех членах даёт одинаковые ID; при смене диапазона ID изменятся.
  • Исключить отдельных пользователей/группы нельзя; shell и home одинаковы для всех (задаются шаблонами).

Бэкенд autorid

idmap config * : backend = autorid
idmap config * : range = 10000-24999999
idmap config * : rangesize = 200000
template shell = /bin/bash
template homedir = /home/%U
  • Раздаёт ID всем доменам автоматически; per-domain конфиги не нужны (доверенные домены покрываются сами).
  • ID не совпадают между разными членами домена — в отличие от rid с одинаковым конфигом.
  • Нельзя winbind use default domain = yes — логин в формате DOMAIN\username.

RFC2307-атрибуты в AD (Setting up RFC2307 in AD)

  • Польза: центральное администрирование ID в AD, одинаковые ID на членах с бэкендом ad, индивидуальные shell/home, управление из ADUC — без локальных баз маппинга, которые могут повреждаться и терять владельцев файлов.
  • Включение: в новом домене — --use-rfc2307 при provision (устанавливает NIS-расширения, недостатков нет). В существующем — проверить наличие дерева ypServ30:
ldbsearch -H /usr/local/samba/private/sam.ldb -s base -b \
CN=ypservers,CN=ypServ30,CN=RpcServices,CN=System,DC=samdom,DC=example,DC=com cn

Одна запись — расширения уже установлены. Иначе: найти DC с ролью Schema Master (samba-tool fsmo show | grep SchemaMasterRole), остановить Samba, поправить в ypServ30.ldif плейсхолдеры ${DOMAINDN}, ${NETBIOSNAME}, ${NISDOMAIN} и импортировать:

ldbmodify -H /usr/local/samba/private/sam.ldb /tmp/ypServ30.ldif --option="dsdb:schema update allowed"=true

затем запустить Samba — схема реплицируется на все DC. Перед обновлением схемы — проверить, что есть рабочий бэкап домена.

  • Атрибуты задают через вкладку Unix Attributes в ADUC (нужны именно NIS-расширения); атрибуты не добавляются автоматически.

Подводные камни

  • Никогда не давать gidNumber группе Domain Admins — ломает sysvol (sysvolcheck); для Unix-администрирования создают отдельную группу с gidNumber (см. Общий ресурс с Windows ACL).
  • Не менять primaryGroupID пользователей — Windows рассчитывает на членство всех в Domain Users; другая первичная Unix-группа — через unix_primary_group = yes (4.6.0+).
  • Следить за уникальностью ID вручную: переиспользованный ID удалённой учётки даёт новому владельцу доступ к старым файлам; ADUC отслеживает ID пользователей/групп, но не компьютеров (машинным учёткам uidNumber задают вручную, если они должны видеть шары).
  • idNumber-диапазоны не должны пересекаться и не должны начинаться с ≤999.
  • hash-бэкенд помечен «Do not use».
  • Строки idmap config из конфига члена домена на DC копировать нельзя.
