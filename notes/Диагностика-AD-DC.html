Диагностика Samba AD DC

Суть

Страница — отправная точка для поиска и устранения проблем контроллера домена (DC) Samba: проверка запущенных процессов, разбор типовых ошибок DNS при присоединении DC к домену и ссылки на специализированные страницы диагностики (уровень логирования, DNS-бэкенды, SELinux, проблемы после обновления). Отдельно разобраны две ошибки join — WERR_DNS_ERROR_RCODE_NAME_ERROR (bug 13298, Samba 4.7+) и WERR_DNS_ERROR_ZONE_DOES_NOT_EXIST — с пошаговым обходом через репликацию DNS-партиций.

Общие вопросы

  • Настройка уровня логирования Samba — см. отдельную страницу Setting the Samba Log Level.
  • Ошибка «The net Command Fails to Connect to the 127.0.0.1 IP Address» — описана на странице Troubleshooting Samba Domain Members (см. Samba как член домена).
  • Ошибки join на Rocky Linux 8: сообщалось, что самособранная Samba на Rocky Linux (по-видимому, то же относится к RHEL, Alma Linux и т.п.) не может присоединить другой DC. Причина — включённый режим FIPS: нужно выключить его на всех RHEL-based DC, перезагрузить их все и повторить join.

  • Контроллеры домена Samba не поддерживают сетевой просмотр (network browsing), поэтому процессов nmbd в выводе нет.

Проблемы DNS при join DC

DNS rcode name error. Есть баг добавления DNS-записей при присоединении к домену — bug 13298; он должен затрагивать только Samba v4.7 и новее. Join падает после «Adding DNS A record … for IPv4 IP: …» и «Join failed - cleaning up» (с удалением созданных объектов: RID Set, учётной записи DC, dns-учётки, NTDS Settings, записи сервера) с финальной ошибкой:

ERROR(runtime): uncaught exception - (9003, 'WERR_DNS_ERROR_RCODE_NAME_ERROR')
  File "/usr/lib64/python2.7/site-packages/samba/join.py", line 1178, in join_add_dns_records
    dns_partition=domaindns_zone_dn)
  File "/usr/lib64/python2.7/site-packages/samba/samdb.py", line 1069, in dns_lookup
    dns_partition=dns_partition)

DNS zone does not exist. Аналогичный трейс заканчивается так:

ERROR(runtime): uncaught exception - (9601, 'WERR_DNS_ERROR_ZONE_DOES_NOT_EXIST')

Ошибки name/zone могут возникать по разным причинам; name-ошибка встречается заметно чаще (особенно против Windows). Если домен мигрирован с Windows 2000 или 2003 (включая R2-варианты и, возможно, 2008 non-R2), DNS-зоны могли быть мигрированы некорректно: устаревшие расположения DNS-зон в Samba не поддерживаются — поддерживаются только полностью реплицируемые AD DNS-зоны (ForestDnsZones, DomainDnsZones). Если ошибка указывает, что зоны может не существовать, возможно, стандартная AD-зона вообще не создана (несмотря на то, что записи из этого расположения как будто отдаются). Один из способов гарантировать, что DNS-записи находятся только в современных расположениях, — полный реимпорт DNS-базы через PowerShell.

Если ошибки — не следствие проблем миграции, а проблема работающего сервера, доступен обход:

Выполнение шагов не по порядку может привести к проблемам репликации из-за того, что некоторые объекты будут созданы дважды.

  1. При samba-tool domain join указать опцию командной строки --dns-backend=NONE.
  2. Выполнить samba-tool drs replicate партиций DC=ForestDnsZones и DC=DomainDnsZones с опциями --local --full-sync.
  3. Запустить samba_upgradedns против базы нового DC.
  4. Выполнить samba-tool dbcheck с опцией --cross-ncs, чтобы исправить расхождения при создании партиций.

Опционально после этого можно запустить samba-tool ldapcmp, чтобы убедиться в согласованности баз (учитывая, что атрибуты msDs-masteredBy, msDS-NC-Replica-Locations, msDS-hasMasterNCs были изменены).

Другие проблемы совместимости с Windows (для доменов, мигрированных с Windows 2003 R2 или ранее) — см. страницу Windows Server Compatibility.

Подводные камни

  • На DC нет процессов nmbd: контроллеры домена не поддерживают network browsing, и это норма, а не проблема.
  • Все процессы samba, smbd, winbindd должны быть дочерними к одному родительскому процессу samba — иная структура означает неисправность.
  • Bug 13298 (добавление DNS-записей при join) затрагивает только Samba v4.7 и новее.
  • Samba поддерживает только полностью реплицируемые AD DNS-зоны (ForestDnsZones, DomainDnsZones); устаревшие расположения зон (после миграции с Windows 2000/2003) не поддерживаются.
  • Шаги обхода DNS-ошибок при join выполнять строго в указанном порядке: при нарушении порядка возможны проблемы репликации из-за повторного создания объектов.
  • После обхода атрибуты msDs-masteredBy, msDS-NC-Replica-Locations, msDS-hasMasterNCs изменены — расхождения samba-tool ldapcmp именно по ним не считаются ошибкой.
  • Режим FIPS на RHEL-подобных системах блокирует join: выключить его на всех RHEL-based DC и перезагрузить их все.
