База знаний Samba AD DC

Дистрибутивные пакеты и службы Samba AD DC

Суть

Функциональность контроллера домена Active Directory в дистрибутивах лежит в отдельном пакете или подпакете, а не в том, который ставится «просто для Samba»: в Debian/Ubuntu это samba-ad-dc (служба samba-ad-dc.service), в Fedora — подпакет samba-dc (служба samba.service, сервис firewalld тоже называется samba-dc), в SLES/openSUSE — samba-ad-dc плюс YaST-модуль provision. В RHEL/CentOS пакетов для AD DC нет вовсе: поддерживаются только роль члена домена и NT4 PDC/BDC, а запрос на поддержку AD DC (RFE Bugzilla 910464) закрыт как WONTFIX — значит, на RHEL остаётся сборка из исходников или сторонние пакеты. Из-за этого путь самосборной Samba /usr/local/samba из Установка Samba AD DC при пакетной установке заменяется на /etc/samba и /var/lib/samba, а имя systemd-юнита у дистрибутивов различается — его нельзя угадать, надо смотреть состав пакета. Отдельный подробный материал — инструкция Arch Wiki, доведённая от набора пакетов до рабочего DC, второго контроллера и динамических DNS-обновлений от DHCP.

Ключевое

Общая страница Samba Wiki

  • Страница Distribution-specific Package Installation — список команд установки по дистрибутивам. Оговорка самой страницы: «the list of commands is neither provided nor actively verified by the Samba team» — при пропущенных или неверных пакетах предлагается исправлять команду или писать в рассылку samba.
  • Страница покрывает только установку: установка Samba и её provisioning/настройка — разные вещи (страница задумана как короткий «крюк» от Установка Samba AD DC).
  • Кроме дистрибутивов из таблицы ниже, та же страница приводит FreeBSD: # pkg install net/samba44 (для бэкенда idmap_ad порт нужно собирать вручную с опцией EXP_MODULES).

Debian / Ubuntu

Установка по Samba Wiki:

# apt-get install acl attr samba winbind libpam-winbind libnss-winbind krb5-config krb5-user dnsutils python3-setproctitle

и дополнительно сам пакет с ролью DC:

# apt-get install samba-ad-dc

Примечания вики: libpam-winbind и libnss-winbind нужны только если AD-пользователи будут логиниться на сам DC; DC обычно служит доменным NTP-сервером, поэтому нужен сервер времени (ntp или chrony) — либо GPO, синхронизирующая рабочие станции с time.windows.com.

Руководство Ubuntu Server (актуальная версия) даёт более короткую команду и сразу переходит к подготовке службы:

$ sudo apt install samba-ad-dc krb5-user bind9-dnsutils
  • Установка krb5-user может задавать вопросы — на этом этапе допустимо отвечать значениями по умолчанию (просто Enter), включая вопросы про Kerberos realm и серверы.
  • Штатные службы Samba нужно выключить и замаскировать, а службу DC — размаскировать и включить (но пока не запускать):
$ sudo systemctl disable --now smbd nmbd winbind
$ sudo systemctl mask smbd nmbd winbind
$ sudo systemctl unmask samba-ad-dc
$ sudo systemctl enable samba-ad-dc
  • Замечание руководства: развёртывание Samba AD/DC — это набор связанных между собой служб, и ему нужен собственный systemd-юнит.
  • Провижн-скрипт захочет создать новый smb.conf и не станет заменять существующий, поэтому старый файл надо убрать:
$ sudo mv /etc/samba/smb.conf /etc/samba/smb.conf.orig
  • Provisioning (пример руководства: domain EXAMPLE, realm EXAMPLE.INTERNAL):
$ sudo samba-tool domain provision \
>     --domain EXAMPLE \
>     --realm=EXAMPLE.INTERNAL \
>     --adminpass=Passw0rd \
>     --server-role=dc \
>     --use-rfc2307 \
>     --dns-backend=SAMBA_INTERNAL

Если --adminpass опущен, пароль генерируется случайно и печатается в выводе provisioning. Предупреждение руководства: пароль в командной строке виден другим пользователям в списке процессов и попадает в историю оболочки (если команда не начинается с пробела).

  • Пост-шаги: поправить dns forwarder в /etc/samba/smb.conf (скрипт просто скопировал туда IP из /etc/resolv.conf, то есть ссылку на себя — например, 127.0.0.53); перевести резолвер на Samba: удалить симлинк sudo unlink /etc/resolv.conf, создать файл с nameserver 127.0.0.1 и search example.internal, затем sudo systemctl disable --now systemd-resolved; скопировать сгенерированный Kerberos-конфиг sudo cp -f /var/lib/samba/private/krb5.conf /etc/krb5.conf (если в системе есть другие realm — файлы объединять вручную); запустить sudo systemctl start samba-ad-dc.
  • Проверки: kinit Administrator, klist (билет krbtgt/EXAMPLE.INTERNAL@EXAMPLE.INTERNAL), hostname и hostname -f, samba-tool dns serverinfo $(hostname -f), цикл dig @localhost +short -t SRV по _ldap._tcp, _kerberos._tcp, _kerberos._udp, _kpasswd._udp, dig @localhost +short -t A $(hostname -f), samba-tool user add noble.
  • Парольная политика по умолчанию довольно строгая; посмотреть/изменить — samba-tool domain passwordsettings show / set, например --min-pwd-length=12.

Состав пакета и юнит (упаковка Debian, ветка master; версия 2:4.25.0+dfsg-1):

  • debian/samba-ad-dc.install перечисляет: /usr/sbin/samba, man samba.8, /usr/sbin/samba_dnsupdate, /usr/sbin/samba_spnupdate, /usr/sbin/samba_upgradedns, /usr/sbin/samba_kcc.
  • debian/samba-ad-dc.service (юнит samba-ad-dc.service; фрагмент дословно):
[Unit]
Description=Samba AD Daemon
Documentation=man:samba(8) man:samba(7) man:smb.conf(5)

[Service]
Type=notify
PIDFile=/run/samba/samba.pid
Environment=SAMBAOPTIONS=
EnvironmentFile=-/etc/default/samba
ExecStart=/usr/sbin/samba --foreground --no-process-group $SAMBAOPTIONS
ExecReload=/bin/kill -HUP $MAINPID
ExecCondition=/usr/share/samba/is-configured samba

[Install]
WantedBy=multi-user.target
# Upstream name:
Alias=samba.service
  • Зависимости пакета (debian/control): Depends: samba, python3-samba, python3-dnspython, samba-dsdb-modules, winbind, …; Recommends: samba-ad-provision, python3-gpg (провижн-файлы в отдельном пакете; python3-gpg используется частью AD-подкоманд samba-tool); Suggests: bind9, bind9utils, ldb-tools, time-daemon | chrony | ntpsec.
  • Версионная оговорка (запись debian/changelog для 2:4.20.1+dfsg-2): «move many files from samba package to samba-ad-dc package. From now on, samba-ad-dc isn't just a meta-package, it is actually needed for AD-DC functionality. If you run AD-DC, please ensure that samba-ad-dc package is installed (it is not recommended by samba)». То есть до этой версии samba-ad-dc был только метапакетом, а samba не «рекомендует» его и в актуальных версиях — ставить нужно явно.
  • Наличие пакета в Ubuntu (Launchpad, getPublishedBinaries для samba-ad-dc): в выдаче фигурируют серии noble (2:4.19.5+dfsg-4ubuntu9.8), plucky, questing, resolute и stonking — вплоть до 2:4.24.7+dfsg-1ubuntu1; более старые выпуски Ubuntu в этой выборке не встречаются.

Fedora

  • samba-dc — подпакет пакета samba; описание со страницы пакета: «The samba-dc package provides AD Domain Controller functionality». Версии на момент проверки: Rawhide 4.25.0-5.fc46, Fedora 45 4.25.0-3.fc45, Fedora 44 4.24.7-1.fc44, Fedora 43 4.23.12-1.fc43.
  • Состав (%files dc в samba.spec, ветка rawhide): юнит %{_unitdir}/samba.service, то есть /usr/lib/systemd/system/samba.service (готовый юнит, не samba-dc.service), /usr/sbin/samba, /usr/sbin/samba_dnsupdate, /usr/sbin/samba_downgrade_db, /usr/sbin/samba_kcc, /usr/sbin/samba_spnupdate, /usr/sbin/samba_upgradedns, плагин KDB /usr/lib64/krb5/plugins/kdb/samba.so и модули LDB в /usr/lib64/samba/ldb/.
  • Тот же spec в %files dc объявляет сервисные скрипты systemd для samba.service (%systemd_post samba.service и т. д.), а в зависимостях samba-dc перечислены, среди прочего, samba-dc-provision, samba-dc-libs, samba-winbind, ldb-tools, python3-setproctitle, python3-samba-dc, krb5-server, bind-utils.
  • Провижн-файлы вынесены в отдельный подпакет samba-dc-provision: %files dc-provision содержит %{_datadir}/samba/setup (шаблоны и LDIF провижна).
  • Для firewalld в Fedora есть готовый сервис samba-dc (файл config/services/samba-dc.xml в firewalld; описание дословно: «This option allows you to use this computer as a Samba Active Directory Domain Controller. You need the samba-dc package installed for this option to be useful.»). Он включает сервисы samba, dns, kerberos, ldap, ldaps, kpasswd и порты 135/tcp, 389/udp, 49152-65535/tcp, 3268/tcp, 3269/tcp.
  • Пути в пакетной раскладке Fedora (%files common того же spec): /etc/samba/smb.conf, /etc/samba/lmhosts, /etc/sysconfig/samba, /var/lib/samba/private (права 700), /var/log/samba, /run/samba, /var/lib/samba/lock.

RHEL / CentOS / Scientific Linux — AD DC не поставляется

  • Samba Wiki (разделы для версий 7 и 8): # yum install samba; «The samba package only supports Samba as a domain member and NT4 PDC or BDC. Red Hat does not provide packages for running Samba as an AD DC.» Альтернативы, названные вики: собрать Samba самостоятельно (см. Build Samba from Source) или взять сторонние пакеты с поддержкой AD у доверенного источника. Для версии 6 — # yum install samba4 с тем же ограничением.
  • Документация RHEL 10 («Configuring and using network file services», глава Using Samba as a server) дословно: «Red Hat does not support running Samba as an AD domain controller (DC).» Там же перечислены поддерживаемые режимы: «An Active Directory (AD) or NT4 domain member», «A standalone server», «An NT4 Primary Domain Controller (PDC) or Backup Domain Controller (BDC)» — с оговоркой, что PDC/BDC поддерживаются только в существующих инсталляциях с ОС, поддерживающими домены NT4, и что новые NT4-домены заводить не следует.
  • Причина, по которой ждать изменений не стоит: RFE Bugzilla 910464 «[RFE] Add Samba AD domain controller support» — статус CLOSED, resolution WONTFIX (создан 2013-02-12, последнее изменение 2022-03-13, продукт в записи — Red Hat Enterprise Linux 8).

SLES / openSUSE

  • Samba Wiki для SUSE Linux Enterprise / openSUSE даёт одну команду:
# zypper install samba samba-winbind samba-ad-dc
  • Проверка по репозиториям openSUSE: в Tumbleweed пакет samba-ad-dc присутствует (на момент проверки samba-ad-dc-4.25.0+git.473.e78e78fbf4-1.1.x86_64, рядом samba-ad-dc-libs). Состав пакета (проверено по списку файлов из rpm): /usr/sbin/samba, /usr/sbin/samba_dnsupdate, /usr/sbin/samba_downgrade_db, /usr/sbin/samba_kcc, /usr/sbin/samba_spnupdate, /usr/sbin/samba_upgradedns, rcsamba-ad-dc, провижн-файлы /usr/share/samba/setup/ (LDIF-шаблоны провижна и схемы AD), man samba.8, шаблон /usr/share/fillup-templates/sysconfig.samba-ad-dc, drop-in /usr/lib/systemd/system/named.service.d/26-samba-dlz.conf (добавляет ReadWritePaths=-/var/lib/samba/bind-dns).
  • Юнит в Tumbleweed называется samba-ad-dc.service (файл /usr/lib/systemd/system/samba-ad-dc.service), фрагмент дословно:
[Unit]
Description=Samba AD Daemon
Documentation=man:samba(8) man:samba(7) man:smb.conf(5)

[Service]
Type=notify
PIDFile=/run/samba/samba.pid
EnvironmentFile=-/etc/sysconfig/samba
Environment=KRB5CCNAME=/run/samba/krb5cc_samba
ExecStartPre=/usr/share/samba/update-samba-security-profile
ExecStart=/usr/sbin/samba --foreground --no-process-group $SAMBAOPTIONS
  • В openSUSE есть YaST-модуль провижна: пакет yast2-samba-provision (в репозиториях Leap 15.6 — 1.0.5-150400.9.3.3, Tumbleweed — 1.0.6-1.2); README модуля: «YaST - The Samba Active Directory Domain Controller provision module».
  • Отрицательный результат проверки: в основных репозиториях openSUSE Leap 15.5 и Leap 15.6 (repo/oss/x86_64) пакета samba-ad-dc нет — там из «самбовых» пакетов есть samba, samba-client, samba-winbind, samba-tool и т. п., но не DC-пакет. То есть команда zypper install … samba-ad-dc из вики Samba на этих выпусках «как есть» не сработает (репозитории SLES отдельно не проверялись; сама вики оговаривает, что её список команд не верифицируется командой Samba).
  • Раздел Samba в актуальном руководстве SLES 15 SP7 («Storage Administration Guide») описывает файловый сервер и подключение к AD-домену через realmd, но не поднятие Samba как AD DC.

Arch Linux (Arch Wiki)

Инструкция Arch Wiki доведена до рабочего DC и проверок на каждом шаге.

  • Набор пакетов — из официальных репозиториев:
# pacman -S krb5 ntp python-cryptography python-dnspython python-markdown openresolv samba

По желанию — bind и/или cups. В статье отмечено, что серверные пакеты поставлены ради клиентских утилит: у Samba есть собственные встроенные LDAP, Kerberos и DNS.

  • Provisioning:
# samba-tool domain provision --use-rfc2307 --interactive

--use-rfc2307 добавляет в схему AD атрибуты POSIX (UID/GID) — нужен, если в домене будут аутентифицироваться Linux/BSD/macOS-клиенты; требования к паролю администратора: минимум одна заглавная буква, одна цифра и восемь символов, иначе provisioning завершится ошибкой.

  • Kerberos-конфиг из провижна:
# mv /etc/krb5.conf{,.default}
# cp /var/lib/samba/private/krb5.conf /etc
  • DNS переключается на локальную Samba через resolvconf (openresolv): создаётся /etc/resolv.conf.tail с search internal.domain.tld и nameserver 127.0.0.1, затем chmod 644 /etc/resolv.conf.tail и resolvconf -u.
  • Запуск службы: «Enable and start the samba.service unit» (пакет Arch ставит именно /usr/lib/systemd/system/samba.service; в пакете также есть nmb.service, smb.service, winbind.service и samba-bgqd.service).
  • Arch-специфично — утилиты LDB требуют пути к модулям LDB; создаётся /etc/profile.d/sambaldb.sh:
export LDB_MODULES_PATH="${LDB_MODULES_PATH}:/usr/lib/samba/ldb"

затем chmod 0755 /etc/profile.d/sambaldb.sh и . /etc/profile.d/sambaldb.sh.

  • Проверки после запуска: host -t SRV _ldap._tcp.internal.domain.com., host -t SRV _kerberos._udp.internal.domain.com., host -t A server.internal.domain.com.; аутентификация — smbclient //localhost/netlogon -U Administrator -c 'ls'; Kerberos — kinit administrator@INTERNAL.DOMAIN.COM (realm заглавными), klist, и проверка билета smbclient //server/netlogon --use-kerberos=required -c 'ls'.
  • Обратные зоны создаются по одной на подсеть и должны жить в DNS Samba (а не в BIND), чтобы работали динамические обновления от клиентов:
# samba-tool dns zonecreate <server.internal.domain.tld> xxx.xxx.xxx.in-addr.arpa -U Administrator
# samba-tool dns add <server.internal.domain.tld> xxx.xxx.xxx.in-addr.arpa zzz PTR server.internal.domain.tld -U Administrator

проверка — host -t PTR xxx.xxx.xxx.xxx.

  • Второй DC в существующем домене: NTP настраивается так же, как для первого; команда присоединения — с теми же опциями, что использовались при провижне домена:
# samba-tool domain join internal.domain.tld DC -U administrator <other options>

где <other options> включают --option='idmap_ldb:use rfc2307 = yes' (если домен создавался с --use-rfc2307), --dns-backend=BIND9_DLZ|SAMBA_INTERNAL, --option="dns forwarder=xxx.xxx.xxx.xxx" (только для SAMBA_INTERNAL) и --site=SITE. Затем cp /var/lib/samba/private/krb5.conf /etc/krb5.conf, включение и запуск samba.service; при бэкенде BIND9_DLZ — samba_upgradedns --dns-backend=BIND9_DLZ, настройка BIND и перезапуск named.service, а записи обновляются командой samba_dnsupdate --all-names --use-samba-tool --verbose.

  • Передача FSMO-ролей перед понижением старого DC вынесена за рамки статьи Arch Wiki (со ссылкой на вики Samba; см. Передача и захват FSMO ролей).
  • DHCP с динамическими DNS-обновлениями: создаётся непривилегированный пользователь AD (samba-tool user create dhcp, при желании samba-tool user setexpiry dhcp --noexpiry), ему выдаётся членство в DnsAdmins (samba-tool group addmembers DnsAdmins dhcp), создаётся SPN и экспортируется keytab:
# samba-tool spn add server/server.internal.domain.tld@INTERNAL.DOMAIN.TLD dhcp
# samba-tool domain exportkeytab --principal=dhcp@INTERNAL.DOMAIN.TLD dhcpd.keytab
# install -vdm 755 /etc/dhcpd
# mv dhcpd.keytab /etc/dhcpd
# chown root:root /etc/dhcpd/dhcpd.keytab
# chmod 400 /etc/dhcpd/dhcpd.keytab

далее правится /etc/dhcpd/dhcpd-update-samba-dns.conf (переменные KRB5CC, KEYTAB, DOMAIN, REALM, PRINCIPAL, NAMESERVER, ZONE), выдаётся sudo-право на скрипт, а в каждую подсеть dhcpd.conf добавляются блоки on commit / on release / on expiry, вызывающие dhcpd-update-samba-dns.sh. Пакеты: dhcp, sudo и samba-dhcpd-update из AUR. Оговорка статьи: клиенты Windows всё равно будут пытаться обновлять DNS сами и получать отказ, поэтому рекомендуется GPO, отключающая «Dynamic Update» и «Register PTR Records»; раздел помечен как требующий обновления под DHCP-сервер kea (на момент чтения).

Подводные камни

  • Имя службы у дистрибутивов различается. Debian/Ubuntu и openSUSE — samba-ad-dc.service, Fedora и Arch — samba.service (в юните Debian при этом есть Alias=samba.service). Общего имени нет; при сборке из исходников юнит вообще создаётся вручную — см. Управление службой AD DC.
  • В Fedora легко перепутать пакет и юнит: пакет называется samba-dc, а systemd-юнит — samba.service; при этом сервис firewalld называется samba-dc.
  • Пакетная установка не использует пути /usr/local/samba из Установка Samba AD DC: конфиг — /etc/samba/smb.conf, состояние и приватные файлы — /var/lib/samba (например, /var/lib/samba/private/krb5.conf), бинарники — /usr/sbin.
  • Debian/Ubuntu: без явного samba-ad-dc DC не поднимется. Запись в changelog для 2:4.20.1+dfsg-2 прямо предупреждает, что пакет samba его не рекомендует: «If you run AD-DC, please ensure that samba-ad-dc package is installed». До версии 2:4.20.1+dfsg-2 samba-ad-dc был просто метапакетом.
  • Маскировка служб-конкурентов обязательна: на Debian/Ubuntu нужно systemctl disable --now smbd nmbd winbind и systemctl mask smbd nmbd winbind, а саму samba-ad-dc — unmask и enable (руководство Ubuntu). Иначе обычные службы Samba могут снова включиться.
  • Провижн-файлы живут в отдельных пакетах: Debian/Ubuntu — samba-ad-provision (в Recommends), Fedora — samba-dc-provision, openSUSE — внутри samba-ad-dc (/usr/share/samba/setup). При минимальной установке без них samba-tool domain provision не заработает.
  • RHEL/CentOS/Scientific Linux: AD DC нет и не планируется. Поддерживаются член домена, standalone и NT4 PDC/BDC; RFE 910464 закрыт WONTFIX. Остаются сборка из исходников (см. Build Samba from Source) или сторонние пакеты от доверенного источника. Не полагайтесь на старые инструкции вида yum install samba4 — по вики Samba это тот же «не-DC» пакет.
  • Требования к паролю администратора (минимум: заглавная буква, цифра, 8 символов — Arch Wiki) и падение provisioning при несоответствии; в Ubuntu-руководстве пароль в командной строке считается небезопасным (виден в списке процессов и в истории).
  • Обратные зоны и динамические обновления: держать обратные зоны в DNS Samba, а не в BIND (Arch Wiki), иначе динамические обновления от клиентов не работают. DHCP-обновления через keytab порождают предупреждения у Windows-клиентов, которым нужна отдельная GPO.
  • dns forwarder после провижна указывает сам на себя (скрипт Ubuntu копирует IP из /etc/resolv.conf, часто 127.0.0.53) — его надо поправить до запуска DC.
  • openSUSE Leap 15.5/15.6: пакета samba-ad-dc в основном OSS-репозитории нет (он есть в Tumbleweed), так что команда zypper install samba samba-winbind samba-ad-dc из вики Samba для этих выпусков не подтверждена; проверены именно репозитории repo/oss/x86_64 на download.opensuse.org, репозитории SLES не проверялись.
  • Провижн ≠ установка: страница-источник покрывает только установку пакетов; сам провижн, включение Group Policy и прочие шаги — по Установка Samba AD DC и соответствующим заметкам.
